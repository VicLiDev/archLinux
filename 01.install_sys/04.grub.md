# GRUB：grub 与 grub2 的区别、安装与排障

- **归属**：Arch 的包名叫 `grub`，提供 GRUB 2.x；GRUB Legacy（0.97）已淘汰
- **一句话**：`grub2` 不是另一款软件，而是 openSUSE/Fedora 等发行版对 GRUB 2 的
  **包名与命令前缀**；Arch 上不存在 `grub2` 包，也不存在 `grub2-mkconfig`
- **适用**：UEFI 与 BIOS 都支持，这是它相对 systemd-boot 的最大优势

## 1. grub 与 grub2 到底是什么关系

### 1.1 版本谱系

| 分支        | 版本      | 状态       | 配置文件              | 特点                              |
|-------------|-----------|------------|-----------------------|-----------------------------------|
| GRUB Legacy | 0.97      | 已停止维护 | `/boot/grub/menu.lst` | 手写菜单，无 `grub-mkconfig`      |
| GRUB 2      | 2.00–2.12 | 当前       | `/boot/grub/grub.cfg` | 脚本化生成，支持 UEFI、多文件系统 |

日常说的 "GRUB" 都指 GRUB 2。判断版本：

```bash
grub-install --version        # grub-install (GRUB) 2.12
```

### 1.2 各发行版的包名与命令

这是最容易照抄出错的地方——**同一套软件，不同发行版的叫法不同**：

| 发行版          | 包名                        | 安装命令        | 生成配置         | 配置文件               |
|-----------------|-----------------------------|-----------------|------------------|------------------------|
| Arch            | `grub`                      | `grub-install`  | `grub-mkconfig`  | `/boot/grub/grub.cfg`  |
| openSUSE        | `grub2`、`grub2-x86_64-efi` | `grub2-install` | `grub2-mkconfig` | `/boot/grub2/grub.cfg` |
| Fedora / RHEL   | `grub2-*`                   | `grub2-install` | `grub2-mkconfig` | `/boot/grub2/grub.cfg` |
| Debian / Ubuntu | `grub-efi-amd64`、`grub-pc` | `grub-install`  | `grub-mkconfig`  | `/boot/grub/grub.cfg`  |

结论：`grub2-install` 就是 `grub-install` 在 openSUSE/Fedora 里的名字，底层是同一个
程序；`grub2-mkconfig` 同理。**不是"GRUB 第二代"与"grub 命令"两套东西**。

### 1.3 怎么判断手头这台机器用的是哪个

```bash
pacman -Q grub                     # Arch：有输出说明装的是 grub 2.x
grub-install --version             # 看版本号，2.x 即为 GRUB 2
ls /boot/grub/grub.cfg 2>/dev/null || ls /boot/grub2/grub.cfg 2>/dev/null
ls /boot/grub/menu.lst 2>/dev/null # 有 menu.lst 才是 Legacy，基本见不到了
```

在 openSUSE 上会看到 `/boot/grub2/grub.cfg`，在 Arch 上是 `/boot/grub/grub.cfg`，
两者互不干扰。

### 1.4 照抄教程时的三条禁忌

- 在 Arch 上执行 `pacman -S grub2` —— 包不存在，正确的是 `pacman -S grub`。
- 在 Arch 上执行 `grub2-mkconfig` —— 命令不存在，正确的是 `grub-mkconfig`。
- 在 openSUSE 上执行 `grub-mkconfig` —— 同理反过来也会失败。

## 2. 在 Arch 上安装

### 2.1 UEFI

```bash
pacman -S grub efibootmgr
grub-install --target=x86_64-efi --efi-directory=/boot --bootloader-id=GRUB
grub-mkconfig -o /boot/grub/grub.cfg
```

- `--efi-directory` 写 **ESP 的挂载点**。本文档体系里 ESP 挂在 `/boot`，所以是
  `/boot`；若挂在 `/efi` 就写 `/efi`。
- `--bootloader-id` 决定 ESP 里的目录名和 NVRAM 项名字，最终生成
  `/boot/EFI/GRUB/grubx64.efi`，NVRAM 里出现一条 `GRUB`。
- 这里只是**安装引导器**，`grub-mkconfig` 才是生成菜单；两步都不能省。

### 2.2 BIOS

```bash
pacman -S grub
grub-install --target=i386-pc /dev/nvme0n1    # 整块盘，不能带分区号
grub-mkconfig -o /boot/grub/grub.cfg
```

BIOS + GPT 的组合需要先有一个 1 MiB 的 `bios_grub`（`ef02`）分区，否则
`grub-install` 会报无法嵌入。这部分在
[01.partition-and-boot.md](01.partition-and-boot.md) 第 1.5 节有完整说明。

### 2.3 与 systemd-boot 共存

两者可以同时装在同一个 ESP 的不同子目录（`/EFI/GRUB/` 与 `/EFI/systemd/`），
由 NVRAM 顺序决定谁先跑。想切回 systemd-boot 不必卸载 GRUB，用
`efibootmgr -o` 调整顺序即可。

反向也能链式启动：在 systemd-boot 的条目里写 `efi /EFI/GRUB/grubx64.efi`，就能
从 Arch 的菜单进 GRUB，不需要 GRUB 去读 Arch 的根分区。示例见
[02.dual-boot.md](02.dual-boot.md) 第 5.1 节。

## 3. 配置：三个位置，只有一个能改

| 路径                  | 角色                                              | 能不能手改                         |
|-----------------------|---------------------------------------------------|------------------------------------|
| `/etc/default/grub`   | 全局变量：默认项、超时、内核参数                  | 可以，改完要重新生成               |
| `/etc/grub.d/`        | 生成脚本：`10_linux`、`30_os-prober`、`40_custom` | 谨慎，`40_custom` 用来加自定义条目 |
| `/boot/grub/grub.cfg` | **生成产物**，每次 `grub-mkconfig` 会覆盖         | 不要手改                           |

`/etc/default/grub` 里值得认识的变量：

| 变量                         | 作用                                    |
|------------------------------|-----------------------------------------|
| `GRUB_DEFAULT`               | 默认条目：序号（从 0 开始）或 `saved`   |
| `GRUB_TIMEOUT`               | 菜单停留秒数，`0` 表示不显示菜单        |
| `GRUB_TIMEOUT_STYLE`         | `menu` / `countdown` / `hidden`         |
| `GRUB_CMDLINE_LINUX_DEFAULT` | 正常启动的内核参数                      |
| `GRUB_CMDLINE_LINUX`         | 所有条目都追加的参数（恢复模式也带）    |
| `GRUB_DISABLE_OS_PROBER`     | 设 `false` 才允许探测其他系统           |
| `GRUB_SAVEDEFAULT`           | 配合 `GRUB_DEFAULT=saved`，记住上次选择 |

改完任何一项都要重新生成：

```bash
grub-mkconfig -o /boot/grub/grub.cfg
```

## 4. 四个常见修改

### 4.1 换默认启动项

菜单顺序由 `/etc/grub.d/` 里脚本的执行顺序决定（`10_linux` 在前、`30_os-prober`
在后），所以"序号"并不直观。稳妥做法是用 `saved`：

```ini
GRUB_DEFAULT=saved
GRUB_SAVEDEFAULT=true
```

之后在菜单里选哪个，下次就默认进哪个，不用记序号。

### 4.2 加内核参数

例如给 NVIDIA 开 DRM 模式设置（细节见
[03.install_gui/01.desktop.md](../03.install_gui/01.desktop.md)）：

```ini
GRUB_CMDLINE_LINUX_DEFAULT="loglevel=3 quiet nvidia_drm.modeset=1 nvidia_drm.fbdev=1"
```

重新生成后可以验证：

```bash
grep -n "nvidia_drm" /boot/grub/grub.cfg
```

### 4.3 探测其他系统

```bash
pacman -S os-prober
```

```ini
GRUB_DISABLE_OS_PROBER=false
```

```bash
grub-mkconfig -o /boot/grub/grub.cfg
grep -A2 "openSUSE" /boot/grub/grub.cfg
```

openSUSE 的 btrfs 子卷布局会让探测时好时坏，具体处理见
[02.dual-boot.md](02.dual-boot.md) 第 5.2 节。

### 4.4 手写自定义条目

`/etc/grub.d/40_custom` 末尾追加，适合 os-prober 探测不到的系统：

```text
menuentry "openSUSE Leap" {
    insmod btrfs
    search --no-floppy --fs-uuid --set=root 一串UUID
    linux /@/.snapshots/1/snapshot/boot/vmlinuz root=UUID=一串UUID \
          rootflags=subvol=@/.snapshots/1/snapshot rw
    initrd /@/.snapshots/1/snapshot/boot/initrd
}
```

UUID 用 `blkid` 查，子卷路径先用 openSUSE 启动后 `findmnt /` 确认。写完
`chmod +x /etc/grub.d/40_custom` 再 `grub-mkconfig`。

## 5. 与 systemd-boot 的分工

| 维度           | GRUB                             | systemd-boot                    |
|----------------|----------------------------------|---------------------------------|
| 固件           | UEFI / BIOS 均可                 | 仅 UEFI                         |
| 菜单来源       | `grub-mkconfig` 生成 `grub.cfg`  | 静态 `entries/*.conf`，开机现读 |
| 探测其他系统   | `os-prober`                      | 只自动发现 Windows/macOS        |
| 配置失败的影响 | 生成出错可能导致全线起不来       | 单个条目写错只影响那一条        |
| 适用场景       | 老机器、加密 `/boot`、要快照菜单 | 新机器、配置越少越好            |

管理命令对照见 [03.bootctl.md](03.bootctl.md)。

## 6. 排障：进不了系统怎么办

### 6.1 `grub rescue>` 提示符

说明 GRUB 本体在，但找不到 `/boot/grub` 或配置损坏。手动引导：

```text
grub rescue> ls                    # 列出 (hd0,gpt1) 这类设备
grub rescue> ls (hd0,gpt2)/boot    # 找到含 vmlinuz 的分区
grub rescue> set root=(hd0,gpt2)
grub rescue> set prefix=(hd0,gpt2)/boot/grub
grub rescue> insmod normal
grub rescue> normal                # 回到正常菜单，然后进系统重装 GRUB
```

### 6.2 从 Live ISO 重建

```bash
mount /dev/nvme0n1p2 /mnt
mount /dev/nvme0n1p1 /mnt/boot        # ESP
arch-chroot /mnt
grub-install --target=x86_64-efi --efi-directory=/boot --bootloader-id=GRUB
grub-mkconfig -o /boot/grub/grub.cfg
```

BIOS 机器把 `--target` 换成 `i386-pc`、参数换成整块盘。

### 6.3 常见错误

| 报错                                        | 原因                                  | 处理                               |
|---------------------------------------------|---------------------------------------|------------------------------------|
| `grub rescue>`                              | 找不到 `/boot/grub`，配置或分区变动   | 按 6.1 手动引导后重建              |
| `unknown filesystem`                        | GRUB 不认该文件系统（如新特性 btrfs） | 用 Live 环境修复，或换独立 `/boot` |
| `no such device: <UUID>`                    | UUID 变了（重装/重建分区表）          | 重新生成 `grub.cfg`                |
| `cannot find EFI directory`                 | `--efi-directory` 指向的不是 ESP      | 确认 ESP 挂载点，FAT32 才有意义    |
| `failed to get canonical path of /boot/efi` | 目录不存在或未挂载                    | 先挂载 ESP 再执行                  |

## 7. 验收清单

- [ ] `grub-install --version` 显示 `(GRUB) 2.x`
- [ ] ESP 下存在 `/EFI/GRUB/grubx64.efi`（UEFI 场景）
- [ ] `efibootmgr -v` 里有 `GRUB` 项，路径与实际文件一致
- [ ] `grub-mkconfig` 无报错，`/boot/grub/grub.cfg` 里有当前内核条目
- [ ] 重启后能看到菜单，选默认项能进系统
- [ ] 改过的内核参数在 `grub.cfg` 里能 `grep` 到
- [ ] 若开了 os-prober，另一个系统的条目也在菜单里
