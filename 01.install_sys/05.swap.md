# 交换分区：什么时候要、建多大、建完谁来挂

- **阶段**：装系统分区时，或系统装好之后想补一块 swap
- **要回答的三个问题**：
  1. swap 分区、swap 文件、zram 有什么区别，我该用哪个
  2. 要建多大，和休眠（hibernate）是什么关系
  3. 建好之后要让谁在开机时把它挂起来
- **结论先行**：内存 16 GiB 以上且不休眠 → 2～4 GiB 的 swap 文件就够（甚至可以
  只上 zram）；要休眠 → 必须有容量 ≥ 内存的磁盘 swap；分区建完别忘 fstab 或
  GPT 类型码，否则开机不会生效。

## 1. swap 是什么，三种形态怎么选

swap 不是"内存的备份"，而是内核换出匿名页的地方：内存紧张时把不常用的匿名页
写到磁盘，进程再访问时缺页读回。它让系统在内存吃紧时变慢，而不是直接触发
OOM killer 杀进程。

| 形态      | 是什么             | 优点                             | 缺点                           |
|-----------|--------------------|----------------------------------|--------------------------------|
| swap 分区 | 一块独立分区       | 性能最好，可休眠，systemd 能发现 | 大小建时就定死，改要动分区表   |
| swap 文件 | 根分区上的普通文件 | 随时改大小，不碰分区表           | btrfs 要特殊处理；根坏它跟着坏 |
| zram      | 内存里的压缩块设备 | 最快，不碰磁盘，寿命无损         | 占内存，不能休眠，断电即失     |

三种可以共存，常见的组合是 zram 先扛住日常压力、磁盘 swap 只留给休眠或极端
情况。下面的章节按"分区优先，文件兜底"的顺序讲。

### 1.1 什么情况一定要有 swap

- 要休眠（hibernate）：**必须有**容量足够的磁盘 swap，zram 不行
- 物理内存 4～8 GiB，却要开很多浏览器标签或并行编译
- 跑数据库、容器、Electron 应用，或大量 fork 的构建
- 希望内存吃紧时变慢一点，而不是某个进程被 OOM killer 直接杀掉
- 程序会 `mmap` 一大块匿名内存但只用其中一部分（很多运行时都这样），没有
  swap 时这类提交会直接失败

反过来说，内存 32 GiB 以上、从不用满、也不休眠，不建 swap 也能用。但仍建议
留 2～4 GiB 兜底，代价很小。

### 1.2 先看现在有没有

```bash
swapon --show          # 当前生效的 swap
free -h                # Swap 行全 0 就是没有
cat /proc/swaps        # 内核视角
zramctl                # 装了 zram 才有输出
```

## 2. 建多大

Arch Wiki 的经验表（不休眠的场景）：

| 物理内存  | 建议 swap   |
|-----------|-------------|
| `< 2 GiB` | 内存的 2 倍 |
| 2～8 GiB  | 等于内存    |
| 8～64 GiB | 4～8 GiB    |
| > 64 GiB  | 至少 4 GiB  |

要休眠则另算：**swap ≥ 内存大小**。内核把内存镜像压缩后写进 swap，实际占用
通常小于内存，但按 1:1 留最保险——16 GiB 内存就留 16 GiB swap。这也是很多
NVMe 机器直接划 16～20 GiB 的原因。

分区大小的现实约束：swap 和根分区抢同一块盘。常见的布局是 ESP 5 GiB + swap
8～16 GiB + 根占剩余。分区规划见 `01.partition-and-boot.md`。

## 3. 安装系统时建

### 3.1 用 archinstall

archinstall 的磁盘配置里有一项 Swap，选项和本文的三种形态一一对应（版本不同
措辞略有差异，大致是这四种）：

| 选项           | 实际做的事                        | 适合谁               |
|----------------|-----------------------------------|----------------------|
| zram           | 启用 zram，不建磁盘 swap          | 内存 ≥16 GiB、不休眠 |
| swap file      | 在根分区建 `/swapfile` 并写 fstab | 单系统、想省分区     |
| swap partition | 建类型为 swap 的分区并写 fstab    | 要休眠、想性能最好   |
| none           | 什么都不做                        | 内存极大、明确不需要 |

选 swap partition 时，分区本身仍要自己划（archinstall 之前用 `fdisk`/`cfdisk`
分好，或者在它的手动分区界面里加），它只负责 `mkswap`、`swapon`、写 fstab。

### 3.2 手工分区

```bash
lsblk -f                      # 先看清盘符、现有分区、空闲空间
sudo fdisk /dev/nvme0n1
#   n   新建分区
#        起始扇区回车取默认（接在最后一个分区后面）
#        +16G 作为结束位置
#   t   改类型 → 19（Linux swap）
#   p   复核分区表
#   w   写入
sudo partprobe /dev/nvme0n1   # 让内核重读分区表
```

类型码不止是"标记"，后面 4.3 的自动挂载要靠它：

| 工具 / 分区表      | swap 类型码 |
|--------------------|-------------|
| `fdisk`（GPT）     | `19`        |
| `sgdisk` / `gdisk` | `8200`      |
| `fdisk`（MBR）     | `82`        |

```bash
sudo mkswap -L swap /dev/nvme0n1p3
sudo swapon /dev/nvme0n1p3
swapon --show
```

`mkswap` 会写入新的 UUID，之后写 fstab 要用 `blkid` 重新读，别抄安装介质上
的旧值：

```bash
sudo blkid -s UUID -o value /dev/nvme0n1p3
```

## 4. 系统装好之后再加

三种做法，按对现有系统的破坏程度从低到高排。

### 4.1 有未分配空间：新建一个分区

步骤同 3.2，只是不需要重装。前提是磁盘尾部确实有空闲空间（`lsblk` 或
`parted -l` 的 `Free Space` 能看出来）。

没有空闲空间就只能缩小现有分区：ext4 先 `e2fsck -f` 再 `resize2fs`，btrfs 用
`btrfs filesystem resize`，然后调整分区表。这一步很容易把系统搞坏，已装好的
系统上更推荐 4.2。

### 4.2 不动分区表：swap 文件

ext4：

```bash
sudo fallocate -l 8G /swapfile     # 文件大小就是 swap 大小
sudo chmod 600 /swapfile           # 只有 root 可读，必须做
sudo mkswap /swapfile
sudo swapon /swapfile
```

btrfs：**不能直接 fallocate**，swap 文件必须关掉 COW：

```bash
sudo btrfs filesystem mkswapfile --size 8g /swapfile
sudo swapon /swapfile
```

`mkswapfile` 等价于「建空文件 + `chattr +C` + `mkswap`」，btrfs-progs 5.16
起提供。老版本可以手工来：`touch /swapfile` → `chattr +C /swapfile` →
`fallocate -l 8G` → `mkswap`。

另外 swap 文件不能放在会被快照的子卷里：快照副本里的 swap 文件会直接报错，
把 `/swapfile` 放在不带快照的子卷或根子卷上。

XFS 和其他文件系统：`fallocate` 产生的文件可能带 extent hole，导致
`swapon: Invalid argument`，改用 `dd`：

```bash
sudo dd if=/dev/zero of=/swapfile bs=1M count=8192 status=progress
```

### 4.3 让它在开机时生效

两条路，选一条，不要两边都配。

**路线一：写 fstab**（通用、可读、迁移时看得懂）

```text
UUID=6f1a...  none  swap  defaults  0 0      # 分区
/swapfile     none  swap  defaults  0 0      # 文件
```

第二列是挂载点，swap 不挂到目录上，所以写 `none`。写完先验证，别直接重启：

```bash
sudo swapon -a
swapon --show
sudo findmnt --verify
```

**路线二：交给 systemd 自动发现**（仅 GPT + UEFI 启动）

分区类型是 Linux swap（`19`/`8200`）时，`systemd-gpt-auto-generator` 会在开机
时自动为它生成一个 `.swap` 单元，不写 fstab 也会被启用。它的条件是：该分区与
ESP/根分区在同一块盘上，且 fstab 里没有这个分区。所以两条路线不要混用，否则
排查时看不出到底是谁挂的。

fstab 写错的代价是开机掉进 emergency shell。此时用 root 登录后：

```bash
mount -o remount,rw /
vi /etc/fstab          # 改掉或注释掉出错的那行
reboot
```

或者在启动时给内核加 `systemd.unit=multi-user.target`，先跳过图形和挂载检查。

### 4.4 多个 swap 共存

分区和文件同时存在时，内核按优先级决定先用谁，默认按加入顺序，后加入的更低。
想指定优先级用 `pri=`：

```text
/swapfile  none  swap  defaults,pri=10  0 0
```

建议让 zram 的优先级最高、磁盘 swap 最低，这样压缩换出先用，磁盘只在必要时
才动。

## 5. 验证与调参

```bash
swapon --show                              # 名称、类型、大小、已用、优先级
free -h                                    # Swap 行应该不为 0
cat /proc/swaps
systemctl list-units --type=swap --all      # 看单元名是从 fstab 还是 gpt-auto 来的
```

`swapon --show` 里 `TYPE` 是 `partition` 或 `file`，`PRIO` 是优先级，`USED`
长期不涨说明内存够用，不必紧张。

调整 swappiness（默认 60，桌面常用 10～20）：

```bash
cat /proc/sys/vm/swappiness
echo 'vm.swappiness=10' | sudo tee /etc/sysctl.d/99-swap.conf
sudo sysctl --system
```

它是匿名页与文件页回收之间的权衡偏置，不是"是否使用 swap"的开关：设成 0 也
不代表绝不换出，内存压力大时仍会换。

### 5.1 zram：不碰磁盘的压缩 swap

```bash
sudo pacman -S zram-generator
```

`/etc/systemd/zram-generator.conf`：

```ini
[zram0]
zram-size = ram / 2
compression-algorithm = zstd
```

```bash
sudo systemctl daemon-reload
sudo systemctl start systemd-zram-setup@zram0.service
zramctl
```

`zram-size` 建议取内存的一半；zstd 在压缩比和 CPU 开销之间比较均衡，老 CPU
可以换 `lz4`。zram 和磁盘 swap 可以共存（前者才用于换出，后者留给休眠），但
**zram 不能用于休眠**。

### 5.2 zram 与 zswap 的区别

两个名字很像，作用层次不同：

| 维度          | zram                          | zswap                            |
|---------------|-------------------------------|----------------------------------|
| 位置          | 内存里的一块块设备，充当 swap | 内核里的压缩缓存，位于 swap 之前 |
| 需要磁盘 swap | 不需要                        | 需要，作为最终落盘的后端         |
| 打开方式      | `zram-generator`              | 内核参数 `zswap.enabled=1`       |
| 能否休眠      | 否                            | 能（数据最终落到磁盘 swap）      |

桌面机器上 zram 更常用；zswap 适合"已经有 swap 分区、只想少写盘"的场景。

## 6. 要休眠还得再做两步

swap 建好只是前提，内核还要知道从哪块 swap 恢复。

### 6.1 内核参数 resume=

分区：`resume=UUID=<swap 分区的 UUID>`。

swap 文件：除了 `resume=UUID=<swap 文件所在文件系统>`，还要
`resume_offset=<文件在磁盘上的物理偏移>`：

```bash
sudo filefrag -v /swapfile | awk 'NR==4 {print $4}'   # 取 physical_offset
```

这两个参数写在 `/etc/kernel/cmdline`（UKI 方案，见 `03.bootctl.md`），改完重新
生成 UKI：

```bash
sudo mkinitcpio -P
```

用传统 `entries/*.conf` 的话写在对应条目的 `options` 行里，见同一篇文档。

### 6.2 initramfs 的 resume hook

用 busybox 风格 initramfs（`HOOKS` 里没有 `systemd`）时，`/etc/mkinitcpio.conf`
的 `HOOKS` 要在 `udev` 之后补 `resume`：

```text
HOOKS=(base udev resume autodetect modconf block filesystems keyboard fsck)
```

用 `systemd` 钩子时由 systemd 自己处理，不必加 `resume`，但 `resume=` 参数
照样要给。两种情况改完都要 `sudo mkinitcpio -P`。

### 6.3 验证

```bash
systemctl hibernate
```

能正常恢复的话，`journalctl -b -1 | grep -i hibernat` 里能看到休眠与恢复的记录。
回不来的三大原因：swap 小于内存、`resume=` 写成了分区 UUID 而实际用的是
swap 文件、改了 swap 大小后 UUID 变了没同步。

## 7. 排障对照

| 现象                                         | 原因                                    | 处理                                                      |
|----------------------------------------------|-----------------------------------------|-----------------------------------------------------------|
| `swapon: read swap header failed`            | 没 `mkswap`，或分区类型不是 swap        | 重新 `mkswap`，核对类型码                                 |
| `swapon: /swapfile: Invalid argument`        | btrfs 没关 COW，或 XFS 文件带 hole      | 用 `btrfs filesystem mkswapfile` 或 `dd` 重建             |
| 开机掉进 emergency shell，提示 swap 挂载失败 | fstab 里的 UUID 已过期（重装/改过）     | 用 `blkid` 核对后改 fstab                                 |
| fstab 有行，但 `swapon --show` 是空的        | 没跑过 `swapon -a`，或单元没加载        | `sudo swapon -a`、`systemctl daemon-reload`               |
| 休眠后黑屏，或直接冷启动                     | `resume=` 缺失/写错，或没重建 initramfs | 核对 `cat /proc/cmdline`，`mkinitcpio -P`                 |
| 加了 swap 反而更卡                           | swap 在机械盘，或 swappiness 偏高       | 降低 swappiness，优先用 zram                              |
| `zramctl` 没输出                             | 没装 `zram-generator` 或没启用单元      | 装包 + `systemctl start systemd-zram-setup@zram0.service` |

## 8. 验收清单

- [ ] `swapon --show` 至少一行，大小符合第 2 节的判断
- [ ] `free -h` 的 Swap 行不为 0
- [ ] `sudo findmnt --verify` 没有 fstab 报错
- [ ] `/etc/fstab` 里 swap 行用 UUID 或绝对路径，不是 `/dev/sdX`
- [ ] 重启一次后 `swapon --show` 仍有输出（说明 fstab 或 gpt-auto 生效）
- [ ] 要休眠的话：`cat /proc/cmdline` 里有 `resume=`，`systemctl hibernate` 能回
- [ ] 上 zram 的话：`zramctl` 能看到 `zram0`，且 `swapon --show` 里它的优先级最高
