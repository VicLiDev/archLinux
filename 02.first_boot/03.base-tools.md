# 基础工具与 SSH：把系统变成能干活的机器

- **阶段**：`pacman` 用法已经熟悉，开始装日常要用的东西
- **目标**：一次性补齐常用工具，并把 SSH 配到"能从别的机器直接连进来"
- **原则**：工具按用途分组装，别一个个试；SSH 先保证能连，再谈加固

## 1. 一次装齐常用工具

| 用途         | 包                       | 说明                                     |
|--------------|--------------------------|------------------------------------------|
| 编译与 AUR   | `base-devel`             | `makepkg`、gcc、make 等，装 AUR 包的前提 |
| 构建工具     | `cmake`                  | 跨平台构建；配 `ninja`/`meson` 更顺手    |
| 版本控制     | `git`                    | 后面拉配置、拉 AUR 仓库都要用            |
| 编辑器       | `neovim`                 | 不想学新键位就换 `vim`                   |
| 终端复用     | `tmux`                   | 断线不丢任务，SSH 场景必备               |
| 系统监控     | `btop`                   | 比 `htop` 好看，二选一即可               |
| 文件同步     | `rsync`                  | 增量拷贝、备份                           |
| 下载         | `curl wget`              | 排查网络时也用得上                       |
| 压缩         | `unzip 7zip`             | `7zip` 提供 `7z`，替代已废弃的 `p7zip`   |
| 目录浏览     | `tree`                   | 看目录结构                               |
| JSON 处理    | `jq`                     | 读 API、看配置文件                       |
| 快速搜索     | `ripgrep fd`             | `rg` 搜内容、`fd` 搜文件名               |
| 手册与补全   | `man-db bash-completion` | `man` 和 Tab 补全                        |
| 网络诊断     | `ethtool mtr tcpdump`    | 网卡速率、路径丢包、抓包                 |
| DNS 诊断     | `bind`                   | 提供 `dig`/`nslookup`/`host`             |
| 传统网络命令 | `net-tools`              | 提供 `ifconfig`/`netstat`，见 1.1        |

一条命令装完（`--needed` 会跳过已经装好的）：

```bash
pacman -S --needed base-devel cmake git neovim tmux btop rsync curl wget \
  unzip 7zip tree jq ripgrep fd man-db bash-completion ethtool bind mtr tcpdump
```

装完 `exec zsh` 或重新登录一次，`bash-completion` 才会生效。

### 1.1 ifconfig 这类命令还要不要装

`base` 里已经带了 `iproute2`，`ip`、`ss` 就是官方推荐的替代品，开箱即用。
`ifconfig`、`netstat`、`route`、`arp` 都属于 `net-tools`，Arch 不默认安装，上游
多年缺维护，功能已被 iproute2 完全覆盖。

那为什么还会缺？因为大量教程和老脚本写的是 `ifconfig`。想迁就它们就
`pacman -S net-tools`，装了不冲突；但**排障时不要用它**，`ip` 给出的信息更准，
比如 `ip -br a` 会直接标出 `NO-CARRIER`、`DOWN`，而 `ifconfig` 只给一个含糊的
`RUNNING`。

| 老命令                       | 现在用                                 |
|------------------------------|----------------------------------------|
| `ifconfig`                   | `ip -br addr`（或 `ip addr`）          |
| `ifconfig eth0 up`           | `ip link set eth0 up`                  |
| `ifconfig eth0 192.168.1.10` | `ip addr add 192.168.1.10/24 dev eth0` |
| `route -n`                   | `ip route`                             |
| `arp -a`                     | `ip neigh`                             |
| `netstat -tlnp`              | `ss -tlnp`                             |
| `netstat -i`                 | `ip -s link`                           |

无线网卡另配 `iw`（`iw dev` 看连接状态、`iw dev wlan0 link` 看信号强度），
再叠加 `ethtool eth0` 看速率和双工、`mtr` 看路径丢包、`tcpdump` 抓包，
日常网络问题基本能定位到"物理层、IP 层还是 DNS 层"。

## 2. SSH 客户端：从这台机器连出去

```bash
pacman -S --needed openssh
ssh-keygen -t ed25519 -C "lhj@archlinux"   # 一路回车，默认存 ~/.ssh/id_ed25519
ssh-copy-id 用户名@目标主机                 # 把公钥追加到对方的 authorized_keys
ssh 用户名@目标主机                         # 验证免密登录
```

想少敲参数就写 `~/.ssh/config`：

```text
Host nas
    HostName 192.168.1.20
    User lhj
    Port 22
    IdentityFile ~/.ssh/id_ed25519
    ServerAliveInterval 60
```

配好后 `ssh nas` 即可。`ServerAliveInterval` 用来防 NAT/路由把空闲连接掐断，
连内网机器长时间挂 `tmux` 时很有用。

权限不对时 SSH 会直接拒绝使用密钥，检查两处：

```bash
chmod 700 ~/.ssh
chmod 600 ~/.ssh/authorized_keys ~/.ssh/id_ed25519
```

## 3. SSH 服务端：让别的机器连进来

```bash
pacman -S --needed openssh
systemctl enable --now sshd
systemctl status sshd
ss -tlnp | grep :22          # 确认在监听
```

首次启动时 sshd 会自动生成主机密钥（`/etc/ssh/ssh_host_*`）；如果是从备份恢复
的系统里没有这些文件，手动补 `ssh-keygen -A`。装了防火墙（ufw/firewalld）的话
记得放行 22 端口，否则本机 `ss` 能看到监听、外部就是连不上。

### 3.1 加固配置

Arch 的 `sshd_config` 顶部若有 `Include /etc/ssh/sshd_config.d/*.conf`，
就把加固项写进单独文件；没有这个 Include，就直接改 `sshd_config` 本体：

```ini
# /etc/ssh/sshd_config.d/10-hardening.conf
PermitRootLogin no
PasswordAuthentication no
KbdInteractiveAuthentication no
```

```bash
systemctl restart sshd
```

**顺序很重要**：先把公钥登录验证通过，再关密码登录。否则一重启 sshd，
现有的密码会话还能用、新连接全被拒，只能跑到机器前用本地终端救。
稳妥做法是留一个已登录的 SSH 会话不关，另开一个窗口验证新连接。

## 4. 传文件与端口转发

```bash
scp 文件 nas:/tmp/                       # 小文件
rsync -avP 目录/ nas:/backup/目录/       # 大目录，可断点续传
ssh -L 8080:localhost:80 nas             # 本地 8080 转发到 nas 的 80
ssh -R 9000:localhost:3000 nas           # 把本地 3000 暴露到 nas 的 9000
```

排查 HTTP 服务为什么只有本机能访问时，`ssh -L` 是最快的验证手段：转发一条
隧道，若通过隧道能打开，说明服务本身没问题，问题在监听地址或防火墙。

## 5. AUR helper（可选，但迟早要用）

官方仓库没有的包在 AUR，手动流程是"克隆仓库 → `makepkg -si`"。想省事就装
`paru`（它本身也在 AUR，第一次只能手动编）：

```bash
git clone https://aur.archlinux.org/paru.git
cd paru && makepkg -si
```

之后：

```bash
paru -Syu            # 官方 + AUR 一起更新
paru -S 包名         # 官方仓库优先，找不到再搜 AUR
```

AUR 是用户提交的内容，没有官方审核。装之前至少扫一眼 `PKGBUILD` 里
`source=` 和 `build()` 在干什么，尤其是要求 `curl | bash` 的。

### 5.1 报错 `could not find all required packages`

```text
:: Resolving dependencies...
error: could not find all required packages:
    dankmaterialshell (target)
```

这不是网络问题，是**包名不对**。AUR 的包名和项目名经常不是一回事：
DankMaterialShell 的包叫 `dms-shell-git`，Noctalia 的叫 `noctalia-git`。

```bash
paru -Ss dank        # 按关键字模糊搜，看 Name 列，别按项目名猜
paru -Ss dms
```

搜的时候注意三点：

- **同名不同义**：AUR 上的 `dms` 是个 UPnP 媒体服务器，和 DankMaterialShell
  毫无关系，装错白下一堆依赖。
- **VCS 包带 `-git` 后缀**：`dms-shell-git` 跟踪上游最新提交，构建时要联网查
  上游；固定版本的同名包一般没有后缀。
- **官方仓库有的别去 AUR 找**：`quickshell` 在 `extra` 里，`pacman -S` 就够，
  AUR 上的 `quickshell-git` 是开发版。

还有一条经验：**项目改名后包名往往不跟着改**。DMS 的上游仓库从
`AvengeMedia/DankMaterialShell` 搬到了 `duxlabs-dev/dux-shell`，AUR 包仍叫
`dms-shell-git`。`paru -Si 包名` 输出的 URL 字段能看出真实仓库地址。

### 5.2 报错 `Failed to connect to github.com:443`

```text
fetching devel info...
error: timed out looking for devel update: https://github.com/xxx/yyy.git
  -> Cloning yyy git repo...
fatal: unable to access 'https://github.com/xxx/yyy.git/':
  Failed to connect to github.com:443 after 135148 ms
==> ERROR: Failure while downloading yyy git repo
```

包名和 PKGBUILD 都没问题了，纯粹是**源码拉不下来**。第一行
`timed out looking for devel update` 是同一原因的早期表现——VCS 包在构建前要先
连上游确认最新 commit。

先分清是谁不通：

```bash
curl -I --max-time 8 https://aur.archlinux.org    # AUR 本身
curl -I --max-time 8 https://github.com           # 源码站
```

AUR 通、GitHub 不通，就与 pacman 和 AUR 配置无关，别去改镜像列表。

**路线一：有代理就用代理**

```bash
ss -ltnp | grep -E '7890|1080|10808'      # 找本机代理监听的端口

export https_proxy=http://127.0.0.1:7890
export http_proxy=http://127.0.0.1:7890
paru -S 包名
```

`makepkg` 会把环境变量传给 `git`，一次性的 `export` 就够。想长期生效就写进
git 配置，用完记得撤销：

```bash
git config --global http.proxy http://127.0.0.1:7890
git config --global https.proxy http://127.0.0.1:7890
git config --global --unset http.proxy
git config --global --unset https.proxy
```

**路线二：没有代理，用镜像前缀**

`git` 的 `insteadOf` 能把 GitHub 地址自动改写成镜像。先测镜像通不通：

```bash
curl -sS -o /dev/null -w '%{http_code}\n' --max-time 10 \
  "https://ghfast.top/https://github.com/duxlabs-dev/dux-shell.git/info/refs?service=git-upload-pack"
```

返回 `200` 才可用：

```bash
git config --global url."https://ghfast.top/https://github.com/".insteadOf "https://github.com/"
paru -S 包名
git config --global --unset url."https://ghfast.top/https://github.com/".insteadOf
```

这类镜像站寿命不定，返回 404/502 就换域名重测（`gh-proxy.com`、
`ghproxy.net`）。**装完必须撤销**：这条是全局配置，留着会让以后所有 GitHub
克隆都绕第三方，`paru -Syu` 检查 VCS 包时也会走它。

**路线三：自己 `makepkg`**

`paru` 只是替你跑 `makepkg`，可以拆开做：

```bash
git clone https://aur.archlinux.org/包名.git
cd 包名
vim PKGBUILD        # 把 source= 里的 github 地址换成能访问的地址
makepkg -si
```

`aur.archlinux.org` 通常能连，所以"只有 GitHub 被墙"时这条路最可靠。

**路线四：先别装**。AUR 里的东西大多有官方仓库的替代，赶时间就绕开，别为
一个 `-git` 包在网络问题上耗一晚上。

## 6. 验收清单

- [ ] `git --version`、`rg --version`、`cmake --version`、`7z` 都有输出
- [ ] `ip -br a`、`ss -tlnp` 正常；装了 `net-tools` 的话 `ifconfig` 也能用
- [ ] `dig archlinux.org` 能返回解析结果（DNS 正常）
- [ ] `ssh -V` 正常，`ssh-keygen` 生成的密钥在 `~/.ssh/` 下
- [ ] `ssh-copy-id` 后能免密登录目标机器
- [ ] `systemctl status sshd` 是 active，`ss -tlnp` 能看到 22 端口
- [ ] 从另一台机器 `ssh 本机用户@本机IP` 能进来
- [ ] 关掉密码登录后，新连接仍能用密钥登录（旧会话先别关）
- [ ] `paru --version` 可用（如果装了）
