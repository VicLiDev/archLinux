# openSUSE 基础工具与 SSH：把系统变成能干活的机器

- **阶段**：zypper 已经会用（[04.zypper.md](04.zypper.md)），开始装日常工具
- **目标**：一次补齐常用工具，把 SSH 配到"能从别的机器直接连进来"
- **与 Arch 的差异**：工具是同一批，包名、分组方式和防火墙默认值不同

## 1. 一次装齐常用工具

| 用途         | 包 / pattern             | 说明                                |
|--------------|--------------------------|-------------------------------------|
| 编译工具链   | `-t pattern devel_basis` | gcc、make、头文件，编任何东西的前提 |
| 构建工具     | `cmake`                  | 配 `ninja`、`meson` 更顺手          |
| 版本控制     | `git`                    | 拉配置、拉 OBS 上的源码             |
| 编辑器       | `neovim`                 | 不想换键位就装 `vim`                |
| 终端复用     | `tmux`                   | 断线不丢任务，SSH 场景必备          |
| 系统监控     | `btop`                   | 与 `htop` 二选一                    |
| 文件同步     | `rsync`                  | 增量拷贝、备份                      |
| 下载         | `curl wget`              | 排查网络时也用得上                  |
| 压缩         | `unzip 7zip`             | openSUSE 的包名就是 `7zip`          |
| 目录浏览     | `tree`                   | 看目录结构                          |
| JSON 处理    | `jq`                     | 读 API、看配置文件                  |
| 快速搜索     | `ripgrep fd`             | `rg` 搜内容、`fd` 搜文件名          |
| 手册与补全   | `man bash-completion`    | `man` 与 Tab 补全                   |
| 网络诊断     | `ethtool mtr tcpdump`    | 网卡速率、路径丢包、抓包            |
| DNS 诊断     | `bind-utils`             | 提供 `dig`/`nslookup`/`host`        |
| 传统网络命令 | `net-tools`              | `ifconfig`/`netstat`，见 1.1        |

分两条命令装，pattern 不能和包名混在一句里：

```bash
sudo zypper in -t pattern devel_basis
sudo zypper in cmake git neovim tmux btop rsync curl wget unzip 7zip tree \
  jq ripgrep fd man bash-completion ethtool bind-utils mtr tcpdump
```

包名不确定时先查：`zypper se -s 7z` 能看到 `7zip` 和 `p7zip` 都存在，
`zypper se -s dig` 能确认 `dig` 在 `bind-utils` 里。

### 1.1 ifconfig 这类命令还要不要装

openSUSE 的最小安装同样只带 `iproute2`，`ifconfig`、`netstat`、`route` 都在
`net-tools` 里，默认不装。老教程和老脚本爱用它们，迁就一下就
`sudo zypper in net-tools`；但**排障时用 `ip`**，它给出的状态更准，比如
`ip -br a` 会直接标出 `NO-CARRIER`、`DOWN`。

| 老命令                       | 现在用                                 |
|------------------------------|----------------------------------------|
| `ifconfig`                   | `ip -br addr`（或 `ip addr`）          |
| `ifconfig eth0 up`           | `ip link set eth0 up`                  |
| `ifconfig eth0 192.168.1.10` | `ip addr add 192.168.1.10/24 dev eth0` |
| `route -n`                   | `ip route`                             |
| `arp -a`                     | `ip neigh`                             |
| `netstat -tlnp`              | `ss -tlnp`                             |
| `netstat -i`                 | `ip -s link`                           |

无线网卡另装 `iw`，速率双工看 `ethtool`，路径丢包用 `mtr`，抓包用 `tcpdump`。
工具和 Arch 侧完全一样，差别只在安装命令。

## 2. SSH 客户端：从这台机器连出去

openSUSE 把 SSH 拆成子包，先看清楚再装：

```bash
zypper se -s openssh
sudo zypper in openssh-clients      # ssh、scp、sftp
```

```bash
ssh-keygen -t ed25519 -C "lhj@opensuse"   # 一路回车，默认存 ~/.ssh/id_ed25519
ssh-copy-id 用户名@目标主机                # 公钥追加到对方 authorized_keys
ssh 用户名@目标主机                        # 验证免密登录
```

`~/.ssh/config` 的写法与 Arch 一致：

```text
Host nas
    HostName 192.168.1.20
    User lhj
    Port 22
    IdentityFile ~/.ssh/id_ed25519
    ServerAliveInterval 60
```

配好后 `ssh nas` 即可。`ServerAliveInterval` 防 NAT 掐空闲连接，挂 `tmux`
跑长任务时有用。

权限不对时 SSH 会静默拒绝密钥，检查两处：

```bash
chmod 700 ~/.ssh
chmod 600 ~/.ssh/authorized_keys ~/.ssh/id_ed25519
```

openSUSE 默认启用 firewalld，但出站连接不受限制，这一节不用动防火墙。

## 3. SSH 服务端：让别的机器连进来

```bash
sudo zypper in openssh-server
sudo systemctl enable --now sshd
systemctl status sshd
ss -tlnp | grep :22          # 确认在监听
```

**openSUSE 的坑在防火墙**：firewalld 默认开着，`ss` 看到本机在监听，外部却
连不上。放行 ssh：

```bash
sudo firewall-cmd --add-service=ssh --permanent
sudo firewall-cmd --reload
sudo firewall-cmd --list-services        # 确认 ssh 在列表里
```

首次启动时 sshd 会自动生成主机密钥（`/etc/ssh/ssh_host_*`）；从备份恢复的系统
没有这些文件时，补一条 `sudo ssh-keygen -A`。

### 3.1 加固配置

先看 `/etc/ssh/sshd_config` 顶部有没有 `Include /etc/ssh/sshd_config.d/*.conf`：
有就写单独文件，没有就直接改本体。

```ini
# /etc/ssh/sshd_config.d/10-hardening.conf
PermitRootLogin no
PasswordAuthentication no
KbdInteractiveAuthentication no
```

```bash
sudo systemctl restart sshd
```

**顺序很重要**：先确认公钥登录能通，再关密码登录。改完留一个已登录的 SSH
会话别关，另开窗口测新连接，出问题还能用旧会话改回去。

改端口的话，除了 `sshd_config`，还要同步防火墙：

```bash
sudo firewall-cmd --add-port=2222/tcp --permanent
sudo firewall-cmd --reload
```

## 4. 传文件与端口转发

```bash
scp 文件 nas:/tmp/                       # 小文件
rsync -avP 目录/ nas:/backup/目录/       # 大目录，可断点续传
ssh -L 8080:localhost:80 nas             # 本地 8080 转发到 nas 的 80
ssh -R 9000:localhost:3000 nas           # 把本地 3000 暴露到 nas 的 9000
```

排查"服务只有本机能访问"时，`ssh -L` 是最快的验证：隧道能打开，说明服务本身
没问题，问题在监听地址或防火墙。

## 5. 第三方源：Packman 与 OBS

openSUSE 没有 AUR，对应的生态是 **OBS**（社区构建）和 **Packman**（多媒体）：

| 源      | 提供什么           | 怎么加                                            |
|---------|--------------------|---------------------------------------------------|
| Packman | 编解码器、多媒体包 | `opi codecs` 或手动 `zypper ar -f <地址> packman` |
| OBS     | 新版本软件、冷门包 | `opi 包名`，自动加对应仓库                        |

```bash
sudo zypper in opi
opi codecs          # 装多媒体编解码器，会提示加 Packman
opi 包名            # 在 OBS 里搜索并安装
```

装完 Packman 的包后要统一 vendor，否则只装不生效：

```bash
sudo zypper dup --from packman
```

和 AUR 一样，第三方源没有官方审核，装之前看一眼是哪个 home 项目、最近有没有
人维护。加源、调优先级、删源的命令见 [04.zypper.md](04.zypper.md) 第 5 节。

## 6. 验收清单

- [ ] `git --version`、`rg --version`、`cmake --version`、`7z` 都有输出
- [ ] `ip -br a`、`ss -tlnp` 正常；装了 `net-tools` 的话 `ifconfig` 也能用
- [ ] `dig archlinux.org` 能返回解析结果（DNS 正常）
- [ ] `ssh -V` 正常，`ssh-keygen` 生成的密钥在 `~/.ssh/` 下
- [ ] `ssh-copy-id` 后能免密登录目标机器
- [ ] `systemctl status sshd` 是 active，`ss -tlnp` 能看到 22 端口
- [ ] 从另一台机器 `ssh 本机用户@本机IP` 能进来（防火墙已放行）
- [ ] 关掉密码登录后，新连接仍能用密钥登录（旧会话先别关）
- [ ] `opi --version` 可用（如果装了）
