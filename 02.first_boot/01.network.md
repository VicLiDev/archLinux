# 首次启动后没有网络：无 IPv4 地址与 DNS 解析失败

- **场景**：系统装完第一次启动，还没有可用的网络管理工具
- **网络**：有线连接，网卡名 `enp3s0`
- **症状**：`ping` 不通、`pacman` 报 `Could not resolve host`
- **目标**：恢复网络并把配置固化，让重装后不再踩同一个坑
- **涉及命令**：`ip link`、`ip a`、`systemd-networkd`、`/etc/resolv.conf`

> Live 安装环境里遇到同样症状时，第 1～5 节的排查步骤完全一致，区别只是
> Live 环境的 `/etc/resolv.conf` 重启后失效，而本机（装好的系统）需要把配置
> 真正落盘，见第 6 节。

## 0. 快速修复清单

下次遇到同样症状（有线、网卡 `enp3s0`），按顺序执行这四步通常能直接搞定：

```bash
ip link set enp3s0 up                      # 1. 拉起网卡，确认 NO-CARRIER 已消失
printf '[Match]\nName=enp3s0\n\n[Network]\nDHCP=yes\n' \
  > /etc/systemd/network/20-wired.network  # 2. 让 systemd-networkd 去要 IP
systemctl restart systemd-networkd
ip a show enp3s0                           # 3. 必须看到 inet 192.168.x.x
printf 'nameserver 223.5.5.5\nnameserver 114.114.114.114\n' \
  > /etc/resolv.conf                       # 4. 补 DNS，然后 pacman -Sy 验证
```

刚装完的系统里可能还没建普通用户，默认以 root 登录，以上命令可不加 `sudo`；
若已切到普通用户则补 `sudo`。每一步失败的原因见后面的分阶段说明。

## 1. 现象

执行 `pacman -Sy`（或安装阶段的 `pacstrap`）时终端疯狂刷屏报错：

```text
error: failed retrieving file 'core.db' from mirrors.xxx : Could not resolve host
```

直接测连通性也失败：

```text
# ping 8.8.8.8
ping: connect: Network is unreachable
```

两条报错指向的是**不同层**的问题，按顺序拆开看：

| 报错                                    | 含义                  | 问题所在                        |
|-----------------------------------------|-----------------------|---------------------------------|
| `ping: connect: Network is unreachable` | 本机没有可用路由/IP   | 网卡 DOWN、无链路、无 DHCP 租约 |
| `Could not resolve host`                | 有 IP，但域名解析失败 | `/etc/resolv.conf` 里的 DNS     |

因此排查顺序是：**网卡 UP → 物理链路 → IPv4 地址 → DNS → 再试 pacman**，
不要把 DNS 问题当成网络不通来查。

## 2. 阶段一：网卡未激活 + 权限不足

先看接口是否被内核识别、是否处于 UP：

```bash
ip link
```

输出里的有线网卡为 `enp3s0`，且带 `<BROADCAST,MULTICAST, ..., DOWN>` 标志，
说明网卡存在但处于 DOWN 状态，自然不会转发任何流量。

直接执行 `ip link set enp3s0 up` 报 `Operation not permitted`，说明当前不是 root。
用 sudo 提权后拉起网卡：

```bash
sudo ip link set enp3s0 up
```

## 3. 阶段二：NO-CARRIER（没插好网线）与拿不到 IP

网卡 UP 之后再看一次，状态里出现 `NO-CARRIER`：

```text
2: enp3s0: <NO-CARRIER,BROADCAST,MULTICAST,UP> ... state DOWN ...
```

`NO-CARRIER` 表示**物理链路没通**（对端没通电/没插好/网线坏/路由器口坏），
这一层不修复，后面配 IP、配 DNS 全是白费。处理方式：

1. 重新插拔网线，确认路由器对应端口的指示灯亮；
2. 换一根网线或换一个路由器口复测；
3. 直到 `ip link` 输出里 `NO-CARRIER` 消失。

链路通了之后，下一步是拿到 IP。新装系统里**默认没有 `dhcpcd`**，通常也没有
NetworkManager，但 `systemd-networkd` 随 `systemd` 一起装好了，直接启用即可：

```bash
systemctl enable --now systemd-networkd
ip a show enp3s0
```

## 4. 阶段三：只有 IPv6，没有 IPv4

上一步之后检查地址，发现问题：接口上只有 `inet6`（链路本地地址），没有
`inet`（IPv4），所以 `ping 8.8.8.8` 依然 `Network is unreachable`。

原因是 `systemd-networkd` 需要一份匹配该网卡的 `.network` 配置文件才会去
跑 DHCP；没有配置文件时它不会替你请求租约。手动创建一份：

```bash
nano /etc/systemd/network/20-wired.network
```

内容如下（`DHCP=yes` 同时请求 IPv4 与 IPv6）：

```ini
[Match]
Name=enp3s0

[Network]
DHCP=yes
```

保存退出（`Ctrl+X` → `Y` → `Enter`），重启服务并复查：

```bash
systemctl restart systemd-networkd
ip a show enp3s0
```

结果拿到 IPv4 地址（本例为 `192.168.7.209/24`），说明物理层、链路层、
网络层的 DHCP 都通了。

> 提示：网卡名不一定是 `enp3s0`，用 `ip link` 确认后替换即可；若想一劳永逸
> 兼容多台机器，可把 `Name=enp3s0` 换成 `Name=en*`。

## 5. 阶段四：有 IP 但 DNS 解析失败

此时 `ping 8.8.8.8` 已经通，但 `pacman` 仍报 `Could not resolve host`，
说明缺 DNS。先确认当前内容：

```bash
cat /etc/resolv.conf
ls -l /etc/resolv.conf    # 若为符号链接，写入会落到链接目标上
```

写入公共 DNS（阿里云 + 114DNS）：

```bash
sh -c 'echo -e "nameserver 223.5.5.5\nnameserver 114.114.114.114" > /etc/resolv.conf'
```

验证解析与下载链路：

```bash
ping -c 3 archlinux.org
pacman -Sy
```

`ping` 能返回域名对应的 IP、`pacman -Sy` 不再报错，即表示网络彻底打通。

## 6. 把配置固化（避免重启后复发）

第 4、5 节的做法能立刻上网，但 `resolv.conf` 是手写的静态文件，切换网络
（换 Wi-Fi、换路由器、连 VPN）后会被覆盖或失效。装好后按需选一套长期方案：

**方案 A：NetworkManager（桌面环境首选）**

```bash
pacman -S networkmanager
systemctl enable --now NetworkManager
```

之后由 `nmcli` / `nmtui` 接管有线、无线、VPN，DNS 也由它下发给
`/etc/resolv.conf`。这套装完后可以不再手动维护 `.network` 文件。

**方案 B：systemd-networkd + systemd-resolved（服务器/极简首选）**

```bash
ln -sf /run/systemd/resolve/stub-resolv.conf /etc/resolv.conf
systemctl enable --now systemd-resolved
```

`systemd-resolved` 随 `systemd` 包提供，不需要单独 `pacman -S`。再给
`20-wired.network` 的 `[Network]` 段补一行 `DNS=223.5.5.5`，让 DNS 也由
networkd 下发，而不是继续手写 `resolv.conf`。

> 两个都不要选就等于维持手动配置：能上网，但每次换网络环境都得重写一遍
> `resolv.conf`，这是这次踩坑的根源。

## 7. 排障总结

1. **先看两层**：`ip link` 看网卡是否被识别、是否 UP（有没有 `NO-CARRIER`）；
   `ip a` 看是否拿到 `192.168.x.x`。拿到 IPv4 之前，谈 DNS 没有意义。
2. **分清报错层级**：
   - `Network is unreachable` → 没有 IP 或没有路由，问题在网卡 / 链路 / DHCP；
   - `Could not resolve host` → 有 IP 没有 DNS，问题在 `/etc/resolv.conf`。
3. **别急着装工具**：新系统里没有 `dhcpcd` 是正常的，`systemd-networkd` +
   一份 `.network` 文件就够，不联网也能直接写文件，比找安装包快。
4. **临时修复要收尾**：`ip link set up` 和手写 `resolv.conf` 都只活在本次
   启动周期里，装完系统一定要用 NetworkManager 或 resolved 接管，否则重启即复发。
5. **安装阶段的对应关系**：`arch-chroot` 里的 `/etc/resolv.conf` 由安装脚本
   临时挂载，只保证 chroot 内联网；真正的网络配置必须写进目标系统。
