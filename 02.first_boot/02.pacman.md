# pacman 用法：装包、查包与日常维护

- **阶段**：首次开机，装任何软件之前先花十分钟把这套命令弄熟
- **目标**：知道每条命令该在什么时候用、看得懂报错、不再靠搜索引擎抄命令
- **一句话**：日常只需要 `pacman -Syu` 和 `pacman -S 包名`，其余都是排错和清理

## 1. 索引与数据库：pacman 的信息从哪来

pacman 本身不包含任何包的信息，它靠几份**索引**工作。索引就是一份目录清单：
只记录"有哪些东西、在哪里、什么版本"，不含东西本身。好比图书馆的检索卡片柜
和书架上书的关系——卡片告诉你书在哪一层，真正取书还得按卡片去找。

### 1.1 四份数据

| 路径                              | 是什么                                       | 谁在用           |
|-----------------------------------|----------------------------------------------|------------------|
| `/var/lib/pacman/sync/*.db`       | 仓库索引：包名、版本、依赖、校验和、下载地址 | `-S` 系列        |
| `/var/lib/pacman/local/`          | 本机已装库：版本、安装原因、文件清单         | `-Q` 系列        |
| `/var/lib/pacman/sync/core.files` | 文件索引：哪个包提供某个路径                 | `-F`（先 `-Fy`） |
| `/var/lib/pacman/db.lck`          | 锁文件，防并发修改                           | 报锁错误时就是它 |

这里最容易混的是两份数据索引的对象不同：

- **仓库索引**（`/var/lib/pacman/sync/*.db`）：索引远端软件源，`-y` 刷新的是它的
  本地副本；断网后 `-Ss` 只能用旧数据，`-Fy`、`-Syu` 直接失败。
- **本机数据库**（`/var/lib/pacman/local/`）：索引本机装了什么，没有刷新命令，
  装包删包时被动更新；断网也能用 `-Qo`、`-Ql`。

另外两个常被问到的东西不在表里，但同样重要：

- **仓库**：官方分 `core`、`extra`、`multilib`（32 位库，默认注释掉）。包名不带
  仓库前缀，`pacman -S` 按顺序找。
- **包缓存**：下载过的包留在 `/var/cache/pacman/pkg/`，删包、降级都靠它。它存的
  是**包本体**，不是索引。

### 1.2 索引过期会怎样

| 现象                               | 索引层面的原因                       |
|------------------------------------|--------------------------------------|
| `target not found`，但包确实存在   | 索引过期，本地 `core.db` 还是旧的    |
| 刚发布的新包搜不到                 | 同上                                 |
| 装完新包启动失败、程序报库版本错误 | 部分升级：索引是新的，本地包还是旧的 |
| `could not lock database`          | `db.lck` 残留                        |
| `pacman -Qk` 报文件缺失或损坏      | 本机数据库与实际文件对不上           |

### 1.3 为什么 `-Syu` 必须连写

1. 索引描述的是**仓库现在的样子**，不知道你本机装了什么。
2. `-y` 把索引换成最新版，等于换了一张新地图。
3. 此后装包时，pacman 拿**新索引**做依赖求解，默认"全世界都是最新版本"。
4. 它可能要求某个依赖 ≥ 2.0，而你本机还是 1.0——于是产生半新半旧的状态。

`-u` 的作用就是让本机状态追上这张新地图，所以 `-y` 和 `-u` 要一起出现。
这正是第 5 节部分升级的根源。

### 1.4 为什么 `-F` 还要先 `-Fy`

`core.db` 只存元数据（名字、版本、依赖），体积小；每个包内含哪些文件记在
`core.files` 里，体积大得多，默认不下载。所以第一次 `pacman -F 文件名` 会提示
找不到，先 `pacman -Fy` 把文件索引拉下来。

## 2. 命令怎么读：一个大写操作 + 若干小写修饰

pacman 的选项是**两层**的：开头的大写字母决定"对哪类数据动手"，后面的小写字母
是修饰。`-Syu` 就是 `-S -y -u`，`-Qdtq` 就是 `-Q -d -t -q`。

### 2.1 大写：对谁动手

| 操作 | 全称    | 作用                               | 例子                       |
|------|---------|------------------------------------|----------------------------|
| `-S` | Sync    | 与仓库同步：装包、更新             | `pacman -S vim`            |
| `-R` | Remove  | 卸载本地已装的包                   | `pacman -R vim`            |
| `-Q` | Query   | 查本机已装包的数据                 | `pacman -Q vim`            |
| `-U` | Upgrade | 装一个本地包文件（也用于降级）     | `pacman -U 包.pkg.tar.zst` |
| `-F` | Files   | 查仓库的文件索引，反查哪个包提供它 | `pacman -F vim`            |

记法：`S` 与 `Q` 是一对（仓库 ↔ 本地），`R` 是删，`U` 绕过仓库直接装文件，
`F` 只查不动。另有 `-T`（Deptest，检查依赖是否满足）和 `-D`（Database，改本地
数据库元数据），用得少，知道存在即可。

### 2.2 小写：怎么动手

| 字母 | 读法               | 作用                                   | 常见组合             |
|------|--------------------|----------------------------------------|----------------------|
| `y`  | refresh            | 刷新仓库索引                           | `-Sy`                |
| `u`  | upgrade            | 升级到最新版本                         | `-Su`                |
| `s`  | search / recursive | 搜索；在 `-R` 下改为递归删依赖         | `-Ss`、`-Rs`         |
| `i`  | info               | 显示包信息                             | `-Si`、`-Qi`         |
| `l`  | list               | 列出包里的文件清单                     | `-Ql`                |
| `o`  | owner              | 反查文件属于哪个包                     | `-Qo`                |
| `e`  | explicit           | 手动显式安装的包                       | `-Qe`                |
| `d`  | dependency         | 作为依赖被装进来的；也是"忽略依赖检查" | `-Qdt`、`-Rd`        |
| `t`  | unrequired         | 不再被任何包需要                       | `-Qdt`               |
| `c`  | clean / cascade    | 清缓存；在 `-R` 下级联删除             | `-Sc`、`-Rc`         |
| `n`  | nosave             | 不保留改过的配置文件                   | `-Rns`               |
| `q`  | quiet              | 只输出名字，方便接管道                 | `-Qdtq`              |
| `w`  | download only      | 只下载安装包，不安装                   | `-Sw`                |
| `k`  | check              | 校验包文件是否完整                     | `-Qk`                |
| `g`  | group              | 按包组列出成员                         | `-Sg gnome`          |
| `m`  | foreign            | makepkg / AUR 编出来的包               | `-Qm`                |
| `p`  | package file       | 直接操作单个包文件                     | `-Qp 包.pkg.tar.zst` |

**同一个字母在不同操作下意思会变**，这是 pacman 最反直觉的地方：

- `-Ss` 是搜索，`-Rs` 是"连同依赖一起删"
- `-Si` 看仓库里的包，`-Qi` 看本机装了的包
- `-Sc` 清缓存，`-Rc` 级联删掉"依赖这个包的包"
- `-Qd` 列出依赖包，`-Rd` 是跳过依赖检查

所以读命令时**先确定大写操作，小写的意思就唯一了**。反过来说，看到一条没见过的
pacman 命令，先把第一个大写字母圈出来，剩下的自然能猜个八九不离十。

### 2.3 逐字母读几条常用命令

```text
pacman -Syu              S 同步 + y 刷索引 + u 升级        → 全量更新
pacman -S --needed pkg   S 装包 + --needed 跳过已是最新    → 批量安装
pacman -Rns pkg          R 卸载 + n 不留配置 + s 连依赖删  → 干净卸载
pacman -Qdtq             Q 查本地 + d 依赖装的 + t 无人依赖 + q 只出名字 → 孤包
pacman -Qo /path/to/file Q 查本地 + o 查归属                → 这文件是谁装的
pacman -Qe               Q 查本地 + e 显式装的               → 我主动装的包
pacman -Sw pkg           S 同步 + w 只下载                   → 只要安装包
pacman -Sc               S 同步库 + c 清理                   → 清掉旧缓存
```

### 2.4 记忆抓手

- **大写字母决定对谁动手**：仓库（S）、本地（Q）、删除（R）、单个文件（U/F）。
- **小写字母决定怎么动手**：`y`/`u` 是刷新与升级，`s`/`i`/`l`/`o` 是找与看，
  `n`/`c`/`w` 是删、清、下时附带的边界条件。
- 记不清就去查：`pacman --help` 是总览，`pacman -S --help` 只看同步类的参数，
  比背表快，而且能确认当前版本支持哪些修饰。

## 3. 安装、删除、更新

```bash
pacman -Syu                  # 刷新索引 + 全量升级，日常维护就用这一条
pacman -S 包名               # 装包（已装过会重装一遍）
pacman -S --needed 包名      # 装包，已装且最新则跳过（写脚本/批量装时用）
pacman -R 包名               # 删包，保留依赖
pacman -Rs 包名              # 删包 + 删除不再被需要的依赖
pacman -Rns 包名             # 再顺手删掉 pacman 自己生成的配置文件
pacman -U 包文件.pkg.tar.zst # 装本地包（降级、离线安装都走这条）
```

`-Rns` 是"干净卸载"的默认选择，但要注意：**配置文件里改过的内容会丢**，
删之前先备份 `/etc` 下对应的文件。

## 4. 查询：定位问题的核心手段

```bash
pacman -Ss 关键词        # 在仓库里搜包
pacman -Si 包名          # 看包信息：版本、依赖、仓库、体积
pacman -Qs 关键词        # 在本机已装的包里搜
pacman -Qi 包名          # 看已装包的信息：安装时间、依赖、被谁依赖
pacman -Ql 包名          # 这个包装了哪些文件
pacman -Qo /路径/文件    # 这个文件属于哪个包
pacman -Qe               # 手动装的包（排除依赖）
pacman -Qdt              # 孤包：没人依赖、也不是手动装的
pacman -Fy && pacman -F 文件名   # 按文件名搜包（先建文件索引）
```

`pacman -Qo` 是最常用的排错命令：系统里出现一个不认识的配置文件时，先确认它
属于哪个包，再决定改还是删。

## 5. 更新与"部分升级"的坑

`-y` 只刷新索引，`-u` 才升级。**单独用 `pacman -Sy` 再装包是禁止操作**：
索引是新的、已装的库还是旧的，依赖关系对不上时会出现"装了新包反而启动不了"。
Arch 官方把这种状态叫 partial upgrade，是新手踩得最多的坑。

```bash
pacman -Sy                 # ❌ 只刷索引，之后装包 = 部分升级
pacman -Sy 包名            # ❌ 等价于部分升级
pacman -Syu 包名           # ✅ 先全量升级，再装这个包
```

另一种常见误区是"先 `-Sy` 看看有没有新版本"，正确做法是直接 `pacman -Syu`；
想先看会升哪些包，用 `pacman -Qu`（列出可升级的包）。

## 6. 配置文件里值得打开的几个选项

`/etc/pacman.conf`：

```ini
Color                 # 彩色输出，读报错更快
ILoveCandy            # 进度条变成吃豆人（纯装饰，可选）
ParallelDownloads = 5 # 并行下载，国内镜像上明显更快
VerbosePkgLists       # 升级时列出每个包的版本变化
```

要用 32 位库（Steam、Wine）时取消 `[multilib]` 段的注释：

```ini
[multilib]
Include = /etc/pacman.d/mirrorlist
```

改完不用重启什么，下一条 `pacman` 命令就生效。

## 7. 镜像源

`/etc/pacman.d/mirrorlist` 越靠前的镜像越优先。手动挑几个国内源放前面即可，
想自动测速排序用 `reflector`：

```bash
pacman -S reflector
reflector --country China --protocol https --latest 10 --sort rate \
  --save /etc/pacman.d/mirrorlist
```

`reflector` 自带 `reflector.timer`，需要定期自动更新就
`systemctl enable --now reflector.timer`，配置写在 `/etc/xdg/reflector/`。

## 8. 缓存、降级与清理

```bash
ls /var/cache/pacman/pkg/            # 里面是所有下载过的包
pacman -U /var/cache/pacman/pkg/旧版本.pkg.tar.zst   # 降级
pacman -Sc                           # 删掉已卸载包的缓存
pacman -Scc                          # 清空全部缓存（之后就没法降级了）
paccache -r                          # 只保留最近 3 个版本（pacman-contrib）
```

升级后某个程序坏了，最常见的原因就是新版本有 bug，用缓存里的旧包
`pacman -U` 回到上一版，等修复再升。所以**不要随手 `pacman -Scc`**。

## 9. 常见报错对照

| 报错                                           | 原因                  | 处理                                             |
|------------------------------------------------|-----------------------|--------------------------------------------------|
| `invalid or corrupted package (PGP signature)` | keyring 过期          | `pacman -Sy archlinux-keyring && pacman -Su`     |
| `conflicting files`                            | 两个包装同一路径      | `pacman -Qo 该文件` 查归属，再决定 `--overwrite` |
| `could not lock database`                      | 上次中断留下 `db.lck` | 确认无 pacman 进程后 `rm /var/lib/pacman/db.lck` |
| `target not found`                             | 包名拼错或仓库未启用  | `pacman -Ss` 搜；multilib 包要开 `[multilib]`    |
| `failed retrieving file`                       | 镜像不可用 / 网络问题 | 换镜像，见 [01.network.md](01.network.md)        |
| `insufficient disk space`                      | 磁盘满                | `df -h` 看哪个分区，清理缓存或扩容               |
| `unable to lock database`（重装后）            | 上次升级被强杀        | 同上，删锁前先确认没有 pacman 进程在跑           |

## 10. 日常命令卡

```bash
pacman -Syu                        # 每周至少一次
pacman -S --needed 包名            # 装东西
pacman -Rns 包名                   # 干净卸载
pacman -Qo /etc/某文件             # 这文件谁装的
pacman -Qdtq | wc -l               # 有多少孤包
pacman -Sc                         # 定期清缓存（保留最近版本）
```

装包过程中每一步都会提示 `:: Proceed with installation? [Y/n]`，
脚本里想跳过交互就加 `--noconfirm`，但**手动操作时不要加**，看清楚它要装什么。
