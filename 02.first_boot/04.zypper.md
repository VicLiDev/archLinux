# zypper 用法：openSUSE 上装包、查包与回滚

- **阶段**：在 openSUSE Leap 上第一次认真用命令行装东西
- **目标**：把 pacman 那套肌肉记忆翻译成 zypper，看得懂报错，知道什么时候
  该 `up`、什么时候该 `dup`
- **一句话**：日常是 `sudo zypper ref && sudo zypper up` 和 `sudo zypper in 包名`，
  其余都是排错、换源和回滚

## 1. 索引与数据库：zypper 的信息从哪来

zypper 自己不含任何软件信息，它读的是**仓库元数据**和**本机 RPM 数据库**。
把这两者分清，后面所有报错都能归位。

### 1.1 四份数据

| 路径                          | 是什么                                                | 谁在用                  |
|-------------------------------|-------------------------------------------------------|-------------------------|
| `/etc/zypp/repos.d/*.repo`    | 仓库定义：地址、启用状态、优先级、GPG 校验            | `zypper lr`、`ar`、`mr` |
| `/var/cache/zypp/`            | 缓存：`raw/` 元数据、`solv/` 解算结果、`packages/` 包 | `ref`、`in`             |
| `/var/lib/rpm/`               | RPM 数据库：本机装了什么、文件归属                    | `rpm -q*`、`se -i`      |
| `/var/lib/zypp/AutoInstalled` | 哪些包是"作为依赖自动装的"                            | 判断能不能删            |

另外两个常被问到的东西：

- **历史**：`/var/log/zypp/history` 记录每次装删，`zypper history` 就是读它。
- **锁**：`/var/run/zypp.pid`，同一时刻只允许一个 zypper 改系统。

和 pacman 一样，索引对象分两类，这是理解"为什么断网还能查"的关键：

- **仓库元数据**（`/var/cache/zypp/raw`、`solv`）：索引远端软件源，`zypper ref`
  刷新的是本地副本；断网后 `zypper se` 还能用旧数据，`in`、`up` 会失败。
- **RPM 数据库**（`/var/lib/rpm`）：索引本机已装内容，没有刷新命令，装删时被动
  更新；断网也能 `rpm -qf`、`rpm -ql`。

### 1.2 索引过期会怎样

| 现象                                            | 原因                                 |
|-------------------------------------------------|--------------------------------------|
| `Package 'xxx' not found`，但包确实存在         | 元数据过期，或该仓库 `autorefresh=0` |
| 刚加完源却搜不到包                              | 没跑 `zypper ref`                    |
| `File ... conflicts with file from package ...` | 两个仓库提供同一路径，见第 5 节      |
| `System management is locked by ...`            | 另一个 zypper/YaST 在跑，或锁残留    |
| `Problem: nothing provides ...`                 | 缺依赖仓库，常见是 Packman 没加      |

### 1.3 为什么有 `up` 和 `dup` 两条更新命令

从 pacman 迁过来最容易懵的就是这里：

| 命令           | 做什么                                    | 什么时候用              |
|----------------|-------------------------------------------|-------------------------|
| `zypper up`    | 已装包升到仓库最新版，不删包、不换 vendor | Leap 日常               |
| `zypper patch` | 只装官方发布的补丁                        | Leap 日常（更保守）     |
| `zypper dup`   | 允许降级、换 vendor、删包，整体对齐仓库   | Tumbleweed；Leap 跨版本 |

Leap 是固定版本发行版，一个生命周期内包版本基本不动，日常 `up` 或 `patch` 就够。
`dup` 用在"整机切到另一个版本集合"的场合，比如 15.6 升 16.0：

```bash
sudo zypper --releasever=16.0 dup --download-in-advance
```

用错方向的代价不对称：Leap 上天天 `dup`，会把第三方源的包也一起换 vendor；
Tumbleweed 上只 `up`，系统会长期停在半旧状态，最后依赖解不开。

### 1.4 为什么一般不用手动 `ref`

zypper 默认在每次 `in`、`up` 前自动刷新（仓库的 `autorefresh=1`）。手动 `ref`
只在三种时候需要：刚用 `ar` 加了源、某仓库关掉了自动刷新、想确认元数据能不能
拉到。pacman 里 `-Sy` 必须和 `-u` 连写，zypper 没有这个约束——它刷新后不会把
系统留在半新半旧的状态。

## 2. 命令怎么读：zypper 用"缩写子命令"

pacman 是"一个大写字母 + 小写修饰"，zypper 反过来：**第一个词就是动作**，
而且几乎都是英文单词的前几个字母。读懂缩写，命令就不用背。

### 2.1 子命令：动作是什么

| 缩写        | 全称              | 作用                        |
|-------------|-------------------|-----------------------------|
| `ref`       | refresh           | 刷新仓库元数据              |
| `in`        | install           | 装包，可配 `-t pattern`     |
| `rm`        | remove            | 卸载                        |
| `up`        | update            | 升级已装包                  |
| `dup`       | dist-upgrade      | 整体对齐仓库（滚动/跨版本） |
| `patch`     | —                 | 只装官方补丁                |
| `se`        | search            | 搜索                        |
| `if`        | info              | 看包信息                    |
| `lr`        | list-repos        | 列出仓库                    |
| `ar` / `rr` | add / remove repo | 加源 / 删源                 |
| `mr`        | modify-repo       | 启用、禁用、调优先级        |
| `al` / `rl` | add / remove lock | 锁住包 / 解锁               |
| `ps`        | processes         | 谁还在用已删除的库          |
| `ve`        | verify            | 校验依赖完整性              |
| `wp`        | what-provides     | 反查文件或能力由谁提供      |

### 2.2 全局修饰：怎么动手

| 参数           | 含义               | 常见用法                   |
|----------------|--------------------|----------------------------|
| `-n`           | 非交互，全部选默认 | 脚本里用                   |
| `-y`           | 自动确认           | `zypper -y in 包名`        |
| `-d`           | 只下载不安装       | `zypper in -d 包名`        |
| `-f`           | 强制重装           | `zypper in -f 包名`        |
| `-t`           | 指定对象类型       | `-t pattern`、`-t package` |
| `-r`           | 指定仓库           | `zypper in -r 源 包名`     |
| `--from`       | 从指定仓库装       | 解决 vendor 冲突           |
| `-D`           | 只演算不执行       | 升级前先看一眼             |
| `--no-refresh` | 本次不刷新元数据   | 断网时查本地状态           |

### 2.3 逐条读几条常用命令

```text
zypper ref                  ref 刷新元数据              → 加源后第一件事
zypper in vim               in 装包                     → 装单个包
zypper in -t pattern xfce   in + -t pattern 装整套      → 装桌面环境
zypper rm --clean-deps pkg  rm + 连自动依赖一起删        → 干净卸载
zypper up                   up 升级已装包               → Leap 日常
zypper dup                  dup 整体对齐                → 滚动/跨版本
zypper se -s vim            se + -s 看各仓库版本        → 会从哪装
zypper wp /usr/bin/vim      wp 反查文件归属             → 这文件谁装的
zypper ps -s                ps + -s 只看服务            → 升级后谁要重启
```

### 2.4 记忆抓手

- **子命令就是英文缩写**：ref/in/rm/up/se/if/lr/ar/mr，念一遍全称就记住了。
- **`up` 是往前挪，`dup` 是换地图**：前者升版本，后者换整个版本集合。
- **`ps` 不是进程列表工具**，是"升级后谁还在用旧库"的检查器。
- 查不到就 `zypper help`、`zypper help in`，比搜博客准。

## 3. 安装、删除、更新

```bash
sudo zypper ref                        # 刷新元数据，加源后手动跑一次
sudo zypper in 包名                    # 装包
sudo zypper in -t pattern devel_basis  # 装一整组（编译工具链）
sudo zypper rm 包名                    # 卸载，保留自动装的依赖
sudo zypper rm --clean-deps 包名       # 连不再需要的依赖一起删
sudo zypper up                         # 升级已装包（Leap 日常）
sudo zypper patch                      # 只打官方补丁
sudo zypper dup                        # 整体对齐（Tumbleweed / 跨版本）
```

`rm --clean-deps` 会顺手动 `AutoInstalled` 里标记的包，删之前先演算一遍：

```bash
sudo zypper rm -D --clean-deps 包名
```

## 4. 查询：定位问题的核心手段

```bash
zypper se 关键词              # 搜包，默认匹配名字和摘要
zypper se -s 关键词           # 列出每个仓库里的版本、架构、是否已装
zypper se -i -t pattern       # 本机装了哪些 pattern
zypper if 包名                # 包信息：版本、依赖、来源仓库
zypper wp /usr/bin/某文件     # 这个文件由哪个包提供
rpm -qa | grep 关键词         # 本机已装（相当于 pacman -Qs）
rpm -qf /路径/文件            # 文件属于哪个包
rpm -ql 包名                  # 这个包装了哪些文件
rpm -qi 包名                  # 已装包的详细信息
```

`rpm` 那四条断网也能用，是 zypper 不可用时的兜底；`zypper wp` 则依赖元数据
完整。排查"这个文件哪来的"时，两条路都值得试。

## 5. 仓库：zypper 的"镜像源 + AUR"

```bash
zypper lr -d                 # 仓库列表：编号、名称、启用状态、优先级、地址
zypper lr -u                 # 只看地址，确认是不是官方源
sudo zypper ar -f 地址 别名   # 加源，-f 表示加完立即刷新
sudo zypper mr -d 1          # 禁用 1 号源（编号来自 lr）
sudo zypper mr -e 1          # 重新启用
sudo zypper mr -p 90 1       # 优先级调到 90（数字越小越优先）
sudo zypper rr 1             # 删除 1 号源
```

Leap 默认只有 OSS、Non-OSS、Update 几个官方源，日常够用。需要额外内容时：

| 需求         | 源            | 说明                                                 |
|--------------|---------------|------------------------------------------------------|
| 多媒体编解码 | Packman       | 官方因专利不打包，装完要统一 vendor                  |
| 新版本软件   | OBS           | 社区构建，相当于 Arch 的 AUR                         |
| NVIDIA 驱动  | NVIDIA 官方源 | 见 [03.install_gui](../03.install_gui/01.desktop.md) |

OBS 上找包用 `opi`，比翻网页快：

```bash
sudo zypper in opi
opi 包名
```

装完 Packman 的编解码器，必须把相关包换成 Packman 版本，只 `up` 不会换
vendor，编解码器依旧不工作：

```bash
sudo zypper dup --from packman
```

## 6. 用 pattern 装整套软件（桌面就是这么来的）

openSUSE 把"一组常一起用的包"叫 **pattern**。装桌面、装开发工具、装打印支持
都是装 pattern，而不是一长串包名。

```bash
zypper se -t pattern                    # 仓库里有哪些 pattern
zypper se -i -t pattern                 # 本机装了哪些
sudo zypper in -t pattern xfce          # Xfce 桌面
sudo zypper in -t pattern kde_plasma    # KDE Plasma
sudo zypper in -t pattern gnome         # GNOME
sudo zypper in -t pattern devel_basis   # 编译工具链
```

pattern 名在各版本略有差异，先 `zypper se -t pattern | grep -i gnome` 确认。
装完桌面还要把默认启动目标切过去：

```bash
sudo systemctl set-default graphical.target
sudo systemctl enable --now display-manager
```

这两步正是"装了桌面却只有文字界面"的最常见原因，图形栈排查见
[02.suse-no-desktop.md](../03.install_gui/02.suse-no-desktop.md)。

Leap 15 自带 YaST（`sudo yast2` 图形、`sudo yast` 文本），软件源、服务、引导器
都能点着改；Leap 16 起安装器换成 Agama，YaST 只剩部分模块。命令行熟练后，
YaST 主要用于分区和引导器这类不常改的地方。

## 7. 缓存、快照与回滚

```bash
zypper clean --all            # 清空元数据与包缓存
zypper clean -m               # 只清元数据，保留已下载的 rpm
ls /var/cache/zypp/packages/  # 下载过的 rpm 在这里
zypper history                # 装删历史，读 /var/log/zypp/history
```

Leap 默认 btrfs + snapper，zypper 每次 `in`、`up`、`dup` 前后自动打快照
（`snapper list` 里成对的 pre/post）。升级把系统弄坏了，回滚比重装快：

```bash
sudo snapper list           # 找到升级前那个 pre 快照的编号
sudo snapper rollback 123   # 回滚到该快照，然后重启
```

`rollback` 后当前系统会切到新快照，重启才生效。装系统时没启用 btrfs/snapper
就没有这层保护，只能靠 Live 介质。

## 8. 常见报错对照

| 报错                                 | 原因                       | 处理                                         |
|--------------------------------------|----------------------------|----------------------------------------------|
| `Package 'xxx' not found`            | 元数据过期或包名不同       | `zypper ref` 后 `zypper se 关键词`           |
| `System management is locked by ...` | 另一个 zypper/YaST 在跑    | 等它结束；确认无进程后删 `/var/run/zypp.pid` |
| `Problem: nothing provides 'xxx'`    | 缺依赖仓库（常为 Packman） | 加源后 `zypper ref`，或 `dup --from`         |
| `File ... conflicts with ...`        | 两个源提供同一文件         | `zypper wp 该文件` 查归属，再决定卸哪个      |
| `GPG key ... not known`              | 新源没导入密钥             | `zypper --gpg-auto-import-keys ref`          |
| `Download (curl) error`              | 源地址失效或网络问题       | 见 [01.network.md](01.network.md)            |
| 升级后某服务行为异常                 | 进程还在用旧库             | `zypper ps -s`，重启列出的服务               |
| `There is no update candidate`       | 已是最新，或包被锁         | `zypper locks` 看是否被锁                    |

## 9. 与 pacman 的思维映射

| 想做的事     | Arch（pacman）     | openSUSE（zypper）               |
|--------------|--------------------|----------------------------------|
| 全量更新     | `pacman -Syu`      | `zypper up`（滚动用 `dup`）      |
| 装包         | `pacman -S 包`     | `zypper in 包`                   |
| 干净卸载     | `pacman -Rns 包`   | `zypper rm --clean-deps 包`      |
| 搜仓库       | `pacman -Ss 词`    | `zypper se 词`                   |
| 搜本机       | `pacman -Qs 词`    | `rpm -qa` 再用 grep 过滤         |
| 文件归属     | `pacman -Qo 路径`  | `rpm -qf 路径`                   |
| 包的文件清单 | `pacman -Ql 包`    | `rpm -ql 包`                     |
| 文件反查包   | `pacman -F 文件名` | `zypper wp 路径`                 |
| 装整组       | `pacman -S gnome`  | `zypper in -t pattern gnome`     |
| 清缓存       | `pacman -Sc`       | `zypper clean -m`                |
| 降级         | `pacman -U 旧包`   | `zypper in --oldpackage 包-版本` |
| 第三方源     | AUR + paru         | OBS + opi、Packman               |

`zypper in --oldpackage 包-1.2.3` 要求该版本还在仓库里；Leap 的 Update 源通常
只留最新版，所以真正的降级往往得靠快照回滚。

## 10. 日常命令卡

```bash
sudo zypper ref && sudo zypper up     # 每周维护
sudo zypper in 包名                   # 装东西
sudo zypper rm --clean-deps 包名       # 干净卸载
zypper se -s 关键词                    # 从哪个源装、什么版本
zypper wp /usr/bin/某文件              # 这文件谁装的
sudo zypper ps -s                     # 升级后谁要重启
sudo snapper list                     # 升级前留个心眼
```

zypper 会把要装、删、升级的包全列出来等你确认；脚本里加 `-n` 跳过交互，
手动操作时不要加。
