# 终端与 Shell：Hyprland / niri 下的选择与美化

本文讨论终端模拟器、shell、提示符和复用器的选型，以及字体、配色、透明度、
模糊的配置。默认 Hyprland 或 niri 已经能启动，也能打开至少一个终端。

**一句话结论**：这台机器用 `kitty` 做主力、`foot` 做备用，shell 选 `zsh`，
提示符用 `Starship`，分屏交给 `tmux`；配色统一 Catppuccin Mocha。

本文以 Arch 仓库当前版本为准：Hyprland 0.56、niri 26.04、kitty 0.49、
foot 1.28。旧版本的配置语法可能不同，文内会单独标注。

## 1. 先分清四层

很多人把“换个终端”理解成“换个 shell”，结果装了一堆东西，仍然不知道哪一层
在起作用。四层各司其职：

```text
终端模拟器  kitty / foot / ghostty      负责窗口、字体、颜色、透明
    ↓
shell       zsh / fish / bash           负责解析命令、补全、历史、别名
    ↓
提示符      Starship / OMZ / p10k       负责命令前面那一段文字
    ↓
复用器      tmux / zellij               负责会话、分屏、断开重连
```

几个常见误解：

- **fish 和 kitty 不是二选一**。fish 是 shell，kitty 是终端模拟器，可以同时用。
- **Starship 不是主题**。它是独立的提示符生成器，不提供补全和高亮。
- **平铺合成器里，终端的标签页大多是重复功能**。分屏和会话交给 tmux 更稳。

| 层         | 作用                     | 本机候选                 | 说明                  |
|------------|--------------------------|--------------------------|-----------------------|
| 终端模拟器 | 画窗口、字体、颜色、透明 | kitty、foot、ghostty     | 决定“看起来怎么样”    |
| shell      | 解析命令、补全、历史     | zsh、fish、bash          | 决定“用起来顺不顺”    |
| 提示符     | 显示目录、Git、语言版本  | Starship、OMZ 主题、p10k | 只是 shell 的一层装饰 |
| 复用器     | 会话、分屏、断开重连     | tmux、zellij             | 和终端模拟器无关      |

本机现状：

- `kitty 0.49.2`、`foot 1.28.0`、`tmux 3.8` 已安装。
- 当前登录 shell 是 `zsh`；`starship` 已装，`fish` 未装。
- `~/.zshrc` 已存在，并且会 source `~/bin/_source_cmd_tools.sh`。
- `FiraCode Nerd Font` 已放在 `~/.local/share/fonts/FiraCode/`，图标字体不用另找。

## 2. 终端模拟器怎么选

如果还没装终端和复用器：

```bash
sudo pacman -S --needed kitty foot tmux
```

### 2.1 五个候选

| 终端      | 渲染方式     | 标签/分屏 | 连字/图片            | 适合谁                    |
|-----------|--------------|-----------|----------------------|---------------------------|
| kitty     | GPU / OpenGL | 有        | 连字、图片、远程控制 | 主力日常、需要分屏/连字   |
| foot      | Wayland 原生 | 无        | 无连字，支持 Sixel   | 轻量备用、远程、niri 布局 |
| ghostty   | GPU          | 有        | 连字、图片           | 想要现代默认值、少调配置  |
| alacritty | GPU          | 无        | 无连字               | 只要一个快的窗口          |
| wezterm   | GPU          | 有        | 连字、图片、Lua      | 配置即代码、跨平台        |

这张表只列差异，不排优劣。五者都能在 Hyprland 和 niri 下运行，因为它们都是
Wayland 原生客户端，不需要 XWayland。

### 2.2 Terminator 作为兼容选项

Terminator 可以用，但定位是“兼容/习惯”选项，不是这套桌面的首选。它的优点是
开箱就有标签、网格分屏、输入广播和布局保存，适合同时盯多台机器、又不想用
tmux 的人。缺点是实现较老：Python + GTK/VTE，没有 GPU 渲染；Arch 包依赖
`libkeybinder3`，在 Wayland 会话里通常经 XWayland 运行，不是 kitty/foot 这样
的 Wayland 原生客户端。透明背景可以配，但模糊和缩放细节取决于合成器对
XWayland 窗口的支持。

如果要用：

```bash
sudo pacman -S terminator
```

配置文件在 `~/.config/terminator/config`，布局和快捷键大多能在右键
Preferences 里改。niri 运行 X11 程序需要 `xwayland-satellite`，本机已安装；
Hyprland 自带 XWayland。

结论：已经习惯 Terminator 的标签和输入广播，可以继续用；想要轻量、原生
Wayland、和 Hyprland/niri 的模糊/缩放更贴合，还是 kitty 主力、foot 备用。

### 2.3 kitty 主力、foot 备用

| 维度       | kitty                             | foot                      |
|------------|-----------------------------------|---------------------------|
| 启动与内存 | 快，但 GPU 渲染内存更高           | 极快、占用低              |
| 标签与分屏 | 内置标签、分屏                    | 没有，交给 tmux           |
| 连字       | 支持                              | 不支持                    |
| 图片       | Kitty graphics 协议               | Sixel                     |
| 透明与模糊 | `background_opacity` + 合成器模糊 | `alpha` + 合成器模糊      |
| 配置       | `~/.config/kitty/kitty.conf`      | `~/.config/foot/foot.ini` |
| 适合       | 主力日常、看图、临时分屏          | 备用、远程、低占用        |

结论：

- **主力用 kitty**：GPU 渲染，支持连字、图片和内置分屏；Hyprland 下配合模糊、
  透明效果最直接，niri 下也能正常使用。
- **备用装 foot**：启动快、占用低，远程或只需要一个轻窗口时用；不支持连字。
- **不装 alacritty**：它是 niri 默认配置里的模板，不是必需依赖。

### 2.4 和合成器的关系

Hyprland 和 niri 都只跑 Wayland 会话，终端必须能原生使用 Wayland，或者至少
能通过 XWayland 启动。上面五个都满足，差别只在细节：

- **Hyprland**：默认终端是 `kitty`，圆角、模糊、透明都成熟。kitty 和 foot 都能
  吃到 `decoration.blur`，不需要终端自己实现模糊。
- **niri**：默认配置写的是 `spawn "alacritty"`，但本机没装 alacritty，所以默认
  的 `Mod+T` 按下去没有反应。把这一行改成 `kitty`（备用可改 `foot`）即可。
- **平铺布局**：Hyprland 是动态平铺，niri 是横向滚动。两者都不需要终端标签页，
  多开窗口比标签更符合使用习惯。

niri 默认写 alacritty，只是因为它轻量、无标签/分屏，和滚动布局的极简思路一致，
并不是硬性要求。只在 niri 下用、追求极简，保留 alacritty 很合理；如果 Hyprland
和 niri 共用一套终端配置，kitty 更省事。

niri 26.04 起支持背景模糊，但要通过 `background-effect` 规则显式开启；Hyprland
则是全局 `decoration.blur`，终端透明后自动生效。具体配置见第 5 节。

## 3. Shell 怎么选

### 3.1 三种 shell 的差别

| shell | 补全与高亮       | 配置位置          | 能否直接 source bash 脚本 | 适合谁               |
|-------|------------------|-------------------|---------------------------|----------------------|
| bash  | 基础，需要自己补 | `~/.bashrc`       | 原生                      | 已有大量 bash 工具   |
| zsh   | 强，插件生态成熟 | `~/.zshrc`        | 大部分简单脚本可以        | 长期主力、想渐进迁移 |
| fish  | 开箱最强         | `~/.config/fish/` | 不能，语法不同            | 全新环境、只做交互   |

### 3.2 本机为什么选 zsh

本机的 `~/.zshrc` 和 `~/.bashrc` 都会 source `~/bin/_source_cmd_tools.sh`，
后者又加载 `~/Projects/miniTools/` 下的一批 bash 函数。这些工具是现成的，换成
fish 后不能直接 source，只能重写或每次显式调用 bash。

所以这台机器上推荐：

- **zsh + Starship + Arch 官方插件**，尽量复用现有 bash 工具。
- 不装 oh-my-zsh。它体积大、启动慢，而且 Arch 官方包已经拆好了补全和高亮。
- 如果是全新机器、没有 bash 工具包袱，fish 可以优先考虑；它的默认体验确实更好。

### 3.3 安装

```bash
sudo pacman -S --needed zsh starship \
  zsh-autosuggestions zsh-syntax-highlighting zsh-completions \
  fzf eza bat zoxide
chsh -s /usr/bin/zsh
```

`chsh` 只改登录 shell，重新登录后才生效。当前会话可以先执行 `exec zsh`
验证配置。

### 3.4 `~/.zshrc` 示例

下面是一份最小可用配置。不要直接覆盖现有的 `~/.zshrc`，先把原来的
`source ~/bin/_source_cmd_tools.sh` 保留下来，再合并下面的内容。

```zsh
# ~/.zshrc
HISTFILE=~/.zsh_history
HISTSIZE=50000
SAVEHIST=50000
setopt HIST_IGNORE_ALL_DUPS HIST_IGNORE_SPACE SHARE_HISTORY

# 上下键按当前输入的前缀过滤历史，而不是遍历全部历史
bindkey '^[[A' history-beginning-search-backward
bindkey '^[[B' history-beginning-search-forward

# zsh-completions 装到 /usr/share/zsh/site-functions，默认已在 fpath 中
autoload -Uz compinit && compinit

# 原有 bash 工具：确认兼容 zsh 后再取消注释
# source ~/bin/_source_cmd_tools.sh

# 可选：fzf 的 Ctrl-R / Ctrl-T / Alt-C
source /usr/share/fzf/key-bindings.zsh
source /usr/share/fzf/completion.zsh

source /usr/share/zsh/plugins/zsh-autosuggestions/zsh-autosuggestions.zsh

eval "$(starship init zsh)"
eval "$(zoxide init zsh)"

alias ls='eza --icons --group-directories-first'
alias ll='eza -lh --icons --git'
alias cat='bat --style=plain --paging=never'

# 语法高亮必须最后 source
source /usr/share/zsh/plugins/zsh-syntax-highlighting/zsh-syntax-highlighting.zsh
```

顺序很重要：

1. 先 `compinit`，再加载自动建议和 Starship。
2. `zsh-syntax-highlighting` 放最后，否则高亮可能不生效。
3. 原有的 `_source_cmd_tools.sh` 放在 `compinit` 之后、语法高亮之前。

上下键按当前输入的前缀搜索历史，`Ctrl-R` 仍然是全量模糊搜索，两者不冲突。

上面的两条绑定只解决第一次上翻；连续上翻时，第二次会把已经补全的整行当成
新前缀。要让连续上翻始终使用最初输入的前缀，并在填入历史命令后把光标移到
行尾、清掉灰色建议，需要在自定义 widget 中保存前缀；本仓库的 `cfg_zshrc`
已经按这种方式实现。

灰色自动建议由 `zsh-autosuggestions` 提供；光标在行尾时按右方向键接受整条
建议，没有建议时右方向键仍然是普通的右移。

输入法的环境变量不要只写在 `.zshrc` 里，放到
`~/.config/environment.d/10-fcitx5.conf`，让桌面会话启动的程序也能读到：

```ini
GTK_IM_MODULE=fcitx
QT_IM_MODULE=fcitx
XMODIFIERS=@im=fcitx
```

重新登录后生效，可用 `fcitx5-diagnose` 检查。

### 3.5 如果选 fish

fish 的配置文件是 `~/.config/fish/config.fish`：

```fish
if status is-interactive
    starship init fish | source
    zoxide init fish | source
end

alias ls='eza --icons --group-directories-first'
alias ll='eza -lh --icons --git'
alias cat='bat --style=plain --paging=never'
```

fish 不能 source 前面提到的 bash 工具。要么重写，要么在需要时显式执行
`bash -c '...'`。这也是本机不选 fish 的主要原因。

### 3.6 已经装了 oh-my-zsh 怎么办

oh-my-zsh 不是不能用，但没必要和 Starship 叠在一起：

- 保留 OMZ 的插件，把主题关掉：在 `~/.zshrc` 里设 `ZSH_THEME=""`。
- 然后再 `eval "$(starship init zsh)"`，否则会出现两个提示符。
- 新机器建议直接用 Arch 官方插件，不装 OMZ；少一层框架，启动更快。

## 4. 提示符：Starship

Starship 是 Rust 写的跨 shell 提示符生成器，配置文件是
`~/.config/starship.toml`。它只负责提示符，不负责补全、高亮和历史。

### 4.1 用预设快速起步

```bash
mkdir -p ~/.config
starship preset catppuccin-powerline -o ~/.config/starship.toml
```

预设会生成一份完整的 Catppuccin 配色配置，适合先看效果。`-o` 会覆盖已有的
`~/.config/starship.toml`，有自定义内容时先备份。想改颜色、模块顺序，再编辑
`~/.config/starship.toml`。

### 4.2 一份更小的配置

如果不想用预设，可以从下面这份开始：

```toml
# ~/.config/starship.toml
"$schema" = 'https://starship.rs/config-schema.json'

format = """
$directory\
$git_branch\
$git_status\
$fill\
$cmd_duration\
$line_break\
$character"""

[directory]
style = "bold #89b4fa"
truncation_length = 3

[git_branch]
style = "bold #cba6f7"

[cmd_duration]
min_time = 500
format = "took [$duration]($style) "

[character]
success_symbol = "[❯](bold #a6e3a1)"
error_symbol = "[❯](bold #f38ba8)"
```

`$fill` 会把后面的内容推到右侧；终端太窄时它不会强行占位。提示符里的图标和
箭头需要 Nerd Font，下一节会检查字体。

### 4.3 验证

```bash
starship --version
exec zsh
```

如果提示符没变，先确认 `~/.zshrc` 里的 `eval "$(starship init zsh)"` 在
`compinit` 之后，并且没有被 OMZ 的主题覆盖。

## 5. 美化：字体、配色、透明与模糊

### 5.1 先确认 Nerd Font

```bash
fc-list | grep -i 'FiraCode Nerd Font' | head
```

有输出就说明字体已经注册。没有输出时：

```bash
sudo pacman -S ttf-firacode-nerd
fc-cache -fv
```

字体名要写完整的 `FiraCode Nerd Font`，不要只写 `Fira Code`。后者是普通字体，
不带图标，Starship 和 waybar 的符号会变成方框。

### 5.2 一套配色贯穿所有工具

下面统一用 Catppuccin Mocha。不要给 kitty、foot、Starship、fuzzel 各配一套，
否则切换窗口时颜色会跳。

| 用途     | 颜色      |
|----------|-----------|
| 背景     | `#1e1e2e` |
| 前景文字 | `#cdd6f4` |
| 次要表面 | `#313244` |
| 蓝色     | `#89b4fa` |
| 紫色     | `#cba6f7` |
| 绿色     | `#a6e3a1` |
| 红色     | `#f38ba8` |
| 黄色     | `#f9e2af` |

### 5.4 foot 配置

```ini
# ~/.config/foot/foot.ini
[main]
font=FiraCode Nerd Font:size=11
pad=8x8

[colors-dark]
alpha=0.95
foreground=cdd6f4
background=1e1e2e
regular0=45475a
regular1=f38ba8
regular2=a6e3a1
regular3=f9e2af
regular4=89b4fa
regular5=cba6f7
regular6=94e2d5
regular7=bac2de
bright0=585b70
bright1=f38ba8
bright2=a6e3a1
bright3=f9e2af
bright4=89b4fa
bright5=cba6f7
bright6=94e2d5
bright7=a6adc8
selection-foreground=1e1e2e
selection-background=89b4fa
cursor=1e1e2e f5e0dc
```

说明：

- `alpha=0.95` 只让背景透明，文字仍然不透明。
- foot 1.28 使用 `[colors-dark]`；更老的版本如果报错，把段名改成 `[colors]`。
- 改完只影响新开的 foot 窗口；已经打开的窗口不会自动换配色。
- 校验配置：`foot -C -c ~/.config/foot/foot.ini`，返回 0 即通过。

### 5.5 Hyprland：模糊与透明度只选一层

透明有两个位置可以做：

- **终端自己做**：kitty 的 `background_opacity`、foot 的 `alpha`。只影响背景，
  文字清晰，推荐。
- **合成器做**：Hyprland 的 `opacity` 窗口规则。整个窗口都变透明，文字也会变淡。

两个都开会出现“透明度叠加”，看起来比预期更透。建议只开终端自己的透明度
（kitty 的 `background_opacity`，foot 则是 `alpha`），合成器只负责模糊。

以下片段写在 `~/.config/hypr/hyprland.lua`。Hyprland 0.55 起改用 Lua 配置，
不要再和 `hyprland.conf` 混用。

Hyprland 的全局模糊：

```lua
hl.config({
    decoration = {
        rounding = 10,
        blur = {
            enabled = true,
            size = 4,
            passes = 2,
            vibrancy = 0.1696,
        },
    },
})
```

如果确实想让合成器控制透明度，再加窗口规则：

```lua
hl.window_rule({
    match = { class = "^(kitty|foot)$" },
    opacity = "0.95 0.9",
})
```

这时把 kitty 的 `background_opacity` 和 foot 的 `alpha` 改回 `1.0`。

备用 foot 如果不需要模糊，可以单独关掉：

```lua
hl.window_rule({
    match = { class = "foot" },
    no_blur = true,
})
```

校验与重载：

```bash
Hyprland --verify-config -c ~/.config/hypr/hyprland.lua
hyprctl reload
```

### 5.6 niri：用 background-effect 开模糊

niri 26.04 起支持模糊。先确认版本：

```bash
niri --version
```

然后在 `~/.config/niri/config.kdl` 里加全局参数和窗口规则：

```kdl
blur {
    passes 3
    offset 3.0
    noise 0.02
    saturation 1.5
}

window-rule {
    match app-id=r#"^(kitty|foot)$"#

    background-effect {
        blur true
        xray false
    }
}
```

说明：

- `blur` 是 26.04 才有的顶层配置，旧版会直接报错。
- `xray false` 是更接近“真实背景模糊”的模式；如果性能吃紧，改成 `true`。
- 透明仍然由终端自己的 `alpha` / `background_opacity` 控制。
- 应用可以通过 `ext-background-effect` 协议自己请求模糊；没有请求时，用窗口
  规则里的 `blur true` 强制开启。

校验与重载：

```bash
niri validate -c ~/.config/niri/config.kdl
niri msg action load-config-file
```

### 5.7 其他工具跟着同一套色

启动器 fuzzel 的 `~/.config/fuzzel/fuzzel.ini`：

```ini
[colors]
background=1e1e2eee
text=cdd6f4ff
match=89b4faff
selection=313244ff
border=89b4faff
```

通知 mako 的 `~/.config/mako/config`：

```ini
background-color=#1e1e2e
text-color=#cdd6f4
border-color=#89b4fa
```

waybar 的 `~/.config/waybar/style.css` 至少统一字体和背景：

```css
* {
    font-family: "FiraCode Nerd Font";
    font-size: 12px;
}

window#waybar {
    background: rgba(30, 30, 46, 0.9);
    color: #cdd6f4;
}
```

这些值不是必须逐字照抄，关键是和终端使用同一组背景、前景、强调色。

## 6. 启动与键位

### 6.1 Hyprland

Lua 配置里通常已经定义了 `mainMod`。如果没有，先加一行：

```lua
local mainMod = "SUPER"
local terminal = "kitty"
local terminal_alt = "foot"

hl.bind(mainMod .. " + Return", hl.dsp.exec_cmd(terminal))
hl.bind(mainMod .. " + SHIFT + Return", hl.dsp.exec_cmd(terminal_alt))
```

这会把 `Super+Enter` 给 kitty，`Super+Shift+Enter` 给 foot。两个都留着，日常用
kitty，需要轻量窗口或远程时用 foot。

### 6.2 niri

niri 默认的 `Mod+T` 指向 alacritty，本机没装，所以按了没反应。改成：

```kdl
binds {
    Mod+T { spawn "kitty"; }
    Mod+Shift+T { spawn "foot"; }
}
```

`Mod+T` 给主力 kitty，`Mod+Shift+T` 给备用 foot。如果配置里已经有 `Mod+T`，
直接替换，不要重复定义同一个键。

### 6.3 tmux：平铺下的分屏正解

```bash
tmux new -s main       # 新建会话
tmux a -t main         # 重新连接
```

常用操作：

- `Ctrl-b d`：断开但保留会话。
- `Ctrl-b %`：左右分屏。
- `Ctrl-b "`：上下分屏。
- `Ctrl-b` 加方向键：切换窗格。

终端自己的标签页在平铺合成器里意义不大，但 kitty 的分屏仍适合临时把一个窗口
切开：`Ctrl+Shift+Enter` 开新窗口，`Ctrl+Shift+L` 切换布局，`Ctrl+Shift+T`
新标签。tmux 的优势是会话能脱离终端窗口存活，关闭窗口后还能 `tmux a` 回来。
两者不冲突：临时分屏用 kitty，长期会话用 tmux。

## 7. 常见坑

| 现象                       | 原因                               | 处理                                               |
|----------------------------|------------------------------------|----------------------------------------------------|
| niri 按 `Mod+T` 没反应     | 默认 spawn 的是未安装的 alacritty  | 改成 `spawn "kitty"` 或 `spawn "foot"`             |
| kitty 分屏没反应           | 没按默认快捷键                     | `Ctrl+Shift+Enter` 开新窗口，`Ctrl+Shift+L` 换布局 |
| 图标显示成方框             | 字体不是 Nerd Font                 | 用 `FiraCode Nerd Font`，必要时 `fc-cache -fv`     |
| 出现两个提示符             | OMZ 主题和 Starship 同时生效       | 设 `ZSH_THEME=""`，只保留 Starship                 |
| 各程序颜色不一致           | 每个工具各配一套色                 | 统一用第 5.2 节的 Mocha 色值                       |
| 背景透明但没有模糊         | 合成器模糊没开，或 niri 低于 26.04 | 开 `decoration.blur` 或 `background-effect`        |
| fish 无法 source bash 工具 | fish 语法与 bash 不同              | 保留 zsh，或把工具重写成 fish 函数                 |
| zsh 高亮不生效             | 插件顺序错了                       | `zsh-syntax-highlighting` 放最后                   |
| 终端透得看不清字           | 终端透明度和合成器 opacity 叠加    | 只保留一层透明度                                   |
| 改完 kitty 配置没变化      | kitty 只在启动时读配置             | 重启 kitty，或 `kill -SIGUSR1`                     |
| foot 报配置错误            | 旧版不认 `[colors-dark]`           | 改成 `[colors]` 后重试                             |
