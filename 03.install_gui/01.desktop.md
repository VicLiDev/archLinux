# 安装桌面：显卡驱动、桌面环境、平铺合成器与中文输入法

- **阶段**：系统已能联网、`pacman -Syu` 正常之后
- **顺序**：驱动 → 四个角色 → X11/Wayland → 桌面环境或合成器 → 外壳 → 字体与输入法
- **原则**：一次只引入一层，每层装完就验证；四层一起装，出问题分不清是哪层

## 1. 先确认硬件与系统状态

```bash
lspci -k | grep -A3 -E "VGA|3D"   # 显卡型号 + 当前加载的驱动
echo $XDG_SESSION_TYPE            # 进桌面后才知道，先记着
pacman -Syu                       # 装桌面之前先全量更新
```

本文讲的是 Arch 侧。openSUSE 上"只有终端、要装桌面"的排查见
[02.suse-no-desktop.md](02.suse-no-desktop.md)，四层模型相同，命令换成 `zypper`。

如果 `lspci` 里显示的是 `Kernel driver in use: nouveau` 或 `simpledrm`，
说明还在用内核自带的兜底驱动，分辨率、刷新率、硬件加速都不完整。

## 2. 显卡驱动

| 显卡               | 包                                     | 说明                                          |
|--------------------|----------------------------------------|-----------------------------------------------|
| Intel              | `mesa vulkan-intel intel-media-driver` | 走内核 modesetting，不要装 `xf86-video-intel` |
| AMD                | `mesa vulkan-radeon libva-mesa-driver` | 同上，不需要 `xf86-video-amdgpu`              |
| NVIDIA（开源模块） | `nvidia-open nvidia-utils`             | Turing（20 系）及以后，推荐                   |
| NVIDIA（闭源）     | `nvidia nvidia-utils`                  | 老卡或开源模块不支持时用                      |

表格「包」列里的包名直接拼成一条命令，`--needed` 用来避免已安装时弹确认：

```bash
# Intel
sudo pacman -S --needed mesa vulkan-intel intel-media-driver
# AMD
sudo pacman -S --needed mesa vulkan-radeon libva-mesa-driver
```

`intel-media-driver` 只支持 Broadwell（Gen9）及以后，更老的核显换成
`libva-intel-driver`；AMD 的老卡（GCN 1.0/2.0）可能要加内核参数
`amdgpu.si_support=1 amdgpu.cik_support=1` 才走 `amdgpu`，否则仍用 `radeon`。

几个容易踩的点：

- **预编译包只对应 `linux` 内核**。用 `linux-lts`、`linux-zen` 或自编译内核时，
  要装 DKMS 版本（`nvidia-open-dkms` / `nvidia-dkms`），否则模块加载失败。
- **装 NVIDIA 会自动屏蔽 nouveau**（`/usr/lib/modprobe.d/` 里的配置），不用手动
  加 blacklist，但需要 `mkinitcpio -P` 让 initramfs 里的模块列表同步。
- **Steam/32 位程序**还要 `lib32-nvidia-utils`（A 卡 `lib32-mesa`
  `lib32-vulkan-radeon`，I 卡 `lib32-vulkan-intel`）；`libva-mesa-driver` 没有
  32 位对应包，不需要找。
- **Pascal（GTX 10 系）及更老的卡**：官方新驱动已逐步停止支持（570 分支是
  Maxwell/Pascal/Volta 的最后一版），要装 AUR 里的 legacy 包（`nvidia-570xx`、
  更老的 `nvidia-470xx`）。装之前先查 Arch Wiki 的 NVIDIA 页面确认自己的卡在哪
  个分支，别硬装 `nvidia`。
- **AMD/Intel 依赖 `linux-firmware`**：`base` 安装时一般已带上，若手动精简过
  系统，先确认 `pacman -Q linux-firmware` 有输出，否则核显可能起不来。

### 2.1 NVIDIA 的额外两步

**内核参数**：Wayland 依赖 DRM 内核模式设置，把下面两项加到引导器命令行
（systemd-boot 改 `/boot/loader/entries/*.conf` 的 `options`，
GRUB 改 `/etc/default/grub` 的 `GRUB_CMDLINE_LINUX_DEFAULT` 后重跑 `grub-mkconfig`）：

```text
nvidia_drm.modeset=1 nvidia_drm.fbdev=1
```

**休眠/唤醒**：启用 `nvidia-utils` 自带的三个服务，否则合盖唤醒容易黑屏：

```bash
systemctl enable nvidia-suspend.service nvidia-hibernate.service nvidia-resume.service
```

**混合显卡笔记本**（Intel/AMD 核显 + NVIDIA 独显）：装 `nvidia-prime`，
需要独显时用 `prime-run <命令>` 启动，平时由核显省电。

验证驱动是否真的在工作（`mesa-utils`、`libva-utils`、`vulkan-tools` 提供这些命令）：

```bash
glxinfo -B | grep -i "OpenGL renderer"    # OpenGL 走的是哪块卡
vulkaninfo --summary | grep -i deviceName # Vulkan 设备
vainfo                                    # 硬件解码能力
nvidia-smi                                # NVIDIA 专用
```

## 3. 图形界面的四个角色

装桌面之前先分清四件事，后面几节都建立在这个划分上：

| 角色       | 负责什么                       | X11 时代         | Wayland 时代 |
|------------|--------------------------------|------------------|--------------|
| 显示服务器 | 屏幕、输入设备、客户端连接     | Xorg，独立进程   | 并入合成器   |
| 合成器     | 把各窗口的像素合成上屏、做动画 | picom，可选      | 合成器本身   |
| 窗口管理   | 布局、焦点、边框、快捷键       | i3/openbox，独立 | 并入合成器   |
| 外壳       | 面板、通知、锁屏、启动器、托盘 | polybar/dunst    | 仍是独立程序 |

X11 时代四件可以任意拼：Xorg 管显示，i3 管窗口，picom 管合成，polybar 管面板，
桌面环境只是把它们打包。Wayland 把前三个角色合并成一个程序——合成器同时也是
显示服务器和窗口管理器，只剩外壳还能拆出来换。

### 3.1 三种粒度

| 粒度          | 组成                   | 例子                                      |
|---------------|------------------------|-------------------------------------------|
| 裸合成器      | 合成器（已含窗口管理） | tty 里直接跑 `sway`，没状态栏也能用       |
| 合成器 + 外壳 | 再加面板、通知、锁屏   | sway + waybar + mako + swaylock           |
| 桌面环境      | 再加应用集、设置、DM   | GNOME = Mutter + GNOME Shell + 应用 + gdm |

所以：

- **只有合成器也成立**，只是没有状态栏和通知弹窗，能用但难用。
- **桌面环境一定两个角色都有**，此外还带文件管理器、终端、设置面板和显示管理器
  ——这些才是它和"合成器 + 外壳"的真正差别。
- 桌面环境不是"包含"合成器和外壳，而是**替你选好并装好**了这两个角色。

### 3.2 两个容易混淆的特例

- **GNOME Shell 是 Mutter 的插件**，两者跑在同一个进程里。所以 GNOME 的合成器
  和外壳在代码层是绑死的，换不掉，这也是它风格统一的原因。
- **sway 自带一个最小外壳** `swaybar`，不装 waybar 也有状态栏；Hyprland 和
  niri 完全不带，面板必须自己配。

后面几节按这个划分展开：第 4 节讲显示服务器之争（X11 与 Wayland），第 5 节讲
整套桌面（桌面环境），第 6 节讲只选合成器，第 7 节讲整套外壳，第 8 节讲单件
配套工具，第 9 节讲显示管理器——谁把桌面拉起来，第 10 节把五套组合从装包到
启用一次讲完，第 11 节讲它们之间的冲突。

## 4. X11 与 Wayland

### 4.1 谁负责合成

两者的根本差别是"谁把窗口画到屏幕上"：

- **X11**：客户端把窗口内容交给 X server，X server 直接画到共享屏幕；合成器是
  可选的附加层。任何客户端都能读整个屏幕、抓全局按键，隔离性差，但录屏、远程
  桌面、全局快捷键实现起来最简单。
- **Wayland**：合成器**就是**显示服务器，客户端只提交 buffer，窗口位置、输入
  分发、缩放全由合成器决定。客户端读不到别人的画面，所以截图、录屏、屏幕共享
  必须经过 `xdg-desktop-portal`。

### 4.2 对比

| 维度          | Wayland                       | X11            |
|---------------|-------------------------------|----------------|
| 现状          | GNOME / KDE 默认会话          | 兼容性兜底     |
| NVIDIA        | 545 驱动以后基本可用          | 一直可用       |
| 分数缩放      | 原生支持                      | 需要调 Xrandr  |
| 多屏混合 DPI  | 每个输出独立缩放              | 全局一个缩放比 |
| 屏幕共享/录屏 | 走 portal，个别软件要额外配置 | 直接抓屏       |
| 全局快捷键    | 合成器实现，跨应用组合键受限  | 成熟           |
| 输入法        | 走 text-input，GNOME 上较弱   | 成熟           |
| 客户端隔离    | 好，读不到别人的画面          | 差，能读全屏   |

### 4.3 兼容层与切换

- 纯 Wayland 桌面不需要装 `xorg-server`；但很多程序仍依赖 XWayland（`xwayland`
  包），桌面环境的依赖会自动带上，不用管。
- 看哪些程序还在走 XWayland 用 `xlsclients`；看会话类型用
  `echo $XDG_SESSION_TYPE`。
- 登录界面（GDM/SDDM）右下角一般能切换会话类型，出问题先进 X11 会话排查。
- 第 6 节的平铺合成器只提供 Wayland 会话，没有 X11 版本。

## 5. 桌面环境

桌面环境（DE）把第 3 节的角色打包成一整套：合成器、外壳、应用集，外加一个
统一的设置面板。它的反面是第 6、7、8 节那种自己挑合成器、外壳、单件工具的
装法。**显示管理器不在这里讲**——它是独立的一环，见第 9 节。

### 5.1 常见桌面环境

| 桌面       | 安装包                                        | 配套 DM（需另装）             |
|------------|-----------------------------------------------|-------------------------------|
| GNOME      | `gnome`                                       | `gdm`                         |
| KDE Plasma | `plasma-meta`（可选 `kde-applications-meta`） | `sddm`                        |
| Xfce       | `xfce4 xfce4-goodies`                         | `lightdm lightdm-gtk-greeter` |

```bash
sudo pacman -S gnome gdm
sudo systemctl enable --now gdm     # 启用细节见 9.3
```

`gnome`、`plasma-meta` 是包组/元包，装之前会列出包含的包，用默认选择即可。
装包只完成一半，**不 enable 就进不了图形界面**，这是第一次装桌面最常见的坑。

### 5.2 三套怎么选

| 维度       | GNOME                    | KDE Plasma            | Xfce                |
|------------|--------------------------|-----------------------|---------------------|
| 合成器     | Mutter                   | KWin                  | Xfwm4               |
| 会话类型   | Wayland / X11            | Wayland / X11         | 仅 X11              |
| 可定制程度 | 低，行为靠扩展           | 高，几乎每处都能改    | 中，主题和面板可调  |
| 安装体积   | 大                       | 大                    | 中                  |
| 认证代理   | 自带                     | 自带 polkit-kde       | 需另装 polkit-gnome |
| 适合       | 不想折腾、要好手势和触控 | 想全面控制、Qt 应用多 | 老机器、需要纯 X11  |

三套都能装在同一台机器上，会话菜单里选哪个进哪个，只是同一时刻跑一个。
拿不定主意就按这条走：不想调配置选 GNOME，想调到底选 KDE，机器老或需要
X11 兼容选 Xfce。

### 5.3 装完之后多出了什么

装一个 DE 不只是多了一堆程序，还会多出四类东西：

| 多出来的         | 位置                                    | 影响                        |
|------------------|-----------------------------------------|-----------------------------|
| 会话文件         | `/usr/share/wayland-sessions/*.desktop` | DM 里能选到这套桌面         |
| 开机自启条目     | `/etc/xdg/autostart/*.desktop`          | 任何会话都会执行，包括 niri |
| portal 后端      | `xdg-desktop-portal-{gnome,kde,gtk}`    | 截图、文件框按会话自动选    |
| 桌面设置与应用集 | `~/.config/`、`/usr/share/applications` | 与其它会话共享配置          |

**显示管理器不会跟着装**：`plasma-meta` 只带 `sddm-kcm` 这个配置页，`sddm`
本体要自己装；`gnome` 和 `xfce4` 也一样，DM 都是单独一行。装完 DM 还要
`enable`，否则开机仍停在 tty——这两件事都在第 9 节。

第一行和第三行是「同一套桌面，换个会话就能用」的基础；第二行是坑的来源：
KDE 的 polkit 代理和电源管理会在 niri 会话里被一起拉起，处理见 6.7。

## 6. 平铺式 Wayland 合成器

平铺（tiling）指窗口自动占满屏幕、不重叠，用键盘切换而不是鼠标拖。这类程序
本身只是**合成器 + 窗口管理**，面板、通知、锁屏要另配（第 7 节）。三者都只
提供 Wayland 会话。

### 6.1 三个选项

| 项目     | 一句话概括                     | 后端       |
|----------|--------------------------------|------------|
| sway     | i3 的 Wayland 重写版，手动平铺 | wlroots    |
| Hyprland | 动态平铺 + 全套视觉效果        | aquamarine |
| niri     | 滚动式平铺，已有窗口不重排     | Smithay    |

**最小安装**（只装合成器本体）：

```bash
sudo pacman -S sway
sudo pacman -S hyprland xdg-desktop-portal-hyprland
sudo pacman -S niri xwayland-satellite
```

**通用配套**（三者都要，一次装完）：

```bash
sudo pacman -S foot fuzzel mako grim slurp wl-clipboard waybar \
          polkit-gnome brightnessctl
```

`foot` 终端、`fuzzel` 启动器、`mako` 通知、`grim`+`slurp` 截图、`wl-clipboard`
剪贴板、`waybar` 状态栏、`polkit-gnome` 认证代理、`brightnessctl` 调亮度。
合成器默认键位指向 `foot` 和 `fuzzel`，不装按了没反应；没有认证代理时，挂载
U 盘、装软件这类需要授权的操作会静默失败。这些工具各自的替代品和作用，
见第 8 节。

启动方式三选一：

1. 从 tty 直接执行：sway 用 `sway`、Hyprland 用 `Hyprland`、niri 用
   `niri-session`（**不是裸 `niri`**，否则拿不到 systemd 用户会话，portal、
   通知会静默失效）。出问题时日志直接打在屏幕上。
2. 用显示管理器：装完会自动出现 `/usr/share/wayland-sessions/*.desktop`，
   GDM/SDDM 的会话菜单里和 GNOME/KDE 并列显示。
3. 装 `greetd` + `tuigreet` 做纯文本登录界面，或用 `uwsm` 把会话交给 systemd
   管理（portal、环境变量更规范，Hyprland 官方推荐这种方式）。

共同点：配置都是纯文本；都支持 `wlr-layer-shell`，面板类工具通用；截图用
`grim` + `slurp`，剪贴板用 `wl-clipboard`，屏幕共享走 `pipewire`。

### 6.2 sway

i3 的 Wayland 重写版，wlroots 后端，配置语法与 i3 基本一致，i3 的配置能直接
拷过来。

- **布局**：手动平铺。窗口进哪个容器、横切还是竖切由你决定，另有 tabbed、
  stacking 两种堆叠方式，`$mod+space` 切换浮动。
- **组件**：`swaybar` 状态栏、`swaylock` 锁屏、`swayidle` 空闲管理、`swaynag`
  提示条；壁纸用独立的 `swaybg`。
- **IPC**：`swaymsg`，可脚本化（`swaymsg workspace 2`、`swaymsg reload`、
  `swaymsg -t get_tree | jq`）。
- **风格**：没有动画、没有圆角，切换是瞬间的。求稳的人喜欢这点。

```bash
pacman -S sway swaybg swayidle swaylock xdg-desktop-portal-wlr
```

`xdg-desktop-portal-wlr` 负责截图、录屏、文件选择框，缺了 `grim` 和屏幕共享
都不工作。状态栏用自带的 `swaybar` 就够，不必装 waybar。

配置在 `~/.config/sway/config`，最小可用片段：

```text
set $mod Mod4
bindsym $mod+Return exec foot
bindsym $mod+d exec wofi --show drun
bindsym $mod+Shift+q kill
output * bg ~/wallpaper.png fill
```

缺点：外观朴素，圆角、模糊这类效果要换合成器才能得到；wlroots 升级时偶尔要
跟着改配置，但很少见。

### 6.3 Hyprland

独立实现的动态平铺合成器，C++，后端是自研的 aquamarine（早期版本基于
wlroots）。功能与视觉在三者中最全，更新也最激进。

- **布局**：动态平铺，自动决定新窗口放哪，`dwindle` 与 `master` 两种算法可选。
- **视觉**：动画曲线、圆角、模糊、阴影、工作区滑动切换，全部可调。
- **IPC**：`hyprctl`（`hyprctl clients`、`hyprctl dispatch workspace 2`、
  `hyprctl reload`）。
- **生态**：`hyprlock` 锁屏、`hypridle` 空闲、`hyprpaper` 壁纸、`hyprpicker`
  取色，插件用 `hyprpm` 管理。
- **注意**：必须配 `xdg-desktop-portal-hyprland`；NVIDIA 要开
  `nvidia_drm.modeset=1`；升级偶尔带破坏性变更，配置和插件要跟着改。

```bash
pacman -S hyprland xdg-desktop-portal-hyprland \
          hyprlock hypridle hyprpaper hyprpicker
```

`hyprlock`/`hypridle` 锁屏与空闲管理，`hyprpaper` 壁纸，`hyprpicker` 取色。
想把会话交给 systemd 管理，另装 `uwsm`，Hyprland 官方推荐这种方式。

配置在 `~/.config/hypr/hyprland.conf`：

```text
$mainMod = SUPER
exec-once = waybar
bind = $mainMod, Return, exec, foot
bind = $mainMod, Q, killactive
general { gaps_in = 5; gaps_out = 10; border_size = 2 }
decoration { rounding = 8; blur { enabled = true } }
```

缺点：配置项多，第一次配能花掉一晚上；升级前最好读一遍 release note。

### 6.4 niri

Rust 写的滚动式平铺合成器（基于 Smithay）。它不重排已有窗口，而是把窗口按列
排在一条无限向右延伸的长条上，靠滚动查看。

- **布局**：滚动式。新窗口加在右边，已有窗口位置不动；列宽可调，一屏放不下
  就横向滚。适合"开了十几个窗口但不想它们跳来跳去"的场景。
- **工作区**：每个显示器有自己独立的一组工作区，插拔显示器不丢窗口。
- **IPC**：`niri msg`（`niri msg workspaces`、`niri msg action quit`）。
- **X11 程序**：不内置 XWayland，要另装 `xwayland-satellite`，它会按需启动。
- **风格**：动画流畅但克制，配置用 KDL 语法，比 key=value 可读性好。

```bash
pacman -S niri xwayland-satellite xdg-desktop-portal-wlr swaylock swayidle
```

niri 不内置 XWayland，也不实现截图和屏幕共享，这两个包都不能少；纯 Wayland
环境下 `xwayland-satellite` 只是待命，不占资源。它同样不带锁屏，`swaylock`
与 `swayidle` 在 niri 上直接可用。

配置在 `~/.config/niri/config.kdl`：

```kdl
input {
    touchpad { tap; natural-scroll; }
}
layout { gaps 16; }
binds {
    Mod+Return { spawn "foot"; }
    Mod+Q { close-window; }
    Mod+Left { focus-column-left; }
}
```

缺点：生态比前两者小，第三方脚本、主题少；习惯"切工作区"的人要适应横向滚动。

### 6.5 对比与选型

| 项目      | sway                      | Hyprland                             | niri                               |
|-----------|---------------------------|--------------------------------------|------------------------------------|
| 实现      | C，基于 wlroots           | C++，自研 aquamarine（早期 wlroots） | Rust，基于 Smithay                 |
| 布局      | 手动平铺，i3 兼容语法     | 动态平铺 + 动画                      | 滚动式平铺，列排在无限横向长条上   |
| 配置      | `~/.config/sway/config`   | `~/.config/hypr/hyprland.conf`       | `~/.config/niri/config.kdl`（KDL） |
| 动画/圆角 | 没有                      | 强项：模糊、圆角、阴影               | 有动画，克制                       |
| X11 程序  | 内置 XWayland             | 内置 XWayland                        | 需另装 `xwayland-satellite`        |
| 稳定性    | 最稳，变更少              | 功能最多，升级偶有破坏性变更         | 很稳，行为可预期                   |
| 自带生态  | swaybar/swaylock/swayidle | hyprlock/hypridle/hyprpaper/hyprpm   | 内置截图与 `niri msg` IPC          |
| 适合      | 从 i3 迁过来、要稳定      | 想要好看、愿意跟更新                 | 笔记本、多屏、讨厌窗口乱跳         |

怎么选：

- **从 i3 过来**：sway，配置几乎照抄。
- **要动画、圆角、模糊、插件**：Hyprland，代价是升级要读 changelog，插件也要
  跟着版本走。
- **笔记本、多屏、窗口多**：niri，工作区按显示器独立，插拔屏幕不丢窗口。
- **显卡**：三者都能在 NVIDIA 上跑，Hyprland 对新驱动要求最高；AMD/Intel 无差别。
- **不想调配置**：装第 5 节的 GNOME 或 KDE，或者选一个合成器配第 7 节的外壳。

### 6.6 三者能否共存

**能装在一起，但同一时刻只用一个。**

- 二进制互不覆盖，各自往 `/usr/share/wayland-sessions/` 放一个 `.desktop`，
  显示管理器的会话菜单里并列显示，随时切换。
- 配置目录独立：`~/.config/sway`、`~/.config/hypr`、`~/.config/niri`。
- 不同 tty 可以各跑一个（tty2 跑 sway、tty3 跑 Hyprland），但只有当前 tty 拿到
  显示输出，实际意义不大，还占内存。
- 真正的冲突不在合成器本身，而在**它们共用的系统组件**：通知服务、锁屏与空闲
  管理、portal、状态栏。见第 11 节的总表。

### 6.7 与完整桌面共存

合成器和桌面环境可以装在同一台机器上，**会话级互斥**：同一时刻只有一套在跑，
切换会话就等于换了外壳。

| 会话             | 谁拉起外壳                    | 外壳是什么                      |
|------------------|-------------------------------|---------------------------------|
| Plasma (Wayland) | `startplasma-wayland`         | plasmashell：面板、启动器、通知 |
| GNOME            | `gnome-session`               | GNOME Shell                     |
| niri / sway      | 会话脚本 + `spawn-at-startup` | waybar、mako、fuzzel            |

`plasmashell` 只在 Plasma 会话里启动，niri 会话碰不到它；waybar 也不会跑进
Plasma。两者共用 `/usr` 和 `~/.config`，进程层面互不干扰。

三个会串的地方：

1. **`/etc/xdg/autostart/` 里的桌面组件**。装 Plasma 会放一批自启项（认证
   代理、电源管理、kaccess），systemd 用户会话在 niri 里也会执行它们，表现为
   两个认证代理抢着弹密码框，或者 `powerdevil` 和 `swayidle` 重复挂起。
   先 `ls /etc/xdg/autostart/ | grep -i kde` 看清单，再在
   `~/.config/autostart/<同名>.desktop` 里写 `Hidden=true` 屏蔽。
2. **portal 后端**。Plasma 带 `xdg-desktop-portal-kde`，niri 要 `-wlr`。
   两者按 `XDG_CURRENT_DESKTOP` 选择（Plasma 是 `KDE`，niri 是 `niri`），
   一般不会错；要强制就在 `~/.config/xdg-desktop-portal/niri-portals.conf`
   里指定。
3. **主题与缩放**。`~/.config/kdeglobals` 和 fontconfig 共享，niri 里的 Qt
   程序会继承 Plasma 的字体设置；觉得不对用 `QT_SCALE_FACTOR`、`QT_FONT_DPI`
   覆盖。

不要做的两件事：在 niri 的 config.kdl 里 `spawn-at-startup "plasmashell"`
（会和 waybar 抢层叠区，还会起第二个通知服务）；把 waybar 塞进 Plasma 自启
（Plasma 有自己的面板）。

切换靠显示管理器的会话菜单；没有 DM 就在 tty 里敲 `niri-session` 或
`startplasma-wayland`。完整 Plasma 占一两个 GB，只想留个备用桌面可以只装
`plasma-desktop` 核心包，不带应用套件。

## 7. 桌面外壳

合成器只给窗口管理。面板（bar）、启动器、通知、控制中心、锁屏这些统称
**shell**（外壳）。GNOME 的外壳是 GNOME Shell，KDE 的是 Plasma Shell，都和
桌面绑死；平铺合成器这边可以自由替换。

### 7.1 三个选项与它们所处的层次

先分清层次，否则容易把 waybar 和 DMS 当成同类东西：

| 层       | 成员                         | 依赖什么                         |
|----------|------------------------------|----------------------------------|
| 框架     | quickshell                   | Qt6、wlr-layer-shell             |
| 整套外壳 | DMS、Noctalia                | quickshell（Noctalia v5 起自带） |
| 单件程序 | waybar、mako、fuzzel         | GTK3/Qt、wlr-layer-shell、D-Bus  |
| 认证代理 | polkit-gnome（KDE 自带同类） | D-Bus PolicyKit1                 |
| 命令行   | brightnessctl、wpctl、grim   | sysfs、pipewire、screencopy      |

- **基于 quickshell 的整套外壳主要是 DMS**，它一个进程就提供 bar、通知、
  启动器、控制中心。Noctalia 从 v5 起改成独立实现，不再依赖 quickshell。
- **waybar、mako、fuzzel 不在 quickshell 上**，是各自独立的程序，只靠
  `wlr-layer-shell` 上屏，一个角色一个程序，自己拼。
- **waybar 与 DMS 是竞争关系**：都实现状态栏，只能选一个。
- **polkit-gnome 是另一个角色**：程序提权时弹密码框，注册在 D-Bus 的
  `org.freedesktop.PolicyKit1.AuthenticationAgent` 上，与状态栏无关，冲突
  情况见 11.1。
- **brightnessctl 这类命令行工具**连图形都不需要，绑到快捷键或 bar 按钮上
  调用即可。

先讲 quickshell 这条线，关系是**套娃**：quickshell 是框架，DMS 是它上面的
完整应用，装 DMS 会自动带上 quickshell；quickshell 单独跑起来是空白的，界面
要自己写。两者都靠 `wlr-layer-shell` 工作，所以与合成器无关，sway、Hyprland、
niri 都能用。Noctalia 虽然同类，但不在这条依赖链上，见 7.4。

安装：

```bash
pacman -S quickshell         # 已在官方 extra 仓库，不必走 AUR
paru -S dms-shell-git        # DMS 的真实包名
paru -S noctalia-git         # Noctalia 的真实包名
```

**别照项目名猜包名**：`paru -S dankmaterialshell`、`paru -S noctalia-shell` 都会
报 `could not find all required packages`，因为 AUR 包名和项目名不是一回事。
拿不准就先 `paru -Ss dms` / `paru -Ss noctalia` 看列表。`dms-shell-git` 会自动
拉 `quickshell`、`dgop`、`accountsservice`。

`paru` 是 AUR 助手，没装的话先看
[03.base-tools.md](../02.first_boot/03.base-tools.md) 的 AUR 一节；报
`Failed to connect to github.com:443` 这类网络失败，见同文件 5.2。三个包别同时
启用，原因见 7.6。

### 7.2 quickshell

QtQuick/QML 写的外壳**框架**，不是现成桌面。它提供写 bar/面板所需的底层：
layer-shell 窗口、通知服务器、系统托盘、音频/亮度/网络状态、IPC，界面用 QML
描述。

```bash
pacman -S quickshell     # 在 extra 仓库里，当前是 0.3.x
```

配置放 `~/.config/quickshell/`，用 `qs` 启动，`qs -c <名字>` 指定配置目录。
适合想把 bar 做成任意形状的人，不适合想"装完就能用"的人。

### 7.3 DMS（DankMaterialShell）

基于 quickshell 的完整外壳，Material 3 风格，观感接近 Android/ChromeOS。bar、
启动器、控制中心、通知、锁屏由一套配置管起来，主题跟壁纸和明暗模式联动。

AUR 包名是 **`dms-shell-git`**。上游仓库已经从 `AvengeMedia/DankMaterialShell`
搬到 `duxlabs-dev/dux-shell`，包名没跟着改，别按新仓库名去搜。`paru -Ss dms`
还能看到一组配套插件（`dms-shell-plugins-git`）。装完按 README 加一条会话
自启。

### 7.4 Noctalia（Noctalia Shell）

同类的完整外壳，主打**壁纸取色**：从当前壁纸生成整套配色，bar、菜单、通知、
OSD 颜色统一。内置设置面板，配置项比 DMS 少，开箱即用程度更高。

**版本分界要注意**：v5 起改成了独立的 C++/Wayland 实现，不再依赖 quickshell；
v4 及更早才是 quickshell 上的配置，现在以 `noctalia-legacy-v4`、
`noctalia-qs-legacy-v4` 两个包留在 AUR。AUR 包名是 **`noctalia-git`**，
`noctalia-shell` 一样搜不到。配置在 `~/.config/noctalia/`。

### 7.5 对比与选型

| 项目       | 是什么                     | 提供什么                              | 适合谁                     |
|------------|----------------------------|---------------------------------------|----------------------------|
| quickshell | QtQuick/QML 写的外壳框架   | 组件库 + 运行时，不提供现成界面       | 会 QML、想完全自定义       |
| DMS        | 基于 quickshell 的完整外壳 | bar、启动器、控制中心、通知、锁屏     | 要 Material 风格、开箱即用 |
| Noctalia   | 独立实现（v5 起）          | bar、启动器、通知、控制中心、取色主题 | 要统一配色、少折腾         |

- **会写 QML、要独一无二的界面**：quickshell，从零搭。
- **想装完就有一个完整桌面**：DMS 或 Noctalia，按审美选。两者功能覆盖接近，
  DMS 偏 Material 风格、组件更多；Noctalia 偏配色统一、配置更少。
- **只缺一条状态栏**：别上完整外壳，用 `waybar` 更轻。

### 7.6 三者能否共存

**能装，但同时只跑一个。**

- 技术上能同时启动两个：DMS 是 quickshell 的配置，Noctalia 是独立进程。结果
  是两条 bar 叠着、两个通知服务抢同一个名字。
- 通知服务的名字 `org.freedesktop.Notifications` 全局唯一，后启动的那个注册
  失败，它的通知面板就是空的。
- 自定义 quickshell 配置和 DMS/Noctalia 也会重复：两套 bar 都往层叠区申请
  空间，窗口边缘出现双倍留白。

## 8. 单件配套：状态栏、通知、启动器与工具

第 7 节讲的是"整套外壳"（DMS/Noctalia）。这一节讲另一条路：**一个角色一个
程序**，自己拼。两条路是替代关系，不是叠加关系。

先看全景：

| 角色     | 单件实现                             | DMS/Noctalia | 合成器限制            |
|----------|--------------------------------------|--------------|-----------------------|
| 状态栏   | waybar、swaybar                      | 内建         | swaybar 仅 sway       |
| 通知     | mako、dunst、swaync                  | 内建         | 无                    |
| 启动器   | fuzzel、wofi、rofi                   | 内建         | 无                    |
| 锁屏空闲 | swaylock+swayidle、hyprlock+hypridle | 内建         | hypr* 仅 Hyprland     |
| 剪贴板   | wl-clipboard + cliphist              | 不含         | 无                    |
| 截图录屏 | grim+slurp、wf-recorder              | 部分         | 无                    |
| 壁纸     | swaybg、swww、hyprpaper              | 内建取色     | hyprpaper 仅 Hyprland |
| 认证代理 | polkit-gnome、hyprpolkitagent        | 不含         | 无                    |
| 亮度音量 | brightnessctl、wpctl                 | 不含         | 无                    |

三条判断规则：

- **已经用 DMS/Noctalia 的**，状态栏、通知、启动器、锁屏都不用再装，装了反而
  抢 D-Bus 名和层叠区。
- **用 sway 的**，自带 `swaybar`、`swaylock`、`swayidle`、`swaybg`，最小配置
  只需要再补终端和启动器。
- **用 niri 的**，几乎全要自己配，它是三者里唯一什么都不带的。

下面按角色逐个说。

### 8.1 状态栏

显示工作区、窗口标题、时间、电量、网络、音量、托盘。

| 实现         | 包       | 归属       | 说明                        |
|--------------|----------|------------|-----------------------------|
| waybar       | `waybar` | 独立，通用 | 模块最多，配置用 JSON + CSS |
| swaybar      | 随 sway  | sway 自带  | i3bar 协议，够用但不花哨    |
| DMS/Noctalia | —        | 各自内建   | 已内建，不要再装 waybar     |
| plasmashell  | 随 KDE   | Plasma     | Plasma 会话专用             |

waybar 的 `workspaces` 模块按合成器分实现：sway 用 `sway/workspaces`，
Hyprland 用 `hyprland/workspaces`，niri 用 `niri/workspaces`，名字配错就是
空白。其余模块（clock、battery、network、pulseaudio、tray）通用。

**与合成器**：waybar 只依赖 `wlr-layer-shell`，三者都能用；但工作区、窗口
标题这类信息要靠各自的 IPC，所以模块名不同。

**与外壳**：DMS 的 bar 由 quickshell 画，Noctalia v5 自己画，两者和 waybar 是
同一角色的不同实现，**只能跑一个**，否则窗口边缘出现双倍留白。

```bash
pacman -S waybar
```

### 8.2 通知

桌面通知走 D-Bus 的 `org.freedesktop.Notifications`，全系统只有一个服务能
注册成功。

| 实现   | 包       | 特点                           |
|--------|----------|--------------------------------|
| mako   | `mako`   | 轻量，纯 layer-shell，配置简单 |
| dunst  | `dunst`  | 老牌，规则和脚本能力强         |
| swaync | `swaync` | 带通知中心与控制中心，GTK      |
| 内建   | —        | DMS/Noctalia 自带通知服务      |

```bash
pacman -S mako
```

配置在 `~/.config/mako/config`。**与合成器**：无关，只要支持
`wlr-layer-shell` 就能弹。**与外壳**：DMS/Noctalia 已含通知服务，再启 mako
会注册失败——不报错，它的面板永远是空的。

### 8.3 启动器

| 实现   | 包       | 说明                       |
|--------|----------|----------------------------|
| fuzzel | `fuzzel` | Wayland 原生，快，配置 ini |
| wofi   | `wofi`   | GTK3，主题好写             |
| rofi   | `rofi`   | X11 起家，Wayland 支持有限 |
| 内建   | —        | DMS/Noctalia 自带启动器    |

```bash
pacman -S fuzzel
```

绑到 `Mod+D` 即可。rofi 在 Wayland 下建议用 `rofi-wayland` 分支，原版在
layer-shell 上有兼容问题。**与合成器、外壳**：都无关，纯粹是替代关系。

### 8.4 锁屏与空闲

| 组合                    | 适用               | 说明                      |
|-------------------------|--------------------|---------------------------|
| `swaylock` + `swayidle` | sway/Hyprland/niri | 通用，只依赖 layer-shell  |
| `hyprlock` + `hypridle` | Hyprland           | 读 Hyprland IPC，动画更好 |
| 内建                    | DMS/Noctalia       | 含锁屏                    |

`swayidle` 负责超时后调 `swaylock`：

```bash
swayidle -w timeout 300 'swaylock -f' timeout 600 'systemctl suspend'
```

**锁屏是安全边界，只能有一个**。同时跑 swaylock 和 hyprlock，先锁的会被后锁
的盖住，解锁后另一个还挂着。

**与合成器**：`swaylock` 只依赖 layer-shell，三个合成器都能用；`hyprlock`
依赖 Hyprland 的 IPC，换到 niri 直接起不来——这是"Hyprland 生态绑死"的典型
例子。

### 8.5 剪贴板

| 工具              | 作用                          |
|-------------------|-------------------------------|
| `wl-clipboard`    | `wl-copy` / `wl-paste`，基础  |
| `cliphist`        | 历史记录，配合 fuzzel/wofi 选 |
| `wl-clip-persist` | 让内容在程序退出后仍保留      |
| `clipse`          | TUI 剪贴板管理器              |

`cliphist` 需要常驻监听：

```bash
wl-paste --watch cliphist store &
```

之后 `cliphist list | fuzzel --dmenu | cliphist decode | wl-copy` 就是一套
历史选择器。**与合成器、外壳**：都无关，纯协议层工具。

### 8.6 截图与录屏

| 工具          | 作用                 |
|---------------|----------------------|
| `grim`        | 截图                 |
| `slurp`       | 选区，配合 grim      |
| `swappy`      | 截图后标注           |
| `wf-recorder` | 录屏                 |
| `obs-studio`  | 直播/录制，走 portal |

```bash
grim -g "$(slurp)" - | swappy -f -     # 选区截图并标注
```

**与合成器**：sway、Hyprland、niri 都实现 `wlr-screencopy`，`grim` 直接可用。
OBS 这类走 `xdg-desktop-portal` 的，需要装对应合成器的 portal，见 11.2。niri
自带截图动作（`niri msg action screenshot`），可以不装 grim。

### 8.7 壁纸

| 实现        | 包          | 适用        | 说明                 |
|-------------|-------------|-------------|----------------------|
| `swaybg`    | `swaybg`    | 通用        | 静态图，最小         |
| `swww`      | `swww`      | 通用        | 带过渡动画，支持 GIF |
| `hyprpaper` | `hyprpaper` | 仅 Hyprland | 走 Hyprland IPC      |

niri 只有纯色背景（`layout { background-color }`），要图片壁纸得装 `swaybg`
或 `swww`。**与外壳**：DMS/Noctalia 从壁纸取色生成主题，换壁纸要用它自己的
方式，否则配色不会跟着变。

### 8.8 认证代理

| 实现              | 包                | 说明                    |
|-------------------|-------------------|-------------------------|
| `polkit-gnome`    | `polkit-gnome`    | 通用，GTK               |
| `hyprpolkitagent` | `hyprpolkitagent` | Hyprland 出品，也能他用 |
| `lxpolkit`        | `lxpolkit`        | 轻量                    |

不装的表现：挂载 U 盘、装软件、改系统设置时弹不出密码框，操作被静默拒绝。

**只能有一个**。两个代理同时运行会抢 `PolicyKit1.AuthenticationAgent`，
表现是弹两个框或者一个都不弹。KDE 会话自带 `polkit-kde`，别再装 gnome 版。

### 8.9 亮度、音量与其他

| 工具            | 控制什么     | 备注                   |
|-----------------|--------------|------------------------|
| `brightnessctl` | 屏幕亮度     | 读写 sysfs，不需要守护 |
| `wpctl`         | 音量、麦克风 | 随 wireplumber 提供    |
| `pamixer`       | 音量         | 命令行，脚本友好       |
| `playerctl`     | 播放器控制   | MPRIS                  |

这些是纯命令行工具，绑到快捷键或 waybar 模块里调用，不占常驻进程，也不存在
冲突问题。

```bash
brightnessctl set 5%+                          # 亮度加 5%
wpctl set-volume @DEFAULT_AUDIO_SINK@ 5%+      # 音量加 5%
```

### 8.10 成套还是单件

| 你的情况            | 建议                                              |
|---------------------|---------------------------------------------------|
| 已经有 DMS/Noctalia | 什么都不用补，bar/通知/启动器/锁屏都已内建        |
| 用 sway             | 自带 bar/lock/idle/bg，补 `foot` 和 `fuzzel` 即可 |
| 用 Hyprland         | 配官方四件 hyprlock/hypridle/hyprpaper/hyprpicker |
| 用 niri             | 全要自己配：waybar+mako+fuzzel+swaylock+swaybg    |
| 只要一条状态栏      | waybar，别上完整外壳                              |

混搭是常态：sway 配 waybar、niri 配 mako、Hyprland 配 swaylock 都行，前提是
每个角色只有一个实现。跨角色的冲突见第 11 节。

## 9. 显示管理器：从开机到登录界面

第 5 节讲整套桌面里有什么，这一节讲**谁把它拉起来**，以及**在哪决定进哪一套**。
先解决一个容易卡住的问题：装了五套桌面，`enable` 的却只有一个 DM——这是对的。

```text
enable sddm → 开机 sddm 常驻，画出登录界面并列出所有会话文件
            → 你点选一个 → sddm 以你的用户执行该文件的 Exec=
            → 那套组合自己的自启项把 bar、通知、输入法拉起来
```

决定「哪套」的不是服务，而是会话文件里那一行 `Exec=`：

| 会话文件                            | `Exec=`               | 这套的配套由谁拉起                 |
|-------------------------------------|-----------------------|------------------------------------|
| `wayland-sessions/hyprland.desktop` | `Hyprland`            | `hyprland.conf` 的 `exec-once`     |
| `wayland-sessions/niri.desktop`     | `niri-session`        | `config.kdl` 的 `spawn-at-startup` |
| `wayland-sessions/plasma.desktop`   | `startplasma-wayland` | Plasma 自启与 plasmashell          |
| `wayland-sessions/gnome.desktop`    | `gnome-session`       | GNOME Shell 内部                   |
| `xsessions/xfce.desktop`            | `startxfce4`          | xfce4-session 恢复的会话           |
| `wayland-sessions/sway.desktop`     | `sway`                | `~/.config/sway/config` 的 `exec`  |

由此两条推论：

- **组合是运行时的选择，不是安装时绑定的**。装包只是把程序和会话文件放到
  磁盘，进哪套是在登录界面点出来的。
- **配套只跟随自己的会话**。`waybar`、`mako` 不会自动出现在任何桌面里，只有
  Hyprland 的 `exec-once` 或 niri 的 `spawn-at-startup` 点名时才起来；进 KDE
  它们根本不启动。

所以系统级常驻的只有一个 DM：五套组合互斥，同一时刻只有一套能拿到显示输出，
为每套都 `enable` 一个服务只会让它们互相抢 tty 和 DRM，结果是弹回登录界面或
黑屏。DM 在启动链上的位置、换 DM 会不会影响桌面，见 9.1。

### 9.1 角色与启动链

第 5 节那张表容易让人以为 DM 是桌面的一部分——**不是**。它职责只有一件：
开机画出登录界面，按你选的会话把桌面拉起来，在启动链上站在合成器之前：

```text
systemd → graphical.target → display-manager.service → 登录界面 → 会话 → 合成器
```

所以三件事成立：

- 换桌面不用换 DM，两者互不依赖。
- 换 DM 也不影响桌面，改的只是 `display-manager.service` 指向哪个单元。
- 五套组合可以共用同一个 DM。

### 9.2 有哪些实现

四个常用实现，能力都够，差别在技术栈和配套：

| DM      | 包                  | 技术栈     | 特点                                | 常见搭配   |
|---------|---------------------|------------|-------------------------------------|------------|
| SDDM    | `sddm`              | Qt/QML     | 主题多，0.21 起支持 Wayland greeter | KDE、LXQt  |
| GDM     | `gdm`               | GTK        | 与 GNOME 会话、锁屏深度集成         | GNOME      |
| LightDM | `lightdm` + greeter | 多 greeter | 轻量，greeter 可选 GTK/Qt/slick     | Xfce       |
| greetd  | `greetd` + greeter  | 极简       | 只做登录，界面完全交给 greeter      | 自定义组合 |

`lightdm` 和 `greetd` 只装本体没用，必须配一个 greeter（`lightdm-gtk-greeter`、
`greetd-tuigreet`），否则登录界面是空白或干脆起不来。SDDM 和 GDM 自带
greeter，装完即用。

**SDDM 常被当成 KDE 的一部分，其实也不是**：源码在 `github.com/sddm/sddm`，
不属于 KDE 代码库，只是 KDE 长期默认搭配。包的关系也印证这一点：

| 包         | 作用                               | 谁带进来         |
|------------|------------------------------------|------------------|
| `sddm`     | 登录界面本体                       | 要自己单独装     |
| `sddm-kcm` | KDE 系统设置里的「登录屏幕」配置页 | `plasma-meta` 带 |
| `breeze`   | SDDM 默认主题用的样式资源          | 装 KDE 时已有    |

`plasma-meta` 只带配置模块，本体要单独装——这就是第 10 节 KDE 那套命令写成
两行的原因。想核实依赖可以直接查：

```bash
pacman -Si plasma-meta | grep -i sddm
```

SDDM 的配置文件与日志：

```text
/etc/sddm.conf              # 主配置，一般不动
/etc/sddm.conf.d/*.conf     # 覆盖片段，autologin 写这里
/usr/share/sddm/themes/     # 主题目录
journalctl -b -u sddm       # 登录界面起不来时看这里
```

SDDM 从 0.21 起支持 Wayland greeter，默认用哪个看 `[General]` 里的
`DisplayServer`。greeter 本身跑 X11 还是 Wayland 不影响你登录后的会话类型，
那是两件事。

### 9.3 启用：装完不等于会用

`pacman -S` 只把文件放到磁盘，**没有任何东西会自己开机启动**。从"装完"到
"能登录"要做三件事：

```bash
# 1. 启用显示管理器：既建立开机自启，也立刻启动一次
sudo systemctl enable --now sddm        # GNOME 用 gdm，Xfce 用 lightdm

# 2. 确认开机会进入图形界面
systemctl get-default                   # 显示 multi-user.target 就要改
sudo systemctl set-default graphical.target

# 3. 确认生效
systemctl is-enabled sddm               # 应输出 enabled
systemctl status display-manager --no-pager
```

`systemctl` 这几个动作容易混，区别只在"现在"和"下次开机"：

| 命令                           | 作用                       | 什么时候用       |
|--------------------------------|----------------------------|------------------|
| `start sddm`                   | 只在本次开机内启动         | 调试，重启就没了 |
| `enable sddm`                  | 只建立开机自启，不立刻启动 | 还没配好，先别起 |
| `enable --now sddm`            | 两件事一起做               | 正常启用         |
| `set-default graphical.target` | 让开机默认进入图形目标     | 一直停在 tty 时  |

**为什么还要 `set-default`**：`enable sddm` 只是让 sddm 挂在
`graphical.target` 上，它自己不会把系统默认目标改成图形。系统默认目标仍是
`multi-user.target` 时，开机根本不会激活 `graphical.target`，DM 永远等不到，
屏幕就停在 tty。archinstall 装的系统一般是 `graphical.target`，手工按 wiki
装的常见是 `multi-user.target`。

`enable` 之后会多出一个符号链接，它指向的就是真正生效的那个 DM：

```bash
ls -l /etc/systemd/system/display-manager.service
# -> /usr/lib/systemd/system/sddm.service
```

多个 DM 都 `enable` 过时，后来的会覆盖这个链接，其余仍处于 enabled 但不生效
——这正是 9.9 要清掉的情况。每套组合怎么启用、服务怎么开停，集中在第 10 节。

验证：

```bash
systemctl is-enabled sddm                    # 输出 enabled 才对
systemctl status display-manager             # 看当前 DM 是否 active
systemctl get-default                        # 应为 graphical.target
ls /usr/share/wayland-sessions/              # 会话菜单里能选的东西
```

**会话从哪来**：DM 读 `/usr/share/wayland-sessions/*.desktop` 和
`/usr/share/xsessions/*.desktop`。装了 niri 就有 `niri.desktop`，装了
Hyprland 就有 `hyprland.desktop`，**不用手写**。列表里没有你想要的桌面，
说明那个包没装成功。

### 9.4 自动登录：连密码也不输

在路线一的基础上加一段配置。适合家用固定机器；笔记本慎用，物理接触即等于
已登录。

**SDDM**，新建 `/etc/sddm.conf.d/autologin.conf`：

```ini
[Autologin]
User=lhj
Session=niri
Relogin=true
```

`Session` 取会话文件名去掉 `.desktop`，比如 `niri`、`hyprland`、`plasma`。
`Relogin=true` 让注销后自动回到登录，不会卡在 tty。

**GDM**，编辑 `/etc/gdm/custom.conf`：

```ini
[daemon]
AutomaticLoginEnable=true
AutomaticLogin=lhj
```

GDM 的自动登录**不能在这里指定会话**，它进上次用过的那个。要改默认会话，
在登录界面齿轮里选一次，或者改 `/var/lib/AccountsService/users/<用户名>` 里的
`XSession=`。

**LightDM**，编辑 `/etc/lightdm/lightdm.conf`：

```ini
[Seat:*]
autologin-user=lhj
autologin-session=niri
```

LightDM 还要求用户属于 `autologin` 组，否则静默回退到登录界面：

```bash
sudo groupadd -r autologin 2>/dev/null
sudo gpasswd -a lhj autologin
```

验证：重启一次，看到桌面出现且没停在任何登录框前。

### 9.5 完全不用显示管理器

单用户、只跑一套桌面时最省资源，开机直接进合成器。两步。

第一步，让 tty1 自动登录：

```bash
sudo systemctl edit getty@tty1.service
```

在打开的编辑器里写：

```ini
[Service]
ExecStart=
ExecStart=-/usr/bin/agetty --autologin lhj --noclear %I $TERM
```

`ExecStart=` 那行空赋值是**必须的**，用来清掉原来的命令；只写第二行会变成两个
`ExecStart`，起不来。

第二步，登录后自动 exec 会话，写进 `~/.bash_profile`（zsh 用户写
`~/.zprofile`）：

```bash
if [ -z "$WAYLAND_DISPLAY" ] && [ "$(tty)" = "/dev/tty1" ]; then
    exec niri-session
fi
```

判断 `WAYLAND_DISPLAY` 是为了避免在图形终端里重复启动；判断 tty 是为了只在
tty1 触发，切到 tty2 仍是普通登录。

要换成 Hyprland 就把最后一行改成 `exec Hyprland`。**必须用会话启动器**
（`niri-session`、`Hyprland`），裸 `niri` 拿不到 systemd 用户会话，portal 和
通知全都会静默失效。

退出桌面后回到 tty1，再 `exit` 才是真的登出。

### 9.6 greetd：轻量但保留会话菜单

比 sddm 轻，比 autologin 灵活，能列会话菜单：

```bash
sudo pacman -S greetd greetd-tuigreet    # 包名以 pacman -Ss greetd 为准
```

编辑 `/etc/greetd/config.toml`：

```toml
[terminal]
vt = 1

[default_session]
command = "tuigreet --time --remember --cmd niri-session"
user = "greetd"
```

```bash
sudo systemctl enable --now greetd
```

`--sessions /usr/share/wayland-sessions` 让它列出所有会话，不加也能用
`--cmd` 指定默认。greetd 会占住 tty1，**和路线三的 getty 覆盖冲突**，二选一。

### 9.7 四条路线怎么选

| 场景                     | 建议路线            |
|--------------------------|---------------------|
| 多用户，或经常换桌面会话 | 一（DM）            |
| 家里固定机器，单人使用   | 二（DM + 自动登录） |
| 单桌面、追求开机最快     | 三（getty + exec）  |
| 想轻量但还要选会话       | 四（greetd）        |

不管选哪条，都留着 tty 作为退路：`Ctrl+Alt+F3` 能进文本终端，图形界面起不来时
从这里修。别再额外配自动登录到所有 tty。

### 9.8 登录时选中哪个会话

DM 的登录界面上有个会话选择器（GDM 在密码框下方的齿轮，SDDM 在左下角），
列出的就是磁盘上现成的会话文件：

```bash
ls /usr/share/wayland-sessions/    # plasma、niri、hyprland、sway 等
ls /usr/share/xsessions/           # 只有 X11 会话才在这里
```

**列表为空 = 装了合成器却没有会话文件**，DM 里自然选不到，只能看到 GNOME/
KDE。这时要么重装对应包，要么在 tty 里手动起（第 6 节）。

不想每次手选，就写死默认会话：

| DM      | 配置文件                                  | 要改的键                          |
|---------|-------------------------------------------|-----------------------------------|
| sddm    | `/etc/sddm.conf.d/10-session.conf`        | `[Autologin]` 的 `Session=plasma` |
| gdm     | `/var/lib/AccountsService/users/<用户名>` | `XSession=gnome`                  |
| lightdm | `/etc/lightdm/lightdm.conf`               | `[Seat:*]` 的 `user-session=xfce` |

sddm 默认会记住上次选的会话（存在 `/var/lib/sddm/state.conf` 的 `LastSession=`），
所以多数人不用改这张表。Plasma 同时提供 Wayland 和 X11 两个会话，选带
`(Wayland)` 的。想确认当前到底进了哪套：

```bash
echo $XDG_CURRENT_DESKTOP      # Hyprland / niri / KDE / GNOME / XFCE
loginctl show-session $(loginctl | awk '/lhj/{print $1; exit}') -p Desktop
```

`XDG_CURRENT_DESKTOP` 是配套程序判断「该不该启动自己」的依据，waybar 用它挑
模块，portal 用它挑后端（见 11.2）。

起不来时的排查顺序固定：先 `systemctl status display-manager` 看是否 active，
再 `journalctl -b -u display-manager` 看具体报错，最后才怀疑显卡驱动。

### 9.9 只能启用一个

- `gdm`、`sddm`、`lightdm` 同时 enable 会互相抢 tty，表现为登录后又弹回登录
  界面。查一遍：

  ```bash
  systemctl list-unit-files --state=enabled | grep -E 'gdm|sddm|lightdm|greetd'
  ```

  多于一行就留一个，其余 `sudo systemctl disable --now sddm` 关掉。
- 平铺合成器不需要 DM 也能跑：登录 tty 后直接执行 `sway`、`Hyprland` 或
  `niri-session`，详见第 6 节。

### 9.10 重启前的自检

- [ ] `systemctl get-default` 输出 `graphical.target`
- [ ] `systemctl is-enabled <你的DM>` 输出 `enabled`
- [ ] `/etc/systemd/system/display-manager.service` 只指向一个 DM
- [ ] `ls /usr/share/wayland-sessions/` 里有你要进的会话
- [ ] `systemctl --failed` 为空
- [ ] 重启后能看到登录界面，选会话后能进桌面
- [ ] `echo $XDG_CURRENT_DESKTOP` 输出与登录时选的那套一致

## 10. 五套桌面组合：从装包到启用

第 5～8 节按角色讲（合成器、外壳、单件工具），这一节反过来，按**成品的组合**
讲：每一套要装哪些包、怎么启用、开机后各自拉起什么。选一套照着做即可，五套
可以共存安装，只是同时只能跑一个。

先给结论，五套的完整搭配：

```text
Hyprland + foot + fuzzel + mako + waybar + hyprlock/hypridle + polkit-gnome
niri     + foot + fuzzel + mako + waybar + swaylock/swayidle + polkit-gnome
KDE      + Konsole + KRunner + Plasma 通知 + plasmashell + KWallet + polkit-kde
GNOME    + GNOME Console + 活动概览 + GNOME Shell + gcr + polkit-gnome
Xfce     + xfce4-terminal + xfce4-appfinder + xfce4-notifyd + xfce4-panel + polkit
```

前两套是"自己拼"，每个角色一个独立程序；后三套是"整套买"，角色由桌面自己
提供。下面先讲所有组合共有的自启问题，再逐套展开。

**先说清楚一件事**：正常开机进图形界面，**不需要你敲任何命令**。只要把某一个
显示管理器 `enable` 起来，开机就自动停在登录界面，选会话、输密码，就进桌面了。
后面每套里出现的 `Hyprland`、`niri-session` 这类命令，只在两种场合用：登录
界面起不来时排查，或者你压根不想装显示管理器。三种程度对照：

| 你要的效果             | 需要做什么                            | 开机看到 |
|------------------------|---------------------------------------|----------|
| 开机到登录界面再输密码 | `enable` 一个 DM                      | 登录界面 |
| 开机直接进桌面         | `enable` 一个 DM + 配 autologin       | 桌面     |
| 不装 DM 也直接进桌面   | 覆盖 `getty@tty1` 或在登录脚本里 exec | 桌面     |

详细做法集中在 9.7，下面各套只提"这套该选哪个会话"。

### 10.1 会话自启：装完不等于跑起来

装完 waybar、mako、cliphist 不等于它们会自己跑。**合成器只负责窗口，状态栏、
通知、剪贴板历史、锁屏、壁纸、认证代理都要在会话启动时点名拉起**。从登录界面
进 Hyprland 看到光秃秃一片，多半就是这一节没做。

三条自启机制，作用域不同：

| 机制             | 位置                                                       | 谁在用           |
|------------------|------------------------------------------------------------|------------------|
| 合成器自启       | Hyprland `exec-once`、niri `spawn-at-startup`、sway `exec` | 自定义组合       |
| XDG autostart    | `~/.config/autostart/*.desktop`                            | KDE/GNOME/Xfce   |
| systemd 用户服务 | `systemctl --user enable`                                  | 需日志与重启策略 |

KDE、GNOME、Xfce 的 bar 和通知由桌面会话自己拉起，不用你写，它们只把 XDG
autostart 留给第三方程序；Hyprland 和 niri 没有这层，主要用第一种，systemd 用户
服务作为补充（见下面 polkit 的第二种装法）。

哪些必须常驻，哪些用到才跑：

| 工具                  | 常驻 | 怎么起                            | 不跑会怎样           |
|-----------------------|------|-----------------------------------|----------------------|
| waybar                | 是   | `waybar`                          | 完全没有状态栏       |
| mako / dunst / swaync | 是   | `mako`                            | `notify-send` 无反应 |
| cliphist              | 是   | `wl-paste --watch cliphist store` | 历史永远是空的       |
| hyprpaper / swaybg    | 是   | `hyprpaper`、`swaybg -i <图>`     | 只剩纯色背景         |
| hypridle / swayidle   | 是   | `hypridle`                        | 不会自动锁屏         |
| polkit 代理           | 是   | 见下面两种装法                    | 挂载、装包静默失败   |
| fcitx5                | 是   | `fcitx5 -d`                       | `Ctrl+Space` 无反应  |
| fuzzel、grim、slurp   | 否   | 键位里 `spawn`                    | 按需，无所谓         |
| wl-copy、wl-paste     | 否   | 命令行直接调                      | 单次复制粘贴         |

Hyprland 写进 `~/.config/hypr/hyprland.conf`：

```ini
exec-once = waybar
exec-once = mako
exec-once = wl-paste --watch cliphist store
exec-once = hyprpaper
exec-once = hypridle
exec-once = fcitx5 -d
```

niri 写进 `~/.config/niri/config.kdl`，一个参数一个引号：

```kdl
spawn-at-startup "waybar"
spawn-at-startup "mako"
spawn-at-startup "wl-paste" "--watch" "cliphist" "store"
spawn-at-startup "fcitx5" "-d"
```

`wl-copy`、`wl-paste` 本身只是命令行工具，不需要常驻；要有历史记录，必须让
`wl-paste --watch cliphist store` 这个进程一直活着，否则 `cliphist list` 永远是
空的。

**认证代理最容易漏**：没有它，挂载 U 盘、用图形界面装包会静默失败——不是报错，
是密码框根本弹不出来。

```ini
# 方式一：polkit-gnome，写进 exec-once
exec-once = /usr/lib/polkit-gnome/polkit-gnome-authentication-agent-1
```

```bash
# 方式二：Hyprland 官方代理，走 systemd 用户服务
sudo pacman -S hyprpolkitagent
systemctl --user enable --now hyprpolkitagent
```

方式二更省事：注销重登自动带起，不用改配置。

验证：

```bash
pgrep -a -f 'waybar|mako|cliphist|polkit'
systemctl --user status hyprpolkitagent
notify-send test
```

`notify-send` 没反应说明通知服务没起，弹两次说明装了两套，见 11.1。

改完配置要**注销重登**，不要只 `hyprctl reload`：`exec-once` 在本次会话已经执行
过，reload 不会再跑一遍。反过来，手动 `hyprctl dispatch exec waybar` 试过之后又
重登，会各起一份，表现为两条 bar 叠在一起。

### 10.2 Hyprland 组合

**组合**：合成器 Hyprland 自带窗口管理、动画、锁屏外的绝大多数视觉效果；终端、
启动器、通知、状态栏都要另装。用 `uwsm` 把会话交给 systemd 管理，环境变量和
portal 最规范。

```bash
sudo pacman -S hyprland xdg-desktop-portal-hyprland uwsm \
  foot fuzzel mako waybar hyprlock hypridle hyprpaper hyprpicker \
  polkit-gnome brightnessctl grim slurp wl-clipboard
```

**启用：开机自动进这套**

```bash
sudo pacman -S sddm                     # 已有 gdm/lightdm 就跳过这行
sudo systemctl enable --now sddm
sudo systemctl set-default graphical.target
```

重启后停在登录界面，会话菜单里选 `Hyprland`（文件在
`/usr/share/wayland-sessions/hyprland.desktop`）。想连密码都不输，在
`/etc/sddm.conf.d/autologin.conf` 把 `Session` 写成 `hyprland`，完整字段见
9.4。三行各自的作用和验证见 9.3。

**不装 DM 时的手动入口**（排查用，正常开机不需要）：

```bash
Hyprland                     # tty 里直接起，日志打在屏幕上
uwsm start hyprland.desktop  # 同上，但会话交给 systemd 管，推荐
```

要让开机直接进 Hyprland 又不装 DM，走 9.5 的 getty 方案，`exec` 后面换成
`Hyprland`。

**启动时拉起配套**，写在 `~/.config/hypr/hyprland.conf`：

```ini
exec-once = waybar
exec-once = mako
exec-once = hyprpaper
exec-once = hypridle
exec-once = fcitx5 -d
```

**查快捷键**：Hyprland 没有 niri 那种内置浮层（`Mod+Shift+/`），绑定存在运行时
状态里，靠 `hyprctl` 查：

```bash
hyprctl binds                                        # 全部绑定
hyprctl binds | grep -i -B1 -A1 kitty                # 某个键绑了什么
hyprctl submap                                       # 当前子模式，空为默认
```

输出字段依次是 `modmask`、`key`、`dispatcher`、`arg`、`description`。`modmask`
是位掩码，要换算才看得懂：

| 值 | 含义          |
|----|---------------|
| 1  | SHIFT         |
| 4  | CTRL          |
| 8  | ALT           |
| 64 | SUPER（Mod4） |
| 72 | SUPER+ALT     |

装上 `jq` 后可以把它变成一行一条的可读清单：

```bash
hyprctl binds -j | jq -r '.[] | "\(.modmask)\t\(.key)\t\(.dispatcher) \(.arg)"'
```

想按一个键就弹出来，写 `~/.config/hypr/binds.sh` 并 `chmod +x`：

```sh
#!/bin/sh
hyprctl binds -j |
  jq -r '.[] | "\(.modmask)\t\(.key)\t\(.dispatcher) \(.arg)"' |
  fuzzel --dmenu
```

```ini
bind = $mainMod, SLASH, exec, ~/.config/hypr/binds.sh
```

按 `Super+/` 弹出可搜索的列表，Esc 关闭。命令放进脚本而不是直接写 `bind`，
是因为 `bind` 的 `exec` 段不适合塞管道和引号。终端版本换成
`kitty --hold sh -c 'hyprctl binds'`。

另一个权威来源是 `/usr/share/hypr/hyprland.conf`，注释里逐条解释了默认绑定：

```bash
grep -n -B2 "^bind" /usr/share/hypr/hyprland.conf | head -60
```

**这套特有的坑**：

- 默认配置里 `$terminal = kitty`，但 `hyprland` 包不依赖 kitty。没装 kitty 时
  `Super+Q` 按下毫无反应，也不报错，换成 `$terminal = foot` 或装 kitty 即可。
- portal 必须装 `xdg-desktop-portal-hyprland`，装成 `-wlr` 时截图、屏幕共享会
  静默失败。
- NVIDIA 显卡必须在 `/etc/kernel/cmdline` 里加 `nvidia_drm.modeset=1`，改完
  `mkinitcpio -P`，否则登录后黑屏或花屏。
- `hyprlock`、`hypridle` 依赖 Hyprland 的 IPC，换成别的合成器就起不来。

### 10.3 niri 组合

**组合**：niri 只管合成和窗口排列，连 XWayland、锁屏、壁纸都不带，配套装得
最全。好处是配置只有一个 KDL 文件，滚动式平铺对宽屏友好。

```bash
sudo pacman -S niri xwayland-satellite xdg-desktop-portal-wlr \
  foot fuzzel mako waybar swaylock swayidle swaybg \
  polkit-gnome brightnessctl grim slurp wl-clipboard
```

**启用：开机自动进这套**

```bash
sudo pacman -S sddm                     # 已有 gdm/lightdm 就跳过这行
sudo systemctl enable --now sddm
sudo systemctl set-default graphical.target
```

重启后停在登录界面，会话菜单里选 `niri`（文件在
`/usr/share/wayland-sessions/niri.desktop`）。想连密码都不输，在
`/etc/sddm.conf.d/autologin.conf` 把 `Session` 写成 `niri`，完整字段见 9.4。

**不装 DM 时的手动入口**（排查用，正常开机不需要）：

```bash
niri-session                     # tty 里起，必须带 -session
```

**不要裸敲 `niri`**：那样拿不到 systemd 用户会话，portal、通知、dbus 服务会
静默失效。要让开机直接进 niri 又不装 DM，走 9.5 的 getty 方案，`exec` 后面
换成 `niri-session`。

**启动时拉起配套**，写在 `~/.config/niri/config.kdl`：

```kdl
spawn-at-startup "waybar"
spawn-at-startup "mako"
spawn-at-startup "swaybg" "-i" "/path/to/wallpaper.png"
spawn-at-startup "fcitx5" "-d"
```

**这套特有的坑**：

- 没有 XWayland：要跑 X11 老程序必须装 `xwayland-satellite`。
- 不实现截图共享：portal 用 `xdg-desktop-portal-wlr`，缺了 `grim` 直接失败。
- 默认配置是空的：登录后就是纯色背景，没有 bar 也没有壁纸，这不是故障。

### 10.4 KDE Plasma 组合

**组合**：`plasma-meta` 一次给全合成器 KWin、外壳 plasmashell、终端 Konsole、
启动器 KRunner、通知服务、认证代理。用 `sddm` 做登录界面——它是独立组件，
不属于 KDE，`plasma-meta` 只带配置模块不带本体，见 9.1。

```bash
sudo pacman -S plasma-meta sddm
sudo pacman -S kde-applications-meta     # 可选：Dolphin、Kate 等应用套件
```

**启用：开机自动进这套**。`sddm` 已在安装命令里装好，只差启用：

```bash
sudo systemctl enable --now sddm
sudo systemctl set-default graphical.target
```

这两行做完，**下次开机就自动停在登录界面**，不用敲任何命令。会话菜单里选
`Plasma (Wayland)`，对应 `/usr/share/wayland-sessions/plasma.desktop`
（Plasma 5 时代叫 `plasmawayland.desktop`）。想连密码都不输，在
`/etc/sddm.conf.d/autologin.conf` 把 `Session` 写成 `plasma`，见 9.4。

**启动时拉起配套**：不需要手写。KDE 的"系统设置 → 开机与关机 → 自动启动"
会往 `~/.config/autostart/*.desktop` 写条目，polkit 代理、电源管理、剪贴板
历史都由它自己管。

**这套特有的坑**：

- 别在 niri 或 Hyprland 会话里 `exec plasmashell`，两套外壳会互相抢通知服务。
- `/etc/xdg/autostart/` 里的 KDE 条目在任何会话都会被执行，和 `polkit-gnome`
  抢角色；屏蔽方法见 6.7。
- 完整 Plasma 占 1～2 GB，只当备用就只装 `plasma-desktop`。

### 10.5 GNOME 组合

**组合**：`gnome` 包组一次给全 Mutter、GNOME Shell、终端、文件管理器、通知、
认证代理；`gdm` 是登录界面。GNOME Shell 是 Mutter 的插件，两者换不掉。

```bash
sudo pacman -S gnome gdm
```

**启用：开机自动进这套**

```bash
sudo systemctl enable --now gdm
sudo systemctl set-default graphical.target
```

这两行做完，**下次开机就自动停在登录界面**，不用敲任何命令。会话菜单里选
`GNOME`（`gnome.desktop`，X11 版是 `gnome-xorg.desktop`）。想连密码都不输，
在 `/etc/gdm/custom.conf` 的 `[daemon]` 段加 `AutomaticLogin=lhj`，见 9.4。
同一个文件里写 `WaylandEnable=false` 会隐藏 Wayland 会话。

**启动时拉起配套**：装扩展用 `gnome-extensions`，自启项在
`~/.config/autostart/` 或"优化"应用里配。不需要 `waybar`、`mako` 这类外部
组件，装上反而会和 GNOME Shell 的 bar、通知重复。

**这套特有的坑**：

- `gdm` 和 `sddm` 都 enable 时登录后会弹回登录界面，只留一个。
- GNOME 自带的 portal 是 `xdg-desktop-portal-gnome`，装了 `-hyprland` 不会
  自动切换，按会话选。
- 想用平铺行为要靠扩展，别指望它像 niri。

### 10.6 Xfce 组合

**组合**：`xfce4` + `xfce4-goodies` 提供 Xfwm4、xfce4-panel、Thunar、
xfce4-terminal、xfce4-notifyd；`lightdm` + `lightdm-gtk-greeter` 做登录界面。
纯 X11，没有 Wayland 会话。

```bash
sudo pacman -S xfce4 xfce4-goodies lightdm lightdm-gtk-greeter
```

**启用：开机自动进这套**

```bash
sudo systemctl enable --now lightdm
sudo systemctl set-default graphical.target
```

这两行做完，**下次开机就自动停在登录界面**，不用敲任何命令。会话菜单里选
`Xfce Session`（文件在 `/usr/share/xsessions/xfce.desktop`）。想连密码都不输，
在 `/etc/lightdm/lightdm.conf` 的 `[Seat:*]` 段写 `autologin-user=lhj` 和
`autologin-session=xfce`，还要把用户加进 `autologin` 组，见 9.4。没装 DM 时
在 tty 里 `startxfce4`。

**启动时拉起配套**：Xfce 自己带面板、通知、窗口管理器；自启项在"设置 →
会话和启动"里配，落在 `~/.config/autostart/`。输入法用 fcitx5 时要设
`GTK_IM_MODULE=fcitx`（X11 走 immodule，不像 Wayland 有 text-input）。

**这套特有的坑**：

- 只装 `lightdm` 不装 `lightdm-gtk-greeter`，登录界面是空白或掉到默认主题。
- X11 下 Wayland 原生程序走 XWayland，屏幕缩放和输入法容易出问题。
- 想同时有 Wayland 会话，就再装一套别的，Xfce 自己不给。

### 10.7 五套对比与共存

| 组合     | 覆盖的角色         | 安装体积 | portal 后端 | 会话类型    |
|----------|--------------------|----------|-------------|-------------|
| Hyprland | 合成器，其余全外挂 | 小       | `-hyprland` | Wayland     |
| niri     | 合成器，其余全外挂 | 小       | `-wlr`      | Wayland     |
| KDE      | 全套               | 大       | `-kde`      | Wayland/X11 |
| GNOME    | 全套               | 大       | `-gnome`    | Wayland/X11 |
| Xfce     | 全套               | 中       | `-gtk`      | 仅 X11      |

五套**都能装在同一台机器上**，靠 DM 的会话菜单切换，同一时刻只有一个在跑。
要注意的是：

- 显示管理器只能 enable 一个（`sddm`、`gdm`、`lightdm` 三选一），其余的
  `disable --now`。
- 切换会话等于换一套外壳，bar、通知、锁屏各用各的，不要指望通用。
- 自定义组合（Hyprland、niri）的 bar、通知程序不要塞进 KDE/GNOME 的自启，
  否则两套外壳会抢 `org.freedesktop.Notifications`。

### 10.8 通用操作：单元、启用、停用

不管选哪一套，开机自启都走 systemd，三套概念先分清：

| 概念     | 是什么                             | 图形界面相关例子                        |
|----------|------------------------------------|-----------------------------------------|
| 单元     | 一个可启动的对象，后缀区分类型     | `sddm.service`、`bluetooth.service`     |
| 目标     | 一组单元的集合，表示"开机到哪一步" | `multi-user.target`、`graphical.target` |
| 会话文件 | 桌面自己声明的入口，给 DM 读的     | `wayland-sessions/niri.desktop`         |

`default.target` 决定开机停在哪：指向 `multi-user.target` 就只有 tty，指向
`graphical.target` 才会拉起显示管理器。`systemctl set-default` 改的就是这个
软链接。

| 命令                   | 作用                           | 什么时候用             |
|------------------------|--------------------------------|------------------------|
| `start <单元>`         | 只在本次开机内启动             | 调试，重启就没了       |
| `enable <单元>`        | 只建立开机自启，不现在启动     | 还没配好，先别起       |
| `enable --now <单元>`  | 两件事一起做                   | 正常启用               |
| `disable <单元>`       | 取消自启，不停止当前实例       | 清理多余的 DM          |
| `disable --now <单元>` | 取消自启并立刻停止             | 彻底退场               |
| `restart <单元>`       | 停再起，配置改完用它           | 改了 drop-in 之后      |
| `mask <单元>`          | 链接到 `/dev/null`，谁都拉不起 | 彻底封杀，防被依赖拉活 |
| `unmask <单元>`        | 撤销封杀                       | 想重新启用时           |

`disable` 只删自启链接，别的单元依赖它时仍会被拉起；`mask` 才是彻底禁用。改过
单元文件或新建 drop-in 后必须 `sudo systemctl daemon-reload`，否则改动不生效。

改行为不要动 `/usr/lib/systemd/system/` 下的文件（升级会覆盖），用
`systemctl edit <单元>` 生成 `/etc/systemd/system/<单元>.d/override.conf`。

**系统级与用户级**：`systemctl` 管开机服务（DM、蓝牙），`systemctl --user` 管
跟着登录会话生灭的（pipewire、fcitx5、通知服务）。用户级单元放
`~/.config/systemd/user/`，enable 用 `systemctl --user enable --now`。**别把
桌面程序写成系统级服务**——它拿不到 `WAYLAND_DISPLAY`，起来就崩。

**XDG autostart**：`/etc/xdg/autostart/*.desktop` 是全局自启，
`~/.config/autostart/` 是个人自启，任何会话都会执行。要屏蔽某个全局条目，
在同名个人文件里写 `Hidden=true`；这是 KDE 条目串到 niri 会话的根源，见 6.7。

### 10.9 启用之后的冲突排查

冲突基本只有五种形态，按形态找比瞎试快：

| 形态        | 表现                             | 常见元凶                    |
|-------------|----------------------------------|-----------------------------|
| 抢 tty      | 登录后弹回登录界面               | 两个 DM 都 enable           |
| 抢 D-Bus 名 | 第二个进程注册失败，功能静默失效 | 两套通知、两套认证代理      |
| 抢配置文件  | 后启动的覆盖前一个的运行时状态   | 两份 PipeWire、两份电源管理 |
| 抢设备      | 设备列表重复、声音时有时无       | 系统级与用户级各起一份      |
| 抢端口      | `Address already in use`         | 两个服务监听同一端口        |

| 常打架的对手                                  | 该留哪个                       |
|-----------------------------------------------|--------------------------------|
| `gdm` / `sddm` / `lightdm`                    | 只留一个                       |
| `mako` / `dunst` / `swaync` / DMS 内建通知    | 只留一个                       |
| `polkit-gnome` / `hyprpolkitagent` / KDE 自带 | 只留一个                       |
| `power-profiles-daemon` / `tlp`               | 二选一，同时开会抢同一个 sysfs |
| `pipewire` / `pulseaudio`                     | 留 PipeWire                    |
| `systemd-networkd` / `NetworkManager`         | 二选一，别都开                 |

```bash
systemctl list-unit-files --state=enabled | grep -E 'gdm|sddm|lightdm|greetd'
ls -l /etc/systemd/system/display-manager.service   # 只应指向一个 DM
systemctl list-dependencies --reverse sddm          # 谁把它拉起来的
busctl --user list | grep Notifications             # 通知服务只能有一个
systemctl --failed; systemctl --user --failed
journalctl -b -u display-manager -e                 # 登录界面起不来时看这个
ss -tlnp | grep <端口>                              # 端口被谁占了
```

**救场**：改崩了就在引导器里给内核加 `systemd.unit=multi-user.target` 进文本
模式，改回来再重启；或者 `Ctrl+Alt+F3` 进另一个 tty 用 root 登录修。

### 10.10 验收清单

- [ ] 选定的那套能进桌面，`echo $XDG_CURRENT_DESKTOP` 输出对应名字
- [ ] `systemctl get-default` 是 `graphical.target`
- [ ] `systemctl list-unit-files --state=enabled | grep -E 'gdm|sddm|lightdm'`
      只有一行
- [ ] `ls -l /etc/systemd/system/display-manager.service` 指向选定的 DM
- [ ] `systemctl --failed` 和 `systemctl --user --failed` 都为空
- [ ] 会话里 bar、通知、启动器、锁屏各有一个，`notify-send test` 只弹一次
- [ ] 切到 tty 能用命令行起同一套会话，退出后回到 tty

## 11. 跨类共存：冲突总表

第 6、7 节讲的是同类之间，这一节是"合成器 × 外壳 × 系统组件"。原则一句话：
**一个角色只留一个实现**。启用、停用、mask 这些操作本身见 10.8，服务级的冲突
排查（DM 抢 tty、socket 激活、端口占用）见 10.9；这里只讲角色层的重复。

但"只留一个"在两类东西上含义不同：会话级的装多少都行，启动哪个就是哪个；
系统级的装完可能自己跑起来，必须显式关掉。

| 类别                          | 能共存安装 | 只启动一个就够 | 还要做什么                  |
|-------------------------------|------------|----------------|-----------------------------|
| 合成器 sway、Hyprland、niri   | 是         | 是             | 无需额外操作，按会话启动    |
| 桌面环境 GNOME、KDE、Xfce     | 是         | 是             | 无需额外操作，按会话启动    |
| 外壳 waybar、DMS/Noctalia     | 是         | 是             | 配置里只写一条自启          |
| 通知 mako、dunst、swaync      | 是         | 是             | D-Bus 名唯一，后启动的失败  |
| 显示管理器 gdm、sddm、lightdm | 是         | 否             | 多余的 `disable --now` 关掉 |
| `/etc/xdg/autostart` 组件     | 是         | 否             | `Hidden=true` 或 `mask`     |
| portal 实现                   | 是         | 自动选         | 按 `XDG_CURRENT_DESKTOP` 挑 |
| NVIDIA 驱动分支               | 否         | —              | 文件冲突，只能选一个        |
| PulseAudio 与 PipeWire        | 否         | —              | 实现互斥，装之前替换        |

**会话级**（合成器、桌面环境、外壳、通知）：进程随会话生灭，各自往
`/usr/share/wayland-sessions/` 放一个 `.desktop`，`/usr` 和 `~/.config`
共用，互不干扰。选哪个启动就等于选哪套。

**系统级**（显示管理器服务、`/etc/xdg/autostart/`、systemd 用户服务）：
不随会话生灭，开机或登录时自动拉起。

- 显示管理器安装时不自动 enable，一旦 enable 过就常驻。装三个只 enable 一个
  没问题，enable 两个才会抢 tty，表现是登录后又弹回登录界面。
- `/etc/xdg/autostart/` 更隐蔽：KDE 装完往里放文件，systemd 的
  xdg-autostart-generator 在任何会话里都执行，包括 niri。结果是
  `polkit-kde` 和 `polkit-gnome` 抢认证代理、`powerdevil` 和 `swayidle`
  抢电源管理。这类只能靠 `~/.config/autostart/` 里写 `Hidden=true` 屏蔽。

少数包根本不能共存，`pacman` 会直接报文件冲突：`nvidia` 与 `nvidia-open`
都提供 `nvidia.ko`，`pulseaudio` 与 `pipewire-pulse` 都占
`pulseaudio.socket`，装之前只能二选一。

下面 10.1 把这些角色摊开，列出抢不到时的具体表现。

### 11.1 冲突总表

| 角色            | 只能有一个                                     | 抢不到的后果                   |
|-----------------|------------------------------------------------|--------------------------------|
| 显示管理器      | gdm / sddm / lightdm 之一                      | 互相抢 tty，登录后弹回登录界面 |
| 通知服务        | mako / dunst / swaync / DMS / Noctalia 之一    | 后启动的注册失败，通知丢失     |
| polkit 认证代理 | polkit-gnome / hyprpolkitagent / lxpolkit 之一 | 弹不出密码框，操作被静默拒绝   |
| 空闲管理 + 锁屏 | swayidle+swaylock 或 hypridle+hyprlock，选一套 | 重复锁屏、重复挂起             |
| 剪贴板管理器    | cliphist 或 wl-clip-persist 之一               | 历史错乱、粘贴内容不更新       |
| 状态栏          | waybar 或 DMS/Noctalia 的 bar，选一个          | 两条面板，窗口边缘双倍留白     |

### 11.2 portal 要按合成器选

`xdg-desktop-portal-hyprland` 与 `xdg-desktop-portal-wlr` 可以同时装着，合成器
按 `XDG_CURRENT_DESKTOP` 选一个：

| 合成器      | 需要的 portal 包              |
|-------------|-------------------------------|
| Hyprland    | `xdg-desktop-portal-hyprland` |
| sway / niri | `xdg-desktop-portal-wlr`      |
| 通用兜底    | `xdg-desktop-portal-gtk`      |

装错的表现是截图、屏幕共享、文件选择框不工作。`-gtk` 可以一直留着，负责文件
选择框。

### 11.3 怎么检查

```bash
systemctl --user --failed                       # 哪个用户服务没起来
ps -ef | grep -E 'mako|dunst|swaync|waybar'     # 有几个通知/状态栏进程
notify-send test                                # 通知能不能弹出来
```

两个隐蔽的坑：

- **环境变量**：在 `~/.config/environment.d/` 或 `~/.profile` 里写死某个合成器
  的变量（`HYPRLAND_*`、`SWAYSOCK`），换会话后可能指向不存在的实例，表现为
  工具连不上 IPC。
- **自启项**：`~/.config/autostart/` 里的锁屏、壁纸、合成器专属守护进程，会在
  另一个合成器里也启动，多数静默失败并刷日志。

实践建议：先装一个合成器加一套外壳跑顺，再装第二个做对比；切换用显示管理器
的会话菜单，或 tty 里直接敲命令。

## 12. 中文字体与 locale


```bash
pacman -S noto-fonts noto-fonts-cjk noto-fonts-emoji ttf-dejavu
```

locale 必须是 UTF-8，否则中文可能显示为方块或乱码：

```bash
sed -i 's/^#zh_CN.UTF-8/zh_CN.UTF-8/' /etc/locale.gen
locale-gen
echo 'LANG=zh_CN.UTF-8' > /etc/locale.conf
```

验证字体确实被 fontconfig 认到：

```bash
fc-list :lang=zh | head -5
locale
```

> `/etc/fonts/local.conf` 里给 `sans-serif` 指定优先使用 Noto Sans CJK。

## 13. 中文输入法（fcitx5）

### 13.1 安装

```bash
pacman -S fcitx5 fcitx5-chinese-addons fcitx5-configtool fcitx5-gtk fcitx5-qt
```

`fcitx5-gtk` / `fcitx5-qt` 是给 GTK、Qt 程序用的输入法模块，缺了会出现
"浏览器里能打字、某些应用里打不出中文"。

### 13.2 环境变量：X11 与 Wayland 不同

**X11 会话**：在 `~/.xprofile` 里写（登录时由显示管理器读取）：

```bash
export GTK_IM_MODULE=fcitx
export QT_IM_MODULE=fcitx
export XMODIFIERS=@im=fcitx
```

**Wayland 会话**：由合成器通过 `text-input` 协议接管，一般**不要**再设
`GTK_IM_MODULE`，否则会退回 XIM 行为。KDE 和 Hyprland 支持较好；
GNOME 的 Wayland 会话对第三方输入法支持偏弱，必要时切回 X11 会话使用。

自启不用手写：`fcitx5` 包自带 xdg autostart，登录桌面后会自动起来
（KDE/GNOME 的应用自启动里能看到 `Fcitx5`）。

### 13.3 配置与验证

```bash
fcitx5-configtool    # 添加"拼音"，设置切换键（默认 Ctrl+Space）
fcitx5-diagnose      # 输出环境变量、模块、前端是否正常
```

`fcitx5-diagnose` 里重点看三项：环境变量是否为 `fcitx`、
`fcitx5` 进程是否在跑、当前前端（GTK/Qt/XIM）是否被识别。
