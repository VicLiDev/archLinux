# openSUSE Leap 只有终端没有桌面：原因与修复

- **现象**：装完 openSUSE Leap，开机停在 `login:` 文本提示，没有图形登录界面
- **结论**：多数情况不是系统坏了，而是"没装桌面"或"默认启动目标不是 graphical"
- **前提**：能登录、能联网、`zypper` 可用；以下命令都在 openSUSE 上执行

## 1. 先确认：是"没有桌面"还是"系统没起来"

两者症状很像，处理方向完全不同：

| 现象                                     | 性质              | 去哪                                                                                                   |
|------------------------------------------|-------------------|--------------------------------------------------------------------------------------------------------|
| 有 `login:` 提示，能登进去敲命令         | 桌面层缺失        | 本文                                                                                                   |
| 黑屏、卡在内核日志、掉进 emergency shell | 引导/文件系统问题 | [02.dual-boot.md](../01.install_sys/02.dual-boot.md)、[03.bootctl.md](../01.install_sys/03.bootctl.md) |

只要能在文本终端里正常 `zypper`，就说明系统本身没问题，缺的只是图形那一层。

## 2. 图形界面由四层组成

理解这四层，就知道"只有终端"可能断在哪一层：

```text
桌面包（pattern）→ systemd 默认 target → 显示管理器（DM）→ 图形会话（X11/Wayland）
```

- **桌面包**：`zypper in -t pattern kde_plasma` 装的几百个包，含会话、文件管理器、
  终端模拟器；没装就什么都没有。
- **默认 target**：`graphical.target` 才会拉起显示管理器；`multi-user.target`
  只给文本登录。
- **显示管理器**：`sddm`（KDE）、`gdm`（GNOME）、`lightdm`（Xfce），负责画登录
  界面、启动会话。它是个 systemd 服务，叫 `display-manager.service`。
- **图形会话**：Xorg 或 Wayland 加显卡驱动。前三层都对、这一层出错，表现为
  "有登录界面但黑屏/花屏/登录后又跳回来"。

## 3. 诊断：六条命令定位断点

```bash
cat /etc/os-release                                   # Leap 15.6 还是 16
systemctl get-default                                 # multi-user 还是 graphical
systemctl status display-manager --no-pager           # DM 在不在跑
zypper se -i -t pattern | grep -Ei 'gnome|kde|xfce|x11'
rpm -q xorg-x11-server sddm gdm lightdm 2>&1          # 关键包装没装
lspci -k | grep -A3 -E 'VGA|3D'                       # 显卡与当前驱动
```

对照判断：

| 输出特征                                         | 断点     | 去哪节  |
|--------------------------------------------------|----------|---------|
| 没有桌面 pattern，`xorg-x11-server` 也没装       | 第一层   | 第 4 节 |
| 有桌面包，`get-default` 是 `multi-user.target`   | 第二层   | 第 5 节 |
| `graphical.target`，但 DM 是 `inactive`/`failed` | 第三层   | 第 6 节 |
| DM `active`，但屏幕黑/花/登录后跳回              | 第四层   | 第 7 节 |
| 有 `transactional-update`，根分区只读            | 特殊角色 | 第 8 节 |

## 4. 情况 A：根本没装桌面（最常见）

安装时选了 **Server** 或 **Minimal** 角色，或者自定义里没勾桌面，系统就只装
文本环境。这不是安装失败，Leap 16 的 Agama 安装器默认更精简，更容易出现。

判断：`rpm -q xorg-x11-server` 输出 `package xorg-x11-server is not installed`，
且 `zypper se -i -t pattern` 里没有任何 gnome/kde/xfce。

先看仓库里有哪些 pattern，再装：

```bash
zypper se -t pattern | grep -Ei 'gnome|kde|xfce'
sudo zypper in -t pattern kde_plasma
```

| 桌面       | pattern      | 显示管理器 | 适合谁                          |
|------------|--------------|------------|---------------------------------|
| KDE Plasma | `kde_plasma` | `sddm`     | openSUSE 的默认桌面，像 Windows |
| GNOME      | `gnome`      | `gdm`      | 简洁、触控板手势好用            |
| Xfce       | `xfce`       | `lightdm`  | 老机器、虚拟机、要轻量          |
| 只有 X     | `x11`        | 无         | 自己配窗口管理器，见第 11 节    |

pattern 会自动带上显示管理器、X/Wayland 基础和常用应用，不需要再单独装。版本
差异：Leap 15.6 是 Plasma 5.27，Leap 16 是 Plasma 6；pattern 名一致，界面差别
不小。

装完如果没自动进图形，继续看第 5、6 节。不想装完整桌面、只要一个平铺
合成器，直接看第 10 节的 niri。

## 5. 情况 B：桌面装了，默认 target 还是 multi-user

`graphical.target` 才会 `Wants=display-manager.service`。从 Server 手工补装桌面
时，target 往往还停在 `multi-user`：

```bash
systemctl get-default                  # 输出 multi-user.target 就是它
sudo systemctl set-default graphical.target
sudo reboot
```

改完 `get-default` 应显示 `graphical.target`。临时试一次不必重启：

```bash
sudo systemctl isolate graphical.target
```

## 6. 情况 C：显示管理器没启用，或没指定

装了桌面包但 DM 服务是 `inactive`，或者 `DISPLAYMANAGER` 为空：

```bash
systemctl status display-manager --no-pager
sudo systemctl enable --now display-manager
grep DISPLAYMANAGER /etc/sysconfig/displaymanager
```

若 `DISPLAYMANAGER=""` 为空，用 alternatives 选一个：

```bash
sudo update-alternatives --config default-displaymanager
```

典型场景：先装 KDE 又装 GNOME，两个 DM 都装着，alternatives 指向了没装好的
那个；或者手工 `zypper in sddm` 却没 enable。`journalctl -u display-manager`
能直接看到它为什么起不来。

## 7. 情况 D：DM 起来了，但黑屏、花屏或登录后跳回

按 `Ctrl+Alt+F2` 切到文本终端，收集三条信息：

```bash
journalctl -b -u display-manager --no-pager | tail -40
grep -E '\(EE\)|\(WW\)' /var/log/Xorg.0.log | tail -20
lspci -k | grep -A3 -E 'VGA|3D'
```

按现象分三类处理：

| 现象                       | 常见原因                     | 处理                                              |
|----------------------------|------------------------------|---------------------------------------------------|
| 登录界面出现，输密码后跳回 | Wayland 会话与该显卡不兼容   | 登录界面齿轮里选 `Plasma (X11)` / `GNOME on Xorg` |
| 一直黑屏，但能切到文本终端 | 显卡驱动缺失或 nouveau 冲突  | 装 NVIDIA 官方驱动，见下                          |
| 花屏、分辨率异常           | 虚拟机显存不足或模式设置错误 | 加大显存；引导参数临时加 `nomodeset` 验证         |

NVIDIA 机器装驱动（版本号随分支变化，先查再装）：

```bash
zypper se -s nvidia | grep -E 'driver|gl-G0'
sudo zypper ar -f https://download.nvidia.com/opensuse/leap/15.6 nvidia
sudo zypper ref
sudo zypper in nvidia-driver-G06-kmp-default nvidia-gl-G06
sudo reboot
nvidia-smi                     # 有输出才算驱动生效
```

URL 里的 `15.6` 要换成你的版本（`cat /etc/os-release` 里的 `VERSION_ID`）。
Leap 16 的驱动分支与包名不同，以 `zypper se -s nvidia` 的结果为准。

想验证是不是桌面会话的问题，可以先在文本终端直接起一次：

```bash
startx
```

`startx` 能进图形、DM 进不去，说明问题在 DM 或会话选择；`startx` 也报错，
错误信息会直接打在终端上，比翻日志快。

## 8. 情况 E：Transactional Server（根分区只读）

如果 `rpm -q transactional-update` 有输出，说明装的是事务型服务器角色，根分区
只读，`zypper in` 会直接失败：

```bash
sudo transactional-update pkg install -t pattern kde_plasma
sudo reboot
```

这个角色是为无人值守服务器设计的，每次改动都要新快照 + 重启。真想要桌面，
重装成 Desktop 角色比在它上面堆桌面更快。

## 9. 验收清单

- [ ] `systemctl get-default` 输出 `graphical.target`
- [ ] `systemctl status display-manager` 是 `active (running)`
- [ ] 重启后能看到图形登录界面，输密码能进桌面
- [ ] 桌面里能打开终端、文件管理器，分辨率正常
- [ ] `lspci -k` 里显卡用的是预期驱动（NVIDIA 机器 `nvidia-smi` 有输出）
- [ ] `Ctrl+Alt+F2` 能切回文本终端，`Ctrl+Alt+F1`（或 F7）能切回图形
- [ ] 中文显示正常（`zypper se -s noto` 找字体包，按需装）

## 10. 附：用 niri 当桌面（不装完整 DE）

不想装 KDE/GNOME 那几百个包、又想要一个现代 Wayland 桌面，可以直接装一个平铺
合成器。niri 是其中配置最省心的：单个 KDL 文件、滚动式平铺、默认键位接近直觉。
Arch 侧三个合成器（sway/Hyprland/niri）的对比见
[01.desktop.md](01.desktop.md) 第 6 节。

### 10.1 先确认源里有没有

```bash
zypper se -s niri
zypper se -s xdg-desktop-portal
```

- **有 `niri` 包**：直接装，跳到 10.2。
- **没有**：到 <https://software.opensuse.org> 搜 niri，选中你的版本，页面会给
  出 `zypper addrepo` 命令，粘过来执行。OBS 的 `X11:Wayland` 项目通常为各版本
  构建了 niri 和配套包。
- **Leap 15.6 装不上**：多半是基础库（Mesa、libdisplay-info）太老，别硬编译。
  改用 Tumbleweed，或退回第 11 节的 icewm。

### 10.2 装合成器与最小配套

```bash
sudo zypper in niri
sudo zypper in xdg-desktop-portal-wlr        # 截图、录屏、文件选择框
sudo zypper in foot fuzzel mako waybar grim  # 终端、启动器、通知、状态栏、截图
sudo zypper in polkit-gnome swaylock swayidle brightnessctl
sudo zypper in swaybg                        # 壁纸，可选但不装就只有纯色
sudo zypper in xwayland-satellite            # 要跑 X11 老程序时才装
```

`polkit-gnome` 是认证代理，没有它挂载 U 盘、装软件都弹不出密码框；
`swaylock` + `swayidle` 负责锁屏与空闲，niri 自己不提供。

`zypper se -s xdg-desktop-portal` 能看到实际包名，不同版本的拆分方式略有差异。

**portal 不能省**：niri 自己不实现截图和屏幕共享，缺了 `-wlr` 时 `grim`、
OBS、浏览器共享屏幕全部失败，表现为"点了没反应"。

**XWayland 也不内置**：niri 只跑原生 Wayland 程序。遇到必须 X11 的老软件
（部分 Steam 游戏、旧版 WPS）才装 `xwayland-satellite`，它按需自动拉起，不用
改配置。搜不到这个包就先跳过，纯 Wayland 环境不受影响。

### 10.3 怎么启动

有显示管理器时（第 5、6 节装过 sddm/gdm），包里带
`/usr/share/wayland-sessions/niri.desktop`，登录界面的会话菜单里会多出
`niri`，选中它登录。

没有显示管理器时，登录 tty 后执行：

```bash
niri-session
```

**用 `niri-session` 而不是 `niri`**：前者会拉起 systemd 用户会话，portal、
通知、dbus 激活的服务才正常工作；直接敲 `niri` 是裸跑，很多功能静默失效。

想让开机直接进 niri，装一个显示管理器并把默认 target 设为 `graphical.target`
最省事；不想装 DM，就在 `~/.bash_profile` 末尾加 `niri-session`，代价是登录
流程要自己维护。

**和 KDE Plasma 共存**：niri 与 `kde_plasma` pattern 可以装在同一台机器上，
会话级互斥——SDDM 的会话菜单里选 `Plasma (Wayland)` 或 `niri`，两套外壳不会
同时在跑。要注意 Plasma 会往 `/etc/xdg/autostart/` 放一批 KDE 自启项，在 niri
会话里也会被执行，和 `polkit-gnome`、`swayidle` 抢角色；屏蔽方法见
[01.desktop.md](01.desktop.md) 的 6.7 节。

### 10.4 第一次进桌面

**先说清楚会看到什么**：登录后 niri 会自己弹出快捷键浮层，也就是那张键位速查
表，按 `Esc` 或再按一次 `Mod+Shift+/` 关掉。浮层后面是一片纯色、什么都没有，
**这是正常的**——niri 只是合成器，默认配置里既没有壁纸也没有自启项，桌面上
不会出现图标、面板、任务栏。那片灰色就是默认背景色，不是系统坏了、不是显卡
驱动没装、也不是漏装了包。

把这块空白填起来靠三样东西：壁纸（`swaybg`）、状态栏（`waybar`）、开机自启
（`spawn-at-startup`），都在下一节配。

首次启动还会在 `~/.config/niri/config.kdl` 生成默认配置。常用键位（以你生成的
文件为准）：

| 键位          | 作用             |
|---------------|------------------|
| `Mod+T`       | 开终端（foot）   |
| `Mod+D`       | 启动器（fuzzel） |
| `Mod+Shift+E` | 退出 niri        |
| `Mod+Shift+/` | 快捷键浮层       |
| `Mod+H/J/K/L` | 焦点上下左右移动 |

`Mod` 默认是 Super（Windows 键）。终端和启动器指向的程序没装，按下就毫无反应
——这是新人最常踩的坑，先确认 `foot`、`fuzzel` 在不在。

### 10.5 配置：一个 KDL 文件

常用片段，直接改 `~/.config/niri/config.kdl`：

```kdl
input {
    keyboard {
        xkb { layout "us"; }
    }
    touchpad {
        tap;
        natural-scroll;
    }
}

layout {
    gaps 16;
    background-color "#1e1e2e";
}

spawn-at-startup "fcitx5" "-d"
spawn-at-startup "waybar"
spawn-at-startup "swaybg" "-i" "/usr/share/wallpapers/openSUSE-default/contents/images/1920x1080.png"

binds {
    Mod+Return { spawn "foot"; }     // 默认终端是 Mod+T，这里额外加一个
}
```

壁纸那行是示例路径，实际用 `ls /usr/share/wallpapers/` 找自己系统里的图片；
没装 `swaybg` 就把那行删掉，只留 `background-color` 一样能看。

**别重复定义已有键位**：默认配置里已经写好了 `Mod+T`、`Mod+Q`、`Mod+Shift+E`
等绑定，片段里再写一遍会被判成重复键位，niri 直接把整个配置文件视为无效、
退回内置默认值，你加的 `spawn-at-startup` 也一起失效。加按键只加新的组合。

保存即生效，niri 监听配置文件变更，不用重启会话。语法错误会直接打在启动它的
终端里，带行号。

### 10.6 中文输入与字体

**第一步：装主体和字体**（下面三个包在 Leap 16.0 上确认存在）：

```bash
sudo zypper in fcitx5 fcitx5-chinese-addons fcitx5-configtool
sudo zypper in noto-sans-sc-fonts        # 包名以 zypper se -s noto 为准
```

**第二步：先别装 GTK/Qt 模块，测了再说。** Wayland 下如果合成器实现了
`text-input-v3`、程序也走这个协议，fcitx5 直接和程序对话，既不需要 immodule
包，也不需要任何环境变量。所以先只加自启，注销重进，在任意输入框按
`Ctrl+Space` 试中文：

```kdl
spawn-at-startup "fcitx5" "-d"
```

**能输入**：到此为止。config.kdl 里不要写 `GTK_IM_MODULE`、`QT_IM_MODULE`。
设了却没有对应的模块包，GTK 程序会报
`Gtk-WARNING: Error loading IM Context type 'fcitx'`，反而输不进字。

**不能输入**：才补 immodule。openSUSE 的包名和 Arch 不同——Arch 上是
`fcitx5-gtk`/`fcitx5-qt`，Leap 16.0 上这两个名字**不存在**，先查真实名字：

```bash
zypper se -s fcitx5 | grep -Ei "gtk|qt"
zypper se -s --provides 'immodule' | grep -i fcitx
```

搜到什么装什么，形如 `fcitx5-gtk3`、`fcitx5-gtk4`、`fcitx5-qt6`。一条都没搜到
说明主源里没有，加 M17N 源再查：

```bash
sudo zypper addrepo https://download.opensuse.org/repositories/M17N:/fcitx5/16.0/M17N:fcitx5.repo
sudo zypper --gpg-auto-import-keys refresh
zypper se -s fcitx5 | grep -Ei "gtk|qt"
```

装好后再把变量写进 config.kdl 的 `environment` 块（不要写进 `~/.profile`，
那是 X11 和文本登录用的）：

```kdl
environment {
    XMODIFIERS "@im=fcitx"
    GTK_IM_MODULE "fcitx"
    QT_IM_MODULE "fcitx"
}
```

`GTK_IM_MODULE` 只为 GTK3 程序保留，GTK4 和 Qt6 走 text-input 时不需要。
**不要设 `GTK_IM_MODULE=xim`**，它会盖掉 text-input，表现为候选框不跟随光标。

**第三步：验证**。注销重进后 `fcitx5-diagnose`，Wayland 一节应显示 text-input
可用；再用 `fcitx5-configtool` 添加「拼音」输入法并设好切换键。

常见现象对照：

| 现象                                    | 原因                          | 处理                    |
|-----------------------------------------|-------------------------------|-------------------------|
| `Error loading IM Context type 'fcitx'` | 设了变量但没装 immodule 包    | 装包，或删掉该变量      |
| `Ctrl+Space` 无反应，诊断为 DBus 连不上 | fcitx5 没随会话启动           | 加 `spawn-at-startup`   |
| 候选框不跟随光标                        | 设了 `GTK_IM_MODULE=xim`      | 改成 `fcitx` 或直接删掉 |
| 只有 X11 老程序能输入                   | XWayland 走 immodule 不走协议 | 装 immodule，保留变量   |

### 10.7 验收清单：最小可用

- [ ] `niri --version` 有输出，`/usr/share/wayland-sessions/niri.desktop` 存在
- [ ] 登录后能开窗口，`Mod+T` 能弹出终端
- [ ] `echo $XDG_SESSION_TYPE` 输出 `wayland`
- [ ] `systemctl --user --failed` 没有 failed 单元
- [ ] `grim ~/shot.png` 能生成截图（说明 portal 正常）
- [ ] `fcitx5-diagnose` 无红色报错，中文能输入
- [ ] 音量/亮度键可用（`wpctl`、`brightnessctl` 需另装）
- [ ] 注销后能回到登录界面，不黑屏

### 10.8 从「能用」到「好用好看」：继续往哪走

10.7 的验收过了，只说明桌面能开窗口。默认配置离顺手、好看还差一截，但不用
一次配完。下面按收益从高到低排，每一步都能单独生效、单独回退——改的全是
`~/.config/` 下的用户文件，不碰系统包；写完 `niri validate` 就能知道有没有
语法错。

**第一步：补齐日常键位（收益最大，半小时）**

默认只绑了终端、启动器、开关窗口这几组。把每天要按十几次的动作都补上：

```kdl
binds {
    Mod+Escape { spawn "swaylock" "-f"; }
    Print { spawn "sh" "-c" "grim -g \"$(slurp)\" - | swappy -f -"; }
    XF86AudioRaiseVolume { spawn "wpctl" "set-volume" "@DEFAULT_AUDIO_SINK@" "5%+"; }
    XF86AudioLowerVolume { spawn "wpctl" "set-volume" "@DEFAULT_AUDIO_SINK@" "5%-"; }
    XF86AudioMute { spawn "wpctl" "set-mute" "@DEFAULT_AUDIO_SINK@" "toggle"; }
    XF86MonBrightnessUp { spawn "brightnessctl" "set" "5%+"; }
    XF86MonBrightnessDown { spawn "brightnessctl" "set" "5%-"; }
    Mod+Shift+R { spawn "niri" "msg" "action" "load-config-file"; }
}
```

截图那行要 `grim`、`slurp`、`swappy` 三个包；swappy 不在基础源里，装不上就
换成 `grim -g "$(slurp)" ~/shot.png` 存文件。`Mod+Shift+R` 重载配置，比注销
重进快得多，配桌面时一直在用。

**第二步：状态栏（有没有 bar 是能不能用的分界）**

waybar 拆成两个文件：`~/.config/waybar/config` 决定放哪些模块，
`~/.config/waybar/style.css` 决定长什么样。最小可用的 config：

```json
{
  "layer": "top",
  "height": 34,
  "modules-left": ["clock"],
  "modules-right": ["pulseaudio", "network", "battery", "tray"]
}
```

**Leap 的坑**：想加工作区模块得写 `"niri/workspaces"` 和 `"niri/window"`，
这要求 waybar 0.11 以上。Leap 15.6 自带的是 0.9/0.10，模块名不认，bar 上直接
一片空白。先 `waybar -v` 看版本；太低就从 software.opensuse.org 的
`X11:Wayland` 装新版，或者先只用时钟、音量、电量这类通用模块，工作区靠
`Mod+1`…`Mod+9` 硬记。

**第三步：统一配色（好看的核心不是挑色，是只用一套色）**

选一张壁纸，从里面取一个主色，然后写进四个程序各自的配置：

| 程序   | 文件                          | 改哪几项                                          |
|--------|-------------------------------|---------------------------------------------------|
| waybar | `~/.config/waybar/style.css`  | `background`、`color`、`border-radius`            |
| mako   | `~/.config/mako/config`       | `background-color`、`text-color`、`border-radius` |
| fuzzel | `~/.config/fuzzel/fuzzel.ini` | `[colors]` 段的 `background`、`text`              |
| foot   | `~/.config/foot/foot.ini`     | `[colors]` 段的 `background`、`foreground`        |

四个文件里填同一个十六进制值，视觉上就统一了。想自动从壁纸取色可以用
`wallust` 或 `matugen`，但 Leap 没有现成包、要装 cargo 自己编，第一次配桌面
不建议先折腾这个。

**第四步：字体与光标（最影响观感的一步）**

```bash
sudo zypper in jetbrains-mono-fonts   # 没有就装 fira-code-fonts
sudo zypper in adwaita-icon-theme
```

中文用 10.6 装好的 `noto-sans-sc-fonts`。光标主题要写进 config.kdl，否则 niri
会话里是默认的大号白箭头，和整体配色格格不入：

```kdl
environment {
    XCURSOR_THEME "Adwaita"
    XCURSOR_SIZE "24"
}
```

**第五步：让 GTK 与 Qt 程序长得一样**

niri 不管主题，GUI 程序各读各的。GTK 侧用 gsettings 设一次：

```bash
gsettings set org.gnome.desktop.interface gtk-theme 'Adwaita-dark'
gsettings set org.gnome.desktop.interface color-scheme 'prefer-dark'
```

Qt 侧装 `qt6ct`，再把 `QT_QPA_PLATFORMTHEME "qt6ct"` 加进上面的 `environment`
块，然后在 qt6ct 里选同一套配色。这一步做完，文件管理器、输入法候选框这些
才会跟着暗色走。

**第六步：多显示器与窗口规则（细节）**

```kdl
output "eDP-1" {
    scale 1.5;
}

window-rule {
    match app-id="pavucontrol";
    open-floating true;
}
```

`output` 按 `niri msg outputs` 里的名字写；`window-rule` 让某些程序默认浮动，
不用每次手动切。

**推荐的推进节奏**

1. 键位——半小时就有体感，先做这个
2. 状态栏——有了 bar 才算"能日常用"
3. 配色、字体——纯观感，可以慢慢试错
4. 窗口规则、缩放——等前面稳定了再动

每改完一块就 `niri validate` 再重载，出错能立刻定位到刚写的那几行。想更稳一
点，把配置纳入 git：

```bash
mkdir -p ~/dotfiles && cp -r ~/.config/{niri,waybar,mako,fuzzel,foot} ~/dotfiles/
cd ~/dotfiles && git init && git add -A && git commit -m "niri setup"
```

改坏了 `git checkout .` 就回去了。

**现在不建议碰的**：DMS / Noctalia 这类整套外壳。它们要在 quickshell 上跑，
Leap 的 Qt 版本不够、没有现成包，编译成本远高于上面六步的总和；等桌面用顺了
再考虑，而且装了之后要把 waybar、mako、fuzzel 撤掉，否则抢 D-Bus 名和层叠区
（见 [01.desktop.md](01.desktop.md) 第 7、8 节）。

完整的配置项清单看 niri 的 wiki（GitHub `YaLTeR/niri` → Wiki → Configuration），
比逐个试快得多。

## 11. 附：轻量方案与回滚

**只要一个能开窗口的最小环境**（老机器、虚拟机）：

```bash
sudo zypper in -t pattern x11
sudo zypper in xinit icewm
startx
```

`icewm` 是极轻的窗口管理器，没有登录界面，`startx` 直接进。想自动进图形，把
`startx` 写进 `~/.bash_profile` 的登录分支即可，但这套没有锁屏、没有会话管理，
不适合日常主力机。

**装桌面把系统弄坏了**，用 snapper 回滚（Leap 默认 btrfs + snapper）：

```bash
sudo snapper list            # 找装桌面之前的 pre 快照
sudo snapper rollback 123    # 回滚后重启
```

装之前手动打一个快照更稳妥：

```bash
sudo snapper create -d "before-install-kde"
```
